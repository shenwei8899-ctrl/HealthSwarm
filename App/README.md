本项目以 [《家庭 AI 营养师：微信小程序产品需求规格》](docs/家庭AI营养师-小程序产品需求规格-v1.0.md)（文件名保留 v1.0，正文 v1.3）为正式产品依据。当前第一版前端采用 Uni-app + Vue 3，白灰底色、系统字体、分组列表、绿色点缀和餐食图片，提供微信小程序构建与 H5 预览。

开发范围见 [前端开发文档](docs/家庭AI营养师-微信小程序前端开发文档-v1.0.md)，导入步骤与验证范围见 [第一版交付说明](docs/家庭AI营养师-前端第一版交付说明.md)。

> 正式目标是可实际使用的微信小程序，不是把离线 HTML 当作最终产品。讨论稿只用于追溯早期想法，不定义当前范围。

## 运行和构建

需要 Node.js 和 pnpm（本次验证使用 Node.js 24、pnpm 10.33.0）。在本目录运行：

```bash
pnpm install
pnpm dev:h5 --host 127.0.0.1 --port 5178
pnpm test
pnpm build:h5
pnpm build:mp-weixin
```

微信开发者工具导入 `dist/build/mp-weixin`。也可导入当前 `App` 目录，根目录 `project.config.json` 已通过 `miniprogramRoot` 指向上述构建目录；两种方式都需先执行 `pnpm build:mp-weixin`，源码修改后重新构建。若提示根目录缺少 `app.json`，检查构建是否完成以及该路径是否正确，不要在源码根目录手写 `app.json`。实际 AppID 在微信公众平台注册小程序后取得，在本机 `.env.local` 填写 `VITE_WECHAT_APPID` 再重新构建；构建会将公开 AppID 写入产物并开启合法域名校验。源码 `src/manifest.json` 的 AppID 保持留空，未配置时只支持游客构建，不能完成真实登录。HBuilderX 也可导入本项目源码，安装依赖后选择运行到微信开发者工具。

`dist` 是生成产物，修改应在 `src` 内完成，不直接编辑产物。

真实微信登录使用单独的 API 构建入口，明确指定已在微信公众平台登记、并已接到对应后台的 HTTPS 地址和 AppID：

```bash
npm run build:mp-weixin:api -- --api-base-url https://api.example.com --commerce-base-url https://shop.example.com --appid wx0123456789abcdef
```

以上地址和 AppID 是占位示例，需替换为实际配置。加上 `--check-only` 可只检查服务。正式入口先核对 Agent 微信配置、AppID、就绪状态和商城鉴权接口，通过后才构建；拒绝临时 `trycloudflare.com` 域名，并固定关闭本机测试登录、演示手机号和本机 HTTP 开关。预检失败不会覆盖已有产物，也不会回退模拟模式；构建完成后再核对产物中的 API 地址、AppID 和合法域名校验开关。

微信的合法域名登记不会自动把请求转发到 Agent。若已登记域名的 `/api/auth/wechat/config` 或 `/api/system/ready` 返回 404，需要先修复该域名服务器的路由；仅替换前端地址仍无法登录。完成正式构建后，在开发者工具中导入当前构建目录，刷新“详情 → 域名信息”并重新编译。

## 配套业务服务

聊天恢复、今日饮食计划与建档准备使用同一版本的 Agent 后端；每日计划的来源引用和准备记录需要健康 Schema 33。部署时先使用后端既有迁移入口完成版本升级，再启动 API 与 Worker，不能只替换前端包。参考餐单保留来源、营养未核算和未专业审核标记；缺少配置时显示实际原因。

收货地址标签与默认地址能力依赖商城的地址偏好迁移。聊天商品和参考餐单采购复用服务端来源回验；餐次替换、商品变更或授权失效后需要重新核对采购。

`npm test` 包含登录、页面返回、每日计划和地址交互回归；`npm run check:mp-size` 检查微信构建目录的上传体积。真实商城 HTTP 集成测试单独使用隔离环境执行，普通测试通过不代表真机、模型或支付验收。构建环境变量参照 `.env.example`，API 地址由部署环境注入。

2026-10-21：正式 API 模式统一为“微信登录 → 云端本人建档／确认 → AI 对话首页”。取消商城账号和业务密码登录、独立商品浏览与旧商城直达；本餐、今日多餐汇总及 AI 对话指定食材包是三种采购来源。两类邀请在登录后继续处理，普通邀请多人分别建档，绑定邀请认领已有档案，均确认本人资料后进入 AI 首页。接口、数据保留规则与验证边界见[统一微信主线实施说明](docs/统一微信主线实施说明-20261021.md)。本轮源码和构建未部署线上，真实微信登录及支付仍需配置和真机验收。

## 当前已覆盖的 v1.0 流程

- 三页建档：使用方式、成员资料与默认就餐选择合为首步，后续为饮食目标与基础健康、健康限制与体检报告。
- AI 首页：按天 AI 对话历史、非吸顶的今日三餐、本餐就餐者，以及“AI专属计划 → 家庭健康档案 → 拍照看热量 → 今日饮食计划”四个入口。
- “我的”：我的家、使用方式、饮食与反馈、计划与订单、资料管理、设置。
- 本餐菜单：菜品卡、直接展示三个换菜候选、食材包与未支付清单同步；菜单页不放逐人成员份量区块。
- 菜品营养：每道菜详情新增两行三列的能量、蛋白质、脂肪、碳水化合物、膳食纤维和钠卡片，注明每 100 克熟制后可食部分；收货后的烹饪页随菜品切换，缺失指标显示暂无数据，新模拟订单保存营养快照。后端字段与持久化要求见[菜品营养字段与后端存储契约](docs/菜品营养字段与后端存储契约.md)，真实菜谱营养服务及服务器存储尚未接入。
- AI 专属计划：每天早中晚三餐、21 天展开、首批价与总价分开、根据适用成员档案检查饮食安全、地址优先的 21 批配送。
- 购买与订单：单包详情、已知冲突阻断购买、全部/进行中/已完成、分批收货、暂停/恢复、改单批地址、剩余计划取消和逐批售后入口；不另设购买前过敏确认页。
- 饮食记录：拍照分析、当天食谱选菜、手动填写；单人餐盘或家庭桌菜；家庭桌菜逐人确认菜品和少量/一般/较多/不确定，不分摊整桌热量。
- 记录去向：仅保存或保存并聊聊这一餐，共用同一个记录 ID；可更正实际菜品和份量、递增版本并清除旧估算，真实原照片加文字重新识别待联调。
- 反馈与记忆：按日期及成员查看当餐/当日/近7天或30天反馈；趋势从保存记录计算，无记录日留空；长期记忆保留来源并可撤回。
- 新增地址管理、成员报告管理与核对、按天对话历史、隐私与账号页面。
- 供应商合作：消费者订单和家庭健康数据之外的独立合作入口。

## 2026-10-09 联调前准备

本次补齐的是前端状态与模拟服务验证，不代表真实 AI、商城或支付已经接通。

- 订单读取、收货、改址、售后、暂停、恢复、取消及支付经过异步服务入口，失败不会显示成功，提交期间防止重复操作。

- 售后按批次保存多张申请，支持商品、数量、原因、说明及最多三张本机凭证；失败保留表单，同一批次处理中申请展示详情，避免重复提交。
- AI 回复失败可以重试，不重复插入用户消息；页面离开、账号切换或跨日后，不写入过期回复。菜单更新仅应用最新请求，更新中或失败未恢复时禁止结算。

- 21 批测试排程保留独立商品快照，测试总价从逐批商品计算；模拟计算不是生产定价或配送规则。
- 本地状态使用 `fn:v2:<mode>:<account>:<household>:` 命名空间。登录页可填写不同测试账号验证隔离，退出后不读取上一账号数据。旧版本无账号归属的本地数据保留但不自动迁入新账号。

### 接入真实服务的入口

2026-10-16 家庭档案共享：API 模式可使用已有健康业务账号登录（`/api/auth/token`），在“账号与家庭”选定家庭后进入“查看与维护家庭共享档案”。有效同家庭成员可维护未认领成员的姓名、关系、健康及饮食资料、五类实测和修改历史。保存携带服务端版本，冲突或结果未知时先重新读取；退出及权限失效后清理页面资料。本人确认、AI、报告原图和订单仍按各自权限处理。商城身份不会自动变成健康业务身份。

`src/services/index.js` 的 `registerApiAdapters()` 用于挂载接口适配器，当前已注册微信登录；`src/services/request.js` 提供 HTTPS 或 H5 同源请求、会话、超时、HTTP 错误及 traceId 处理。真实会话保存最小业务账号、token 和当前家庭选择，允许用户尚未加入家庭。其他服务方法仍是前端内部约定，需要各自完成后台契约适配。

`api` 模式下未注册的服务明确失败，不回退到 mock；当前开放登录页、“账号与家庭”及“家庭共享档案”页，可读取真实家庭、选择/创建/通过成员邀请加入家庭，维护共享资料及实测，并在本人页面确认本人基础资料。完成某页所有数据来源的真实适配和验证后，再通过 `registerApiPages()` 放行路由。其余菜单、档案、记忆、报告和照片仍含本地演示逻辑，不能仅注册订单接口就把全部页面放行。开发者工具仍需实际 AppID、合法域名及真机验收。

当前内部订单方法为 orders、order、createOrder、payOrder、paymentResult、receive、pausePlan、resumePreview、resumePlan、changeBatchAddress、refundPreview、cancelRemaining、submitAfterSale。商城返回的 allowedActions 决定按钮权限；实际支付还需接微信支付参数、调起支付及服务端查询，不能直接使用模拟结果选择器。

凭证仍是临时本机文件。正式售后接入时需上传后转为 fileId；临时图片失效会提示，不把本机路径当作后端附件。AI 流式、图片识别、专业安全规则、真实配送排程和退款金额继续由对应团队提供并联调。

## 微信登录接入（2026-10-11）

前端登录链路为 `uni.login` → `POST /api/auth/wechat/login` → 最小业务会话；登录前读取 `GET /api/auth/wechat/config` 核对客户端和服务端 AppID，恢复会话使用 `GET /api/auth/wechat/session`。H5 的真实模式明确提示使用微信小程序，缺少配置时不会创建模拟身份。默认 `mock` 保留开发演示流程，登录页的示例家庭直达入口已移除。

前端本机 `.env.local` 的配置示例（值需换成实际环境）：

```dotenv
VITE_SERVICE_MODE=api
VITE_API_BASE_URL=https://your-api.example.com
VITE_WECHAT_APPID=你的微信小程序AppID
```
