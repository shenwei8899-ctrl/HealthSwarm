# 小程序与 Healthflow2 本地商城联调

本页为 2026-10-13 阶段记录。后续已接入统一会员身份、服务端餐单、测试付款和收货后记餐；原商城数据仍缺最新导出。请以 [2026-10-14 联调记录](商城接口联调-20261014.md) 为准。

本次连接本目录的 Vue 3 小程序与微信文件目录中的 `Healthflow2/Healthflow2` 商城，未修改 `HealthSwarm/agent`，未提交、推送或部署。

## 使用入口

- 前端：`http://127.0.0.1:5178/#/pages/shop/index?commerce=1`。
- 后端：`http://127.0.0.1:18081`，业务接口前缀 `/api/v1/commerce`。
- 从“我的 → 选购食材”进入商城。“我的订单”和配送地址读取真实商城。
- 会员账号及随机测试密码保存在后端 `runtime/local-link/credentials.json`。这是合成会员，不能用于生产；后台管理员账号不能当作会员登录。

当前 `.env.local` 开启 `VITE_COMMERCE_MODE=api`，健康服务沿用原模式。H5 对本地商城使用 `/commerce-api` 同源代理，小程序使用 `VITE_COMMERCE_API_BASE_URL`。正式环境改为可访问的 HTTPS 域名，并配置微信请求、图片域名和真实 AppID；手机的 `127.0.0.1` 不会指向电脑。

## 数据与业务边界

商城使用独立 PostgreSQL 容器 `healthflow-link-db-20261013`、端口 `15435`、数据库 `healthflow_link_test`。未连接原商城数据或现有 Agent 数据。测试库只有合成会员、测试商品、上海徐汇区测试配送范围及测试订单。

商城直接使用现有会员登录及微信登录接口，Token 独立于健康档案会话。不将测试家庭账号、昵称或数字 ID 自动绑定为商城会员。服务端保存价格、购物车、地址和订单；本机仅保存商城凭证与待确认操作的幂等键。切换账号拒绝旧响应，同一会员重新登录保留待确认操作。

现有营养菜单页面保留；点击购买转入商城自主选购。尚未接入菜单到 SKU 的采购映射，演示食材包、示例营养数值和 21 天计划不会生成真实商城订单。本次不改变原后端的计划购买或退款政策。

支付按钮只调用真实微信流程及服务端状态查询；会员密码登录不能伪造微信身份。尚未配置和验收真实微信商户扣款。售后按原接口每次选择一件商品，审核与退款由服务端处理，提交申请不代表退款成功。

## 启动与验证

在 Healthflow2 源码目录执行 `scripts/start-local-link.ps1` 启动本地 PHP 服务；首次准备测试库加 `-Initialize`。脚本只使用隔离数据库，不改原 `.env`。需要现有 `healthflow-link-db-20261013` 容器及 Windows PHP 的 mbstring、curl、pdo_pgsql、openssl 扩展。

在当前小程序目录执行：

```powershell
pnpm dev:h5 --host 127.0.0.1 --port 5178
pnpm test
pnpm build:h5
pnpm build:mp-weixin
$env:HEALTHFLOW_LINK_ROOT='E:\林恬伊2.0\xwechat_files\wxid_q35rd0v6sucl22_fcb6\msg\file\2026-10\Healthflow2\Healthflow2'
node --test tests/commerce-http.test.mjs
```

HTTP 验证使用前端实际适配器、PHP HTTP 和独立 PostgreSQL，直接读取数据库核实订单唯一性、库存占用和售后落库，并验证跨会员拒绝、Token 撤销。已支付售后及收货使用明确标记的合成状态，未调用支付网关。原后端 `MiniappCommerceTest.php` 和 `MiniappRouteTest.php` 也在隔离库运行。

微信开发者工具导入 `dist/build/mp-weixin`。本次构建成功不能替代真机、微信授权、合法域名或商户支付验收。

后端增量为：订单详情返回可操作项，按归属查询订单售后，售后图片上传，以及隔离本地数据库启动配置。没有替换后台 Workspace、商品导入、供应链或 Agent 项目。
