# 今日安排真实服务改造

确认日期：2026-10-17。用户已确认实施；页面尽量不用绿色，沿用黑白灰。

## 行为

完成建档 → 云端保存成员和默认就餐者 → Agent 根据服务端当前来源生成完整三餐 → 程序校验与库存匹配 → 保存 → 显示搭配说明 → 显示今日安排。卡片与详情使用相同安排 ID 和版本。当日重进只读；调整只改目标餐。已支付订单和履约快照不修改。

不增加常规补资料或逐餐确认页。草稿可本机暂存，但完成建档必须成功回读后端；网络或保存结果未知使用同一请求键恢复。客户端不能声称模型、来源、营养或库存已经通过验证。

三餐缺失、字段不完整、校验失败、保存未确认时不展示空卡。异常先自动恢复，最终在对话区域显示重试；不使用笼统的“本餐有待处理的饮食问题”。具体冲突提供对应成员、菜品和调整入口。

## 真实来源

复用家庭档案、健康 Agent Request/Run、批准规则、发布菜谱、确定性营养计算和商城接口。不创建演示成员、固定菜单、固定分析或示例营养值。前端只保留格式化和短期输入/请求恢复状态。

正式推荐必须使用当前可购食材；展示后库存变化不删除已保存菜单，采购区给出替换/刷新入口。无可靠商品映射或库存证据时不能将菜单发布为已就绪。营养依据和明确医嘱优先由后端版本化来源提供，不能由模型补造。
