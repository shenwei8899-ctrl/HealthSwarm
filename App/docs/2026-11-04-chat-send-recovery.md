# 发送消息后的故障恢复

用户要求：普通故障由系统自动处理；发送或处理明确失败时，在原消息旁显示红色感叹号，保留问题和已有对话。

## 已复现的问题

`health-task-flow.js` 将任务接口 404、完成结果格式异常与身份/权限失效归入同一失效分支；`CloudNutritionChat.vue` 随后清空消息列表。明确的 400/422/429 提交拒绝还会丢失当前请求 ID，留下“提交中”的状态。这些分支已通过合成请求复现。未获取截图当次的真实请求日志，因此不认定其中某一分支就是当次唯一根因。

## 实现

- 提交/任务接口返回 404 时，独立调用原会话的受控历史接口复核访问权。仅在会话 ID、角色和返回结构匹配时保留会话；不展示这次复核读取的正文。
- 已接受的任务暂时读不到时，自动读取同一请求，采用已有退避策略。连续三次失败后原消息显示红色感叹号，仍自动恢复；点击标记仅重新读取，不重复提交。
- 已确认的结果格式/解析错误最多读取三次，持续失败仅标记本条消息。未通过业务校验的结果不展示。
- 明确的提交拒绝保留原消息的请求归属和失败原因；恢复页面时不把未接受的请求当作正在执行的任务。
- 事件流 404 回退至权威任务读取；停止入口 404 先核对原任务。
- 401/403、原会话访问被拒绝、成员/线程错配及来源或政策变化仍停止读取并清理不可访问的内容。账号切换和页面隐藏后拒绝迟到响应。

没有引入自动重新生成或自动重复 POST。提交结果未知时继续使用原请求 ID 核对，避免重复执行和扣费。
