# 无 AppID 的本机业务账号登录

微信开发者工具可以使用普通业务测试账号，通过真实的 `POST /api/auth/token` 登录。该入口只用于本机联调；使用账号密码认证，不生成微信身份、模拟 token 或演示数据。

## 使用

当前开发者工具目录：`D:/OneDrive/文档/ChatGPT/ai healthy agent/.codex/unified-mainline-20261021/final-api/mp-weixin`。

本机 `.env.local` 配置 `VITE_LOCAL_BUSINESS_LOGIN=1`、`VITE_SERVICE_MODE=api`、`VITE_ALLOW_LOCAL_HEALTH_API=1`，且 API 地址为 `http://127.0.0.1:15050`。运行环境还必须是微信开发者工具，或 localhost / 127.0.0.1 上的 H5。缺少任一条件均不启用测试登录。

1. 如本地转发服务未运行，执行 `npm run dev:health-proxy`，保持进程运行。
2. 重新编译小程序，点击“测试账号登录，开始使用”。
3. 输入专用普通账号；凭据保存在本机 `.codex/local-business-login-20261022/credentials.json`，不得写入前端代码、文档或提交。
4. 首次登录进入本人建档，按实际测试需求填写；不使用虚构建档完成标记跳过校验。

本机转发连接真实远端后端，测试账号和后续保存的数据在远端数据库中。此次创建的普通账号与既有用户独立；不重置旧用户密码，不授予管理员角色。

## 会话与边界

业务客户端使用 `/api/auth/me` 核对账号，再读取 `/api/family`。登录、恢复、家庭选择和退出共用此客户端；身份及家庭未改变时保持会话版本，避免恢复动作使正在进行的请求失效。密码只用于表单提交，不保存到小程序会话。

正常发布继续使用微信登录，发布配置保持 `VITE_LOCAL_BUSINESS_LOGIN=0`，并使用正式 HTTPS 接口。业务密码会话不能证明微信身份；依赖微信身份的支付及商城能力必须按实际后端校验结果处理。

此次本机源码、配置及原开发者工具构建的备份位于 `.codex/local-business-login-20261022/before/`。该目录中的 `all-tests.log`、`http-verification.json`、`installed-build.json` 和 `devtools-verification.json` 分别记录测试、真实 HTTP、目标构建文件及开发者工具登录结果。证据不包含登录 token 或密码。
