# 家庭 AI 营养师：前端第一版交付说明

日期：2026-10-06。产品依据为《家庭 AI 营养师微信小程序产品需求规格》（文件名 v1.0，正文 v1.2），及本次确认的跨成员 AI 档案写入规则。实现入口为 `src`，本次未修改 PRD。

## 第一版包含什么

采用 Uni-app + Vue 3，微信小程序为目标平台，H5 用于快速评审。白灰底、系统中文字体、分组列表、线性图标、绿色点缀，登录和计划页面使用餐食图片。餐食图片为 AI 生成的示意素材，三种计划暂复用同一张图，不代表商品实拍或套餐内容。

- 登录与四步建档、家庭总览与成员详情。
- AI 对话、今日三餐、逐餐就餐成员、换菜、做法与采购清单。
- AI 专属计划、21 天菜谱、首批价及总价、21 批配送设置。
- 地址新增、编辑、选择；模拟支付与订单、配送、计划管理。
- 三种记餐入口、家庭桌菜逐人确认、记录详情及事实更正。
- 按日期和成员查看反馈，近 7／30 天趋势使用已保存记录计算，空白日保留为无记录。
- 报告管理与核对、按天对话历史、长期记忆及撤回、隐私与账号。
- “我的”保留原产品分组；健康设备仅显示“敬请期待”；家庭总览未添加底部导航。

新增地址、报告、纠错及模拟登录使用 `src/services/mock.js` 的异步方法。已有菜单、计划、订单及记忆模块仍使用本机状态和固定规则；全业务统一 API 服务入口、流式 AI、超时及离线重试场景尚需下一阶段整理，不能理解为接口联调已完成。

## 微信开发者工具怎么打开

1. 本项目根目录运行 `pnpm install`、`pnpm build:mp-weixin`。
2. 微信开发者工具选择“导入项目”，目录选 `dist/build/mp-weixin`，开发模式选“小程序”。不要直接导入源码根目录作为原生小程序。
3. 尚无 AppID 时，可以尝试工具提供的“测试号”入口。不同工具版本及账号资格可能有差异，如果入口不可用，先注册实际小程序。
4. 注册入口为微信公众平台 <https://mp.weixin.qq.com/>，选择注册“小程序”，根据实际主体填写并完成验证。进入后台“开发管理 → 开发设置”查看 AppID。主体选择按计划开展的业务确定，个人主体的类目及交易能力可能有限制。
5. 将 AppID 写入 `src/manifest.json` 的 **`mp-weixin.appid`**，重新构建再导入。顶部 Uni-app 的 `appid` 是另一项配置，不替代微信 AppID。不要在前端填写 AppSecret。
6. 进入登录页后，可以先点“先体验示例家庭”。当前演示数据只在本机保存，不需要启动后端。

本机已安装微信开发者工具，但 CLI 打开默认 `touristappid` 工程返回“不存在此 AppID”。微信构建已通过，**开发者工具模拟器和微信真机尚未验收**。当前未代替用户注册账号，未填入他人的 AppID。

后续持续开发可运行 `pnpm dev:mp-weixin`，在开发者工具导入 `dist/dev/mp-weixin`；应等首次编译完成后再导入。构建产物会被重建，长期配置应修改源文件。


## 关键业务边界

- 家人可通过明确对话更新另一位已认领成员的长期健康信息，记录“家人提供／用户自述”、提供者及时间，允许撤回；这不开放另一位成员的手工编辑或报告共享授权。
- 已知过敏、忌口或医嘱冲突阻止购买，没有“我已知晓”绕过或额外人工健康审核流程。
- 更正记录使用同一 ID 并递增版本；清除旧估算。家庭桌菜的个人反馈和成员详情只读该成员确认的菜品。
- 已支付订单的配送地址及商品、价格、做法快照不会随后续档案、菜单或地址簿编辑变化。
- 登录、语音、AI、报告识别、商品、支付、订单及配送均为测试流程。选图用于本机预览，真实图片识别、专业营养计算、报告内容解析及支付未接入。
- 页面权限只是前端演示；真实身份、数据隔离及每次写操作的授权必须由后端实现。
