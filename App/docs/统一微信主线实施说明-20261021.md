# 统一微信主线实施说明

本轮已完成源码修改和候选验证，未提交、推送或发布生产环境。原有未提交工作保持，不重建业务UID、不改变商城客户端标识、不清空旧会员数据。

## 实际用户流程

微信登录 → 读取云端本人状态 → 必要建档或确认 → AI对话首页。恢复会话、冷启动、热启动和内部跳转均执行主线判断。正式小程序不再提供业务密码、商城账号登录或通用商品浏览入口；旧商城链接和独立会员缓存不能绕过。

家庭总览的普通邀请卡可由多人接受，各自建立本人档案；未认领成员详情的绑定邀请只认领已有档案，同一档案只能一个账号认领。邀请在登录中保留，接受前展示邀请人、家庭和共享说明，拒绝不加入。收到邀请后不会先自动新建另一个家庭。受邀人仅填写、核对和确认本人，不重新设置家庭使用方式或默认就餐成员，完成后进入AI首页。

本人完整字段和当前确认版本是建档完成依据，家庭整体完成标记不能替代本人确认。创建人代建的AI来源在本人明确同意分析后保留原ID转交本人，撤销创建人原来的AI访问grant；专业来源不自动转移。

采购保留三种方式：本餐选购；“今日安排”卡片下方“一键选购”选择多餐汇总；AI判断明确购买意图后查询指定菜品的真实食材包。对话购包不修改今日安排，也不要求先把菜加入餐单。查商品和查看页面不会自动加购、下单或支付。

## 代码与接口

| 范围 | 主要源码 | 本轮行为 |
|---|---|---|
| 登录、恢复、旧入口 | `src/pages/index/index.vue`、`src/services/navigation.js`、`wechat-auth-client.js`、`session.js` | 只走微信；服务端验证来源；同身份恢复不使页面请求失效 |
| 两类邀请 | `src/services/family-invitations.js`、`CloudFamilyInvitation.vue`；Agent `family_invitation_service.py`、`family_service.py` | 预览、明确接受/拒绝、跨登录保留、多人加入和唯一认领 |
| 本人建档 | `cloud-profile.js`、`pages/onboarding/index.vue`；Agent `miniapp_profile_service.py`、`miniapp_profile_types.py` | `scope=self`仅本人；完整资料与当前版本确认；默认成员设置分开 |
| 对话购包 | `ConversationFoodPackages.vue`、`ConversationPackagePurchase.vue`；Agent `conversation_purchase_service.py`、health工具和咨询graph | 真实目录查询、同Request/Run签名来源、历史回读、明确结算 |
| 商城身份和来源 | Healthflow2 `addons/shop/library/v5/AgentMemberService.php`、`AgentSessionVerifier.php`、`AgentMealSourceService.php`、`CartService.php` | 自动复用/建会员；拒绝无有效来源和来源外SKU |

| 接口 | 用途 |
|---|---|
| `GET /api/auth/wechat/config`、`POST /api/auth/wechat/login` | 微信code登录；正式流程不提交另一套账号密码 |
| `GET /api/auth/wechat/session` | 返回经认证的账号、可访问家庭和本人建档状态；`wechat_authenticated`来自JWT渠道声明 |
| `POST /api/family/{fid}/invite` | 普通多人家庭邀请 |
| `POST /api/family/{fid}/members/{mid}/invite` | 绑定已有未认领成员的两天邀请 |
| `GET /api/family/invitations/{code}` | 登录后安全预览，不返回健康档案 |
| `POST /api/family/join`、`POST /api/family/invitations/{code}/decline` | 用户明确接受或拒绝 |
| `GET/POST /api/family/{fid}/miniapp-profile` | 云端完整建档；本人scope不修改家庭设置 |
| `GET/POST /api/family/{fid}/daily-arrangements/{day}/meals/{meal}/purchase` | 复用本餐采购增量 |
| `GET/POST /api/family/{fid}/daily-arrangements/{day}/purchase` | 复用多餐汇总采购增量 |
| `GET/POST /api/health/v1/conversation-purchases/{request_id}` | 读取已完成对话中的真实商品；明确购买后发布原回执对应采购包 |
| `POST /api/v1/commerce/session/exchange` | 携带微信业务Bearer和空对象，自动复用或创建商城会员 |

商城关联键保持 `shop_external_identity(client_id, external_user_ref='uid:业务UID')`。已有可靠关联直接复用原会员；未关联旧会员的数据保留，不按昵称、编号或未经验证的客户端参数合并。新逻辑要求经微信认证的业务会话，旧密码会话需重新微信登录。

对话回执绑定账号、成员、Request、Run、资料摘要、商品组成及有效期。商城继续使用现有推荐包、核价、地址、订单和支付能力。实际配料覆盖量按净重×换算率×可食比例核对。本人资料、授权、来源版本、配料或库存变化时重新核对；不能将任意SKU附上有效来源后结算。
