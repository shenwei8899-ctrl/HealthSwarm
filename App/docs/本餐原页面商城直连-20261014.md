# 本餐安排沿用原页面接入商城

- “查看本餐安排”进入原 pages/shop/index?meal=dinner 页面，保留成员选择、营养与份量位置、菜品卡片、食材清单、底部商品小计和结算抽屉。
- 显式 commerce=1 且未指定餐次时进入通用商品页；“我的 → 选购食材”继续使用此入口。
- 本餐菜单、菜谱版本、SKU、规格、价格与库存读取当前会员的商城接口。进入页面只读；点击结算后同步本餐购物车、核对配送地址并请求后端报价。
- 报价只包含本餐所选购物车项，确认下单使用后端 checkout_token。订单创建后进入既有订单详情，支付、配送、收货与后续做饭沿用既有商城订单流程。
- 下单结果不确定时重试原幂等请求；成员、健康档案、数量、地址、时段、菜单或账号变化后不可沿用旧报价。
- 菜品预览沿用原做法页，核对已保存菜单与菜谱版本，不借用本机模拟菜谱。
- 当前个体化营养、个人份量与成员重配/换菜服务未接入，页面明确显示缺失；没有服务端菜单的餐次显示待确认。三餐合并、食材包筛选和周期计划不借用单餐订单契约。

本地数据库仍是既有合成测试库。此修改未恢复原商城数据库，也未修改账号密码、数据库配置或上线配置。真实微信登录与支付仍需 AppID、AppSecret、商户和 HTTPS 配置及设备验收。

验证：新增 meal-commerce 测试覆盖原入口、原抽屉、只读打开、数量/勾选、无关购物车隔离、报价失效、健康依据变化、账号切换、异常下单恢复。执行 pnpm test、pnpm build:h5、pnpm build:mp-weixin 后再进行开发者工具验收。
