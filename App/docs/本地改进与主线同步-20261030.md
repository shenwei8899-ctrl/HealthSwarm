# 本地改进与主线同步

客户端源码以主线 `0b45f3422a5b1578092105e7eb8b3bb86e263551` 为基线。男孩形象与 idle、thinking、planning、success 状态由 NutritionistCharacter 拥有；当前成员、自然语言指定就餐者、“其他餐次不变”和模型工具参数规则沿用主线。

## 客户端行为

普通登录和冷启动进入首页，明确的会话入口恢复对应记录。发送时保护后续输入的草稿，生成期间允许编辑但阻止重复提交。用户手动滚动后停止自动跟随，可显式回到最新回复。取消请求先核对服务端终态；超时后成功回读仍在运行的任务恢复显式停止入口与流式接收，不自动重复取消。失败消息通过红色感叹号提供原因，界面不显示旧恢复卡片及编辑按钮。

快捷入口位于滚动区域外并持续显示。档案表单按类别展开，草稿按账号、家庭和成员隔离。今日餐单在工作台展示，详情和采购使用独立页面并保留返回位置；营养未知值保持未知，个人份量沿用来源。单餐采购和多餐采购引用当前日期、版本与来源，不在客户端扩大采购范围。

## 验证与边界

正式 App 测试入口包含导航壳与今日餐单测试。整合验证为 966 项测试通过，H5 与微信小程序的普通和 API 模式构建通过；普通构建可上传文件 1,839,530 字节，低于既定 1.8 MiB 预算。浏览器合成接口核对男孩素材加载、餐单入口、营养卡片、100g 份量以及 320/375/390px 布局，无页面脚本错误。
