# 服务器 H5 功能测试入口

访问 `http://8.136.134.29/family-app/#/`，点击“测试账号登录，开始使用”，输入独立普通测试账号的账号和密码。此入口连接真实服务，档案保存到服务器；不使用商城会员密码，也不模拟微信身份。

本地联调与服务器 H5 测试共用现有业务账号认证、会话恢复和建档路由。正式小程序仍使用微信登录；默认配置不开放 H5 密码入口。

## 构建配置

仅为该 H5 测试包设置：

```dotenv
VITE_SERVICE_MODE=api
VITE_API_BASE_URL=
VITE_COMMERCE_MODE=api
VITE_COMMERCE_API_BASE_URL=/commerce-api
VITE_LOCAL_BUSINESS_LOGIN=0
VITE_ALLOW_LOCAL_HEALTH_API=0
VITE_H5_TEST_LOGIN=1
VITE_H5_TEST_ORIGIN=http://8.136.134.29
```

在 App 项目目录运行 `pnpm exec uni build -p h5 --base /family-app/`。环境变量必须覆盖本机 `.env.local` 的联调设置；H5 输出默认位于 `dist/build/h5`。在隔离源码目录构建时，Vite 的根目录与 `UNI_INPUT_DIR` 必须指向同一份 App 项目，检查生成包确实包含欢迎页、页面分包和“测试账号登录”。

入口需要同时满足 H5 平台、显式测试开关、API 模式、API 同源空地址，以及浏览器 origin 与配置完全一致（包含协议和端口）。重新发布正式微信包时保持 `VITE_H5_TEST_LOGIN=0`，本机联调开关也保持关闭。此构建开关只决定客户端入口，所有账号、家庭和健康资料权限仍由服务器校验。

## 测试和交付边界

- 为同事与发布验收分别建立普通测试账号，角色为 `user`；密码保存在不入库的本地私密文件中。
- 使用虚构的测试资料。当前入口是 HTTP 测试地址，正式使用前需要 HTTPS。
- 验证欢迎页、错误密码、登录、首次建档、云端保存、刷新恢复、退出和再次登录。
- 健康 AI、识别与餐单生成依赖服务端专业配置和审批；入口部署不能替代这些条件。微信授权、真实微信支付和手机验收另行进行。
- 发布到独立目录后原子切换 `/opt/healthswarm-commerce/shared/family-app`，保留旧目录与静态资源；校验所有新文件的 HTTP 哈希及其他页面和容器状态。失败时将软链接恢复至发布前目录。
