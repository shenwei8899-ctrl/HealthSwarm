# 家庭档案正式功能

日期：2026-10-04。用户已确认在现有 Yuxi 中增加左侧“家庭档案”，并实现页面、后端保存及成员授权。

## 目标与页面

现有 AppLayout 增加一个登录用户可见的家庭档案入口，路由 /family。复用 PageHeader、Ant Design Vue、主题变量和 ECharts。页内四个视图：成员档案、健康指标、统计概览、授权管理。首次无数据时创建家庭并建立本人档案；允许加入其他家庭，切换家庭和成员。

## 数据与权限

PostgreSQL 保存家庭、成员、档案版本、测量记录及审计。家庭管理员可添加昵称与关系；其他成年成员通过短期邀请代码登录认领本人档案。邀请只用于认领关系，不直接授权健康数据。认领后由本人设置家庭营养管理用途、可访问字段与有效期，授权同时包含这些字段的查看和代维护。本人始终能管理本人数据；其他成员仅在授权有效时访问指定字段，系统管理员也不绕过。

字段包括性别、出生日期、身高、活动水平、目标、病史、用药、医嘱、过敏原、忌口、偏好及体重、血压、血糖、血脂。缺失保留空值，过敏原与忌口分开。原型阶段未做的监护身份验证不以一个勾选框替代；一期页面只接受本人认领的成年成员授权。

## 保存与统计

档案更改使用 expected_version 校验，确认和修改分别留痕，保留历史版本；未确认或关键字段不全明确展示。测量保存数值、单位、测量条件、时间、来源及备注，采用客户端生成的 UUID 防止重复；更正保留旧版本。服务端拒绝未来测量时间、非有限值、非法测量结构和跨家庭成员 ID。

授权失效后查询、写入、历史与聚合均停止访问。请求都使用服务端认证身份。前端每次切换重新加载，取消旧请求状态写回；没有浏览器持久化健康资料。授权修改与业务读写以家庭行锁排序，避免撤回与写入并发绕过。

统计只汇总所选期间当前可见的有效记录和档案状态。个人趋势单成员、同指标、同测量条件，不混合成员；缺失不补零，无疾病推断、临床阈值和健康评分。导出受当前访问范围限制。

## 实现与验证

API → service → repository → PostgreSQL。业务 schema 从 7 升级为 8，仅由既有 storage-migrator 幂等创建新增表并记录版本。API/worker 只检查版本。

先写权限、过期、撤回、版本冲突、重复写入及统计测试，再实现后端和页面。使用独立 PostgreSQL 和已有镜像的依赖验证，避免改动其他仓库运行服务；验证 lint、unit、build 和浏览器核心操作、浅深主题、窄屏、空状态与错误恢复。正式环境部署前需要执行迁移并重启 API/worker。

范围不包含 Agent 追问、配餐、专业复核、商城、小程序或临床评估。
