# 商城数据库直读搜索交接

日期：2026-11-06。接收方：商城数据库与部署负责人。范围：咨询 Agent 的 SKU 发现。用户已授权本轮同时修改 `agent/` 与 `shop/`；Shop 侧操作说明见 `shop/docs/agent-catalog-readonly.md`。

## 当前实现

Agent 设置 `HEALTH_COMMERCE_SEARCH_DSN` 后，先用商城签名接口读取当前有货分类并校验本轮分类回执，随后通过只读 PostgreSQL 连接筛选 `fa_shop_goods_sku`、`fa_shop_goods`、`fa_shop_category`、`fa_shop_ingredient`、`fa_shop_ingredient_alias`、`fa_shop_ingredient_sku_map`，读取所选分类中最多 3 个当前可售 SKU 身份和目录版本。当前页名称与规格由随后的商城详情接口构建，避免两次读取间商品变化造成旧索引。未设置 DSN 时保持原来的商城接口按分类读取目录路径。设置 DSN 后若数据库不可用，本次搜索返回明确错误，不静默把慢路径当成新路径成功。

条件查询支持商品名、SKU 名称和编码、分类名称和编码，以及当前已审核、有效的食材名称和别名。按 SKU 主键稳定排序，使用偏移量分页，单页额外取一条判断下一页，不为每次查询扫描计算精确总数。数据库结果只用于候选发现；Agent 对本页最多三个候选仍调用既有 `GET /api/v1/integration/ai/catalog/skus/{sku_id}` 获取商城加工后的配料、说明、价格和库存。历史展示和购买来源核对也按该 SKU 详情回源。核价、下单和支付继续由商城交易服务负责。

Agent 侧代码位于 `backend/package/yuxi/repositories/shop_catalog_repository.py` 和 `backend/package/yuxi/services/conversation_purchase_service.py`。商城表结构、发布规则及字段变更由商城负责人维护；变更后需通知 Agent 负责人更新查询与测试。

## 商城负责人需要交付

1. 提供与商城生产数据库连通的**私有网络路径**，不要公开 5432 端口。API 和 Worker 都需具备相同的访问能力。
2. 创建专用只读数据库角色，仅授予数据库 CONNECT、`public` schema USAGE，以及上述六张商品/食材表和 `fa_shop_catalog_version` 的 SELECT；不授予用户、订单、支付或健康资料表权限。凭据通过部署密钥注入 `HEALTH_COMMERCE_SEARCH_DSN`，不写入仓库或日志。应限制来源地址、连接数和查询超时。
3. 在实际数据上检查 `EXPLAIN (ANALYZE, BUFFERS)`。名称、SKU 编码、分类和食材别名的模糊匹配可能需要 PostgreSQL `pg_trgm` 索引；索引由商城负责人评估和维护。确认可售过滤与 Shop 当前发布规则一致，尤其是 `agent_visible`、`catalog_status`、商品状态、删除标志及 `stocks-reserved_stock-safety_stock`。
4. 在隔离环境验证只读角色无法执行写操作、无法读取用户和交易表；验证名称、分类、已审核食材及别名、空查询、分页、下架、库存归零、映射失效和歧义别名。商品目录变更后，旧候选的详情回源必须反映变化。

## 联调与启用

商城访问路径、只读角色和索引准备好后，刘潇在 Agent API 与 Worker 同时注入 DSN，使用合成数据先联调真实数据库和商城详情接口。比较原全目录路径与直读路径的数据库耗时、接口请求数、返回字节、Agent 工具耗时、模型输入量和最终答复 P50/P95。确认受限档案的配料核对、商品变更失效、旧回执以及正式客户端购买流程后再启用。

当前 Agent 直读代码、Shop 只读授权与索引脚本、同机私有网络叠加配置及合成验证已准备好。尚无真实商城只读凭据和网络连通验证，也没有真实提速数据。不要把已写代码等同于生产可用。
