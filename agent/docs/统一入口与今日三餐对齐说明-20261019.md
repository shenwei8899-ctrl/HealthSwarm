# 统一入口与今日三餐对齐说明

## 修改范围

统一入口以同事发布的 `family-unified-20261019-199d0a52af` 前端和 `unified-commerce-20261019-bb472cf7e8` 后端、商城为对齐基线。登录后的账号页、原餐单采购入口、商城会员关联、购物车、地址、订单与支付身份接口沿用该版本。新增今日饮食安排、饮食建档和今日采购入口，不覆盖原入口。修改前源码、服务器源码快照和合并记录保留在本地独立目录。

建档后的三餐使用持久后台任务执行；完整三餐、营养与来源校验、可售食材匹配和最终保存完成后，聊天页面先显示搭配说明，再显示今日安排卡片。当天再次进入只读取已保存结果；详情与采购绑定同一安排以及已保存的采购包编号、版本。单餐调整保留原完整快照，成功后替换；已支付订单和履约快照不参与改写。

每日配餐优先复用统一入口的商城地址配置，兼容已有配置名。商品匹配只使用已审核映射，按逐人需求、逐餐整包数量核对共享库存。商城再次检查提交的SKU、食材覆盖量和合计库存；既有相同单位及可选食材契约继续有效。采购来源使用签名及逐餐内容摘要回读，撤权或替换本餐后旧来源失效，修改其他餐时保留未变餐次采购依据。

配餐模型选择已确认为 DeepSeek-V4-Flash；模型启用设置与处理政策继续保留为待验收项。不编造政策、批准规则、菜谱来源或商品映射，不将合成验收数据写入生产。

实现取舍见[今日安排的后台完成与真实来源接入](../Yuxi-main/docs/develop-guides/decisions/proposed/2026-10-19-daily-arrangement-completion.md)。

| 范围 | 结果与边界 |
|---|---|
| 小程序前端回归 | `npm test`：282项通过 |
| 后端与真实数据库、HTTP | 以统一版本镜像和候选源码运行：164项通过，7项微信接口测试因缺少专用测试数据库、Redis环境而跳过；每日安排的PostgreSQL和HTTP测试未跳过 |
| 商城合计库存及覆盖量 | `test_daily_commerce_contract.php`：7项通过；覆盖缺货、未审核映射、覆盖量不足、单位不匹配、既有单位和可选食材；使用独立输入，不连接生产数据库 |
| PHP语法 | 对齐的15个商城文件通过 |
| 前端构建 | 正式API模式H5和微信小程序编译通过；小程序编译使用本机联调地址，不代表真机验收 |
| 实际浏览器 | Tabbit检查本地正式构建：原账号登录落点、说明先于卡片、同版本餐次详情、异常不显示空卡片、采购包编号和版本一致；已保存安排访问没有生成写入，未出现页面异常 |

浏览器仅拦截本机验收地址的HTTP响应，使用明确标注的合成账号和菜单，验收结束清理会话。它证明页面与接口契约的连接，不代表真实模型、商城生产交易或营养专业结果验收。
