# Yuxi 上游升级交付说明

## 升级范围

基于 [上游提交 031e2c7](https://github.com/xerrors/Yuxi/commit/031e2c72681edb8f95f71b60ceb66881f7915b8d)（2026-09-29，版本 0.7.3），同步完整 Yuxi 源码并合并家庭档案。工作位于 `agent/Yuxi-main/`；没有另建应用。升级前的差异来源见 [原功能核对快照](./2026-10-04-Yuxi原功能保留与差异核对.md)。

| 模块 | 保留内容 |
|---|---|
| 智能体 | 对话、智能体管理、预置角色、SubAgent、定时任务、运行与调试入口 |
| 个人空间 | 项目、文件、附件及工作区接口 |
| 知识与扩展 | 知识库、图谱、评估、Skills、工具、MCP、模型配置 |
| 平台管理 | 用户、部门、系统设置与 Dashboard，沿用原角色权限 |
| 家庭档案 | 左侧菜单及成员档案、健康指标、统计概览、授权管理；后端保存、版本和幂等控制 |

正式应用注册 235 个 OpenAPI 路径。注册与入口验证证明模块同时装配，实际模型、检索和交易结果仍需各自业务验收。

## 文件与数据处理

上游 1325 个文件均存在；9 个已有修改文件通过三方合并保留家庭接线与兼容逻辑。上游移除或重组的 99 个旧文件，在确认没有本地修改后移到忽略的备份目录。它们主要涉及 Skills 拆分与文档归档，采用上游替代实现；完整路径及同内容映射见 [上游重组文件清单](./2026-10-04-Yuxi上游重组文件清单.md)。

升级前源码备份、原 diff 与 SHA256 清单位于 `agent/.tmp/yuxi-upgrade-20261004/`。二进制文件按上游原字节保留，5 个上游脚本的 Git 执行位已恢复。脚本执行位与两个新上游脚本当前位于暂存区，其余改动保留工作区，没有提交。备份目录同时包含数据库备份与本地验证输出，被 Git 忽略，不提交或公开分享。

组合 business schema 为 **10**，knowledge 为 **2**。唯一 `storage-migrator` 接受未版本化数据库及 2/7/8/9；在旧版本补建家庭表，保留上游资源选择迁移到 9 的原子步骤，完成迁移后记录 10。当前版本重跑不改写资源选择中的空数组。本地家庭 8 的历史结构先执行业务结构收敛，API 与 Worker 只校验当前版本。

已有账号及家庭数据已从备份恢复到本项目独立的持久化 PostgreSQL。数据库回读确认账号角色保留，合成验收家庭与 2 条指标记录保留；没有读取其他项目的数据或凭据。家庭邀请沿用原派生密钥。

## 当前本地入口

- 页面：<http://127.0.0.1:5178/family>
- API：<http://127.0.0.1:55058/api/system/ready>
- 应用使用 `server.main`、正式路由及独立 Worker；旧家庭预览 API/Web 已停止。
- 已有登录账号可继续使用。普通用户遵循原有权限：管理接口返回 403；家庭管理员仍须成员明确授权才能访问健康信息。

运行配置为子项目忽略的 `.env`，独立状态目录在 `agent/.tmp/yuxi-upgrade-20261004/runtime/state/`。本地 Compose 使用既有镜像中的依赖与本项目挂载源码；该镜像来源不改变数据隔离。复用本地环境时，从 `agent/Yuxi-main/` 执行：

```powershell
docker compose -f docker-compose.yml -f ../.tmp/yuxi-upgrade-20261004/runtime/compose.local.json up -d --no-build
```

标准部署按 [Yuxi 开发约定](../Yuxi-main/AGENTS.md) 准备运行配置并构建本项目镜像。迁移前停止业务写入，保留数据库和文件备份；回滚源码时须同时恢复匹配的数据库版本。
