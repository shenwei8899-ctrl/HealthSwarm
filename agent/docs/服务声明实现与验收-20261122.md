## 用户可见行为
欢迎页在微信登录按钮下方展示简短文案“我已阅读并理解《服务声明与健康提示》”，默认不勾选；点击独立声明标题只读查看全文，关闭不自动勾选、登录或保存确认。明确勾选当前版本后才显示微信原生手机号授权按钮，仍需用户主动点击。取消勾选、账号变化、离开页面或版本拒绝后清除本次确认。已有会话但未绑定手机号时，将已经明确勾选的确认绑定本人账号，避免进入首页重复确认。

AI 首页及其欢迎回退界面暂不显示饮食建议参考提示。老用户首次进入首页异步补确认，可关闭；新 AI 操作需要确认，账号、订单、售后和历史读取保留原权限路径。“我的 → 设置 → 隐私与账号”增加只读全文入口，显示版本、生效日期与本人确认状态。

## 服务端事实与接口
`GET /api/service-notice` 公开读取当前版本与正文摘要；`GET /api/account/service-notice` 读取当前认证账号状态；`POST /api/account/service-notice` 提交版本、正文摘要和 `acknowledged: true`，拒绝代选账号及客户端时间。微信登录增加独立 `service_notice` 字段，新注册必须明确确认；注册、身份关联与确认记录同事务提交。

业务 schema 升至 17，迁移新增 `service_notice_acknowledgement`，按账号 UID 与版本唯一保存首次服务端时间。历史用户不回填任何确认事实，记录独立于成员健康数据处理授权。声明正文或确认文案变化时必须增加 `NOTICE_VERSION`；同一版本正文不可覆盖。

健康 Agent 提交、意图分类、独立计划、显式重试、后台排队与模型外呼边界核对声明；迁移前未确认账号的 pending 任务不会先发起新的模型调用。公共历史读取授权保持原有逻辑。服务端明确返回声明拒绝后，客户端确认并仅重试同一请求一次；换账号或家庭不重放旧请求。确认回执丢失先读取本人状态。声明接口失败属于原 AI 请求的明确拒绝，不当作 AI 写入结果未知，也不轮询不存在的请求。
