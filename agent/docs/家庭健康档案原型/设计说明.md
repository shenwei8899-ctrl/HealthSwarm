## 2. 交互稿的功能范围

| 页面 | 核心内容 | 核心操作 |
| --- | --- | --- |
| 家庭概览 | 成员建档状态、授权可见人数、期间记录量、待补充事项 | 按日期筛选；从待完善事项进入对应档案 |
| 健康档案 | 成员基础信息、活动水平、目标；按授权展开健康信息；完整度、版本、来源和确认时间 | 搜索和切换成员；添加、编辑、确认档案；查看变更 |
| 健康趋势 | 单成员的体重、血压、血糖、血脂记录；单位、测量条件、时间、来源与历史 | 切换指标和日期；录入、更正记录；查看缺失状态 |
| 授权管理 | 授权对象、成员、字段、用途、期限及状态 | 发起申请；由本人或适当授权人确认；撤回；查看记录 |

健康信息包含用户填报的病史、用药与医嘱、过敏原、忌口及偏好。过敏原与忌口分别维护；未填写与明确“无”分别表达。高级或敏感内容通过详情页渐进展开，避免首页一次展示全部字段。

建议主流程：进入家庭 → 选择成员 → 核对访问范围 → 补充并确认档案 → 记录健康指标 → 查看历史趋势 → 根据需要更正记录。

新增其他成年成员时，基础成员关系与健康信息授权分别处理；添加成员不自动开放其健康详情。更正测量值保留原记录、原因和操作历史。

## 3. 看板口径

看板首先回答“资料是否可用、记录是否持续”。统计范围及更新截止时间应始终可见。

| 指标 | 定义与展示规则 |
| --- | --- |
| 家庭成员数 | 当前家庭中处于有效状态的成员数量 |
| 已授权查看人数 | 当前操作者可查看所选健康字段的成员数；本人与代理授权分别说明 |
| 关键档案就绪人数 | 选定业务能力所需字段齐全、已确认，且用途授权有效的成员数 |
| 待补充档案数 | 当前可维护范围内，仍缺少该业务能力关键字段的成员数 |
| 本期指标记录数 | 选定期间、当前授权范围内的有效测量记录条数；更正后的同一条记录不重复计数 |
| 本期记录人数 | 上述有效记录对应的去重成员数 |
| 指标记录趋势 | 按测量日期统计条数，纵轴为整数；区分无记录、未授权与加载失败 |
| 个人指标趋势 | 单成员、同指标、同单位及可比较测量条件的实测值；缺失不补零、不生成推测点位 |

“信息已确认”与“关键档案就绪”是不同状态。已确认的档案仍可能缺少某项评估所需信息，不能用一个标签同时表示二者。

家庭概览可汇总记录量；个人趋势保留成员维度。血压保留收缩压和舒张压；血糖区分空腹、餐后等测量条件；血脂分项展示。默认不计算跨成员健康指标平均值，不使用无专业定义的家庭健康评分。

平台运营看板在后续独立页面按角色提供聚合数据，例如完成建档家庭数、7 日活跃家庭比例、菜单确认率和专业复核情况。本次视觉草稿展示家庭侧档案与记录统计，不代表运营人员获得成员健康详情的访问权。

## 4. 必须表达的状态

- **待授权：**隐藏未授权字段及其指标、趋势、近期记录；入口说明由谁确认和需要哪些权限。
- **待补充：**列出缺少的具体信息，并说明影响哪项能力；完整度不表达健康好坏。
- **未记录：**显示缺口及录入入口；不与数值为零混同。
- **待确认：**导入或代理填写的信息先由有权确认的人核对，保存确认时间和版本。
- **保存失败或版本冲突：**保留输入，提供重试或核对最新版本的路径。
- **授权撤回：**后续读取立即受限；正式实现需清理相应缓存和已展示的敏感数据。
- **数据请求：**更正、导出、撤回与删除申请具有明确状态和处理结果。

## 5. 与现有项目的衔接

交互原型在本目录交付；正式功能开发优先复用 `agent/Yuxi-main/web/` 的布局、Ant Design Vue 组件、现有图标、主题变量和图表能力。

普通档案操作和指标统计通过业务接口完成。授权校验、版本控制、事实数据和计算结果由服务端保证；涉及 Agent 的理解或解释功能单独接入，并只读取当前任务所需的授权信息。

按照既有分工，开发者 A 负责档案、授权、指标及统计接口；开发者 B 负责 Agent 所需工具与交互协议。页面实现的人选需在两人排期中明确，不默认已经包含在原有后端分工工期内。
