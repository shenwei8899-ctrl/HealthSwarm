# 动态商城配餐 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 在不改变三方页面外观的前提下，让 Agent 快速、动态地读取商城已上架商品，按真实家庭档案生成可替换且尽量不重复的菜品，并异步准备菜品图片。

**Architecture:** 商城继续作为商品、规格、库存与营养说明的唯一事实源；Agent 通过轻量版本探测维护版本化内存快照，配餐匹配只使用商城返回的结构化食材映射和别名。菜谱图片在餐单保存后交给既有持久任务后台生成，不阻塞文字和卡片返回。

**Tech Stack:** ThinkPHP/PHP、FastAPI/Python、SQLAlchemy/PostgreSQL、既有 Durable Task/Worker、pytest/PHPUnit。

## Global Constraints

- 仅修改本地代码，不发布线上。
- 不改小程序、Agent 管理端和商城后台页面外观。
- 不伪造商品、库存、营养、审核或健康资料，不自动把待审核改为通过。
- 不创建或操作真实订单。
- 商城商品变更必须能被 Agent 在短周期内感知，同时不能每次配餐全量拉取。
- “再换一批菜”保持日期、就餐人和餐次上下文，并排除近期已选菜谱。
