# 健康报告逐页复核

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_vision_tasks.py

## 问题

多页报告需要同时表达执行终态与单页识别结果。整份执行完成不能证明每页识别成功；正式指标需要可追溯的原页映射与用户对不完整报告的明确处理决定。

## 决策

执行器仅将供应商超时、失败及受控解析错误转为服务器拥有的页失败状态，继续处理其余页。授权、同意、政策、源文件、取消及租约异常仍终止整份任务。至少一页成功才形成候选草稿；全页失败保留整份失败与显式重试语义。部分结果的 job phase 为 partial_ready，Task 成功只表达结果已生成。页状态、稳定错误代码和分辨率提示保存在草稿快照，客户端修订必须保持这些原始元数据。确认用例拒绝尚未显式排除的失败页，accept_incomplete 不能绕过。

ReportReview 提供私有鉴权原页预览、明确排除及恢复操作与缺页提醒。页面将识别状态、人工排除状态、持久化确认状态分别投影；已确认快照保留失败与排除事实。confirmed 属性读取草稿 review_status，忙碌期间的 readonly 不代表已确认。排除操作通过事件交给父页面保存，同时撤销旧人工复核勾选。

低分辨率提示只依据实际处理页短边，不声称自动判断模糊、反光、截断或实样准确率。旧页快照默认识别成功，修订时通过同一 DTO 补默认字段保持可读。失败页的选择性重识别、版本合并和历史 receipt 由[失败页重识别决定](2026-10-04-health-report-reprocess.md)拥有，本记录只解释逐页复核与确认语义。

## 替代方案

整份失败保留简单执行语义，但缺少部分成功的复核路径。所有异常逐页吞掉会把撤权与租约失败误记为可继续识别。自动排除失败页消除人工判断，不符合明确确认要求。

## 后果

本地合成协议验证不证明真实识别准确率。部分失败草稿提供显式排除、重新上传及[单页重识别](2026-10-04-health-report-reprocess.md)，服务未配置时重识别按钮禁用。成功页暂不持久化单页模型结果，整份失败后重试仍有重复模型调用的窗口；OCR checkpoint 恢复语义沿用[已有决定](2026-10-04-health-ocr-resume.md)。本记录补充[健康识图工作台](2026-10-04-health-vision-workbench.md)，不声明完整详细设计已完成。
