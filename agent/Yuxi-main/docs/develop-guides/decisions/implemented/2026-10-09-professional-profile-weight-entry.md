# 专业档案导入与明确体重选择的后台入口

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_profile_import_service.py

## 问题

专业确认投影和选定实测体重已能通过接口进入营养目标及配餐检查，但后台缺少明确选择与核对的入口。专业操作者无法在页面区分投影导入成功、目标缺失和旧餐单审核失效；管理员身份及健康档案授权也不能代替原始家庭字段读取授权。

## 决策

增加一个专业导入上下文GET，HTTP与service均复核管理员，并分别核对健康成员的profile_edit与profile_view。复用统一当前专业投影，提供真实当前/下一版本。原始来源读取在健康成员锁后取得当前操作者可见的家庭锁，核对有效本人来源关联，再用现有authorized_fields计算字段、用途与期限。只返回有权且必要的基础字段；完整REQUIRED_PROFILE_FIELDS读取权才公开本人确认状态与导入来源坐标。体重候选另外要求weight字段读取权，按有效未作废、非未来记录分页，保留显式较旧记录选择；损坏持久化值明确拒绝。无原始访问权时相关区块为not_ready，不输出来源ID或值。当前专业投影按独立健康授权读取，原本人咨询接口保持原契约。

在健康识图的本人档案分区增加专业导入组件，来源坐标与选定体重ID/版本来自受权服务响应，操作者明确选择并确认外部专业载荷及依据。未知或明确无的六组专业状态由专业内容直接提供，页面不从原文填临床值。提交复用ProfileImport版本/摘要幂等接口；未知写入结果保留同一完整请求重试，成功回读与目标读取分开。批准规则代码由操作者明确输入并读取当前规则版本，目标直接展示服务端结果和缺失项。成员、账号、权限变化立即清空，迟到响应不能重填私有状态。

餐单草稿复用现有approval-state服务，在不可采用时重验当前版本最近复核的来源并返回实际状态和失效原因，页面据此提示并返回档案分区。pending_review展示等待专业审核；餐单列表或审核读取的健康授权403/404响应统一清除私有状态，并推进请求代次，使迟到的预览、保存、换菜、生成结果和补充问题失效。保存及换菜在详情回读后再次校验原请求代次，避免审核读取拒绝后继续恢复旧结果。普通网络错误、错版本提示、未知写入的同包重试和取消404恢复沿用既有语义。生成时快照有明确标题及说明，当前可用性由服务端回读管理；专业复核与正式采用仍由既有服务执行。

验收范围限定授权后台读取、明确导入、目标展示及餐单状态提示。生产专业字典、公式与适用人群、其余参数语义、完整多人产品流程、小程序和真实外部模型质量继续待交付；不新建数据库表或修改模型处理审批。

## 替代方案

直接放开本人实测接口会改变既有本人身份契约。前端用健康授权猜家庭原始字段权限会绕过用途与期限。全量专业管理后台和自动临床编码超出当前入口需要；复用现有导入、目标及复核服务，只增加必要受权上下文及当前状态投影。

140项相关backend单元测试通过，由96项上下文与体重来源回归和44项复核状态、质量及采用回归组成，无重叠。13项唯一真实TCP/PG案例已验证：上下文集合11项中8项按原函数通过，其余3组校正错误响应断言后通过；当前审核状态2项通过。自然过期案例只推进真实TCP服务同进程的来源门禁时钟，先回读专业投影reason=expired，再确认未批准复核失效；PG依据、有效期和摘要保持原值。

最终117项相关前端测试、530项全量前端测试、全前端lint和build通过，覆盖真实SFC渲染、明确体重选择、零值与单位、同包重试、明确成功回执与较高当前版本及撤权响应。餐单组件的30项包含12项新增异步回归：分别以403/404拒绝清除旧状态，随后送达旧预览、保存、换菜、生成草稿、补充问题及审核响应，确认私有内容不能恢复。原实现运行同一30项时，12项均在业务断言失败；修正后全部通过，独立审查再次运行30项通过。517项及70项保留为较早阶段的通过记录，当前全量结果以530项为准。

入口开发阶段冻结的17份源码通过真实浏览器HTTP/PG E2E 1项（346.86秒）。已有较新90kg仍明确选择65日前60kg，专业版本1目标由独立手算30+5×60=330核对。家庭指标页面更正所选记录至61kg/测量版本2后，在任何审核GET之前直接PG确认review/adoption失效。页面回读失效原因并返回档案分区，旧专业载荷隐藏；重新专业确认版本2的目标为335，旧快照不变且旧批准不恢复。全部数据和公式为合成测试材料，配置的模型审批字段保持关闭，无新增同意或AgentRun。验收配置比较保留所有模型、处理方和政策字段，只排除夹具发布菜谱而增加的food_count目录显示计数。其后的餐单请求代次修复通过上述真实SFC异步回归和独立复核验证，未重新运行浏览器E2E，不将较早冻结源码的浏览器结果描述为最终提交的浏览器验收。

九项权限缺陷与两项审核状态缺陷通过独立进程恢复负控被业务断言捕获，符号随后恢复且未修改生产文件。发布检查中后端非slow全量单元测试3772项通过、59项跳过；66份变更Python文件Ruff及格式检查、63项工程检查器unit通过。入口开发阶段的17份源码差异与补丁回放保留为历史证据，发布时另冻结完整暂存补丁并独立复核。错误响应断言及浏览器夹具早期失败保留，不计入通过数量。

验证入口为现有默认Compose API中的上下文及复核状态unit/HTTP测试，以及隔离health-diet-analysis-e2e API中启用HEALTH_CONSULTATION_E2E_ISOLATED与独立HEALTH_PROFILE_IMPORT_UI_CONTROL_DIR的test_health_professional_profile_ui.py。浏览器控制文件只同步阶段，独立HTTP及PG断言拥有业务结果证据。

## 后果

现有家庭字段授权仅支持本人及获得本人授权的家庭管理员；任意专业账号没有自动原始字段读取权。界面明确告知所需授权，保留现有用途、期限和专业内容确认职责。专业投影已导入不代表目标、安全检查或审核通过，完整角色与父项继续部分完成。本地设计Word、Excel和记录Skill不提交或上传。
