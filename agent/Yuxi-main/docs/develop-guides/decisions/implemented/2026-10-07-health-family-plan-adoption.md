# 家庭餐单的逐成员正式采用

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_plan_adoption_service.py

## 问题

六 Agent 工程范围要求家庭配餐可明确采用并被各参与成员的今日来源读取。入口成员的唯一约束无法表达共同餐单与单人餐单的参与者占用。读者为健康后端维护者和接口联调人员，完整目标见[六 Agent 工程范围](../proposed/2026-10-07-health-agent-engineering-completion.md)。

## 决策

复用既有采用及专业审核 Owner，保存当前批准的完整不可变快照。新增账号、成员、日期唯一的采用指针表，全部实际参与者指向同一采用；指针只在关联采用仍 active 时表达有效占用，来源失效、取消及替代沿用采用状态，不复制状态。Schema 增量迁移回填旧单成员 active 采用，重复迁移不覆盖当前指针。

明确采用必须选择全部档案版本和当前专业批准。新输入允许选择多项替代采用及各自版本，原单对象选择保留；实际占用集合与选择集合须完全相同。替换共同餐单会使其整体 superseded，包括未参加新餐单的旧成员；同一事务保存新采用、全部参与者指针和幂等动作，失败全部回滚。

用例先只读新对象及当日重叠占用，再按 ID 排序锁定新旧全部参与者并复核授权。锁后发现新的占用成员或计划参与者变化则要求刷新，不追加逆序成员锁。读取与取消共同餐单逐一授权全部历史参与者，今日读取返回当前选定成员的覆盖餐次及个人营养投影，不把家庭合计视为个人全天结果。

该阶段不包含参与者调整、家庭模型处理同意与工具、初始个体化生成、日终提议、21 天控糖及采购，六 Agent 目标继续执行。红阳完整档案和专业生产验收保持外部未交付状态。

## 替代方案

只移除单成员 guard 会继续只占用入口成员。将家庭采用复制为多条独立采用会允许部分取消或失效并破坏共同版本。一个采用加逐成员指针保留共同状态和数据库唯一占用位置；既有不可变快照提供历史成员集合。

## 后果

家庭采用锁定新旧参与者集合。未参加新餐单但属于被替代共同餐单的成员同样需要当前编辑授权；否则明确拒绝操作。旧失效指针不占用有效餐单，新采用可更新该位置；读取仅通过 active 采用，并复核当前专业批准。今日读取等待锁后重新选择指针，新的成员集合超出已锁集合则返回冲突并要求刷新。

旧单成员采用的幂等参数摘要保持兼容。Schema 12 从既有 active 采用回填逐成员指针，保留历史采用、动作、修订及专业证据。家庭多成员工具和处理同意尚未发布，现有家庭模型入口仍明确拒绝；正式采用由用户明确 API 动作触发。
