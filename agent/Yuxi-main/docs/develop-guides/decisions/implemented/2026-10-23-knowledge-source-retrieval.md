# 知识库正文与导航检索分离

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/knowledge/implementations/milvus.py

## 问题

分类目录、来源摘要与原文一起参与向量检索。命中目录只能得到文件指针；部分专题库虽然关联其他库的原件，当前检索仍只返回短摘要。文件已索引不能证明 Agent 获得了回答所需的正文。

## 决策

### 实现方案

Milvus 执行器读取当前库查询参数中的 `excluded_file_ids`，在向量、BM25 和混合召回之前应用文件排除条件，并在图谱融合后再次排除这些文件。Milvus 召回中的既有文件名过滤继续取交集。参数只改变检索相关性，不授予任何读取权限；直接搜索文件与按 ID 打开原文仍使用既有权限检查。缺省空列表保持原行为，非法配置明确失败。

`KnowledgeBase.build_search_output` 为本地知识文件提供本站原文地址；`KnowledgeBaseManager.open_document` 的返回值保留实际窗口起始行。Web 原文页通过已有认证接口读取正文，显示带行号上下文、可展开的完整正文和版本变化提示。Markdown 渲染器将有效 `knowledge://` 指针映射到本站阅读页，保留代码块原文，拒绝外部域名和路径穿越形式。网页复用工作区解析文件下载接口，无需管理员界面权限；版本哈希通过下载响应头传递，文件读取权限仍由后端 owning repository 执行。

本次资料修复通过正常知识库接口新增带来源、版本和原件哈希的正文副本。原有目录和摘要保留，用排除配置避免作为正文命中。已归档原件先按文件 ID 回取，新增公开原文按实际许可与读取范围处理；正文完整性、表格和 OCR 限制明确记录，专业审核状态保持不变。

## 替代方案

删除目录会破坏既有文件引用和导航；仅在 prompt 中要求忽略目录无法避免目录占用召回窗口；直接清理向量会造成索引与文件状态不一致。查询时配置精确文件 ID 能保留原件且支持恢复，但需要导入流程对新增导航更新排除列表。

## 后果

精确排除列表由管理员维护，后续新资料仍需分类。原始文本和 OCR 不能自动成为经过专业审核的营养规则。部分来源有访问或再利用限制，保留明确缺口，不把摘要算作完整原文。生产部署只叠加到已核实的当前镜像，避免覆盖并行版本。普通读者通过既有工作区下载接口阅读正文；管理界面依赖仍限制管理员访问。
