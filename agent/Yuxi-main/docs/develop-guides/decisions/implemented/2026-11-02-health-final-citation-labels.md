# 最终健康答复的完整资料引用标签

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/middlewares/health_final_answer.py

## 问题

手机普通文字咨询的受控测试中，模型返回有效的本轮资料 ID，却漏写完整文件名，最终来源校验拒绝发布。另两次成功请求约耗时 28 至 31 秒；工具耗时不足一秒，准备阶段的首次模型输出不是用户可见首字。本决定只减少引用格式遗漏，不承诺整体延迟已经改善。

## 决策

### 实现方案

最终无工具模型调用从当前带 `health_request_id` 的用户消息之后的成功家庭知识工具回执提取资料 ID 和完整文件名，提供可逐字复制的引用标签。提示模型仅引用实际采用的来源，在对应完整句段后附标签并换行。旧请求、失败回执及其他工具不贡献标签。

原工具回执、checkpoint、正文、授权与来源校验不被改写。`health_family_kb_service` 继续校验当前来源及完整文件名，`TrustedHealthFinalAnswerStream` 仍只公开已经通过校验的完整句段；最终模型继续走原 handler、预算和用量链。

## 替代方案

放宽完整文件名校验会改变现有发布契约；程序无条件附加全部检索来源会把未采用的资料标成引用；失败后新增模型重试会增加延迟和用量。本方案保留这些边界，只改善最终调用的输入。

## 后果

2026-11-02：新增图回归在旧中间件上因缺少本轮完整标签失败，加入提示后通过。此前五文件补丁阶段（参考餐单224步及上下文精简修改之前），候选镜像组合回归为 176 项通过、当时源码 unit 为 5431 项通过。该五文件补丁于12:09部署到 API 与 Worker，并回读源码和 readiness。发布后手机普通问答成功一次：用户观察约33秒、服务端约26.4秒；首字时间未单独记录。一次成功不足以证明稳定性或提速。

提示不能保证供应商始终遵循格式；仍需真实模型验收。模型准备、网络、知识检索和引用校验各有耗时，资料标签不等同于整体提速。正式专业资料未交付，不因普通科普测试通过而完成专业业务验收。
