# 成员识图运行统计

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_vision_statistics.py

## 问题

健康报告与饮食识图设计要求耗时、失败原因、用户修订和营养数据缺失的可观察统计。最近五十条任务及一百条正式记录不能证明完整统计，模型请求成功也不能证明识别正确。统计必须遵守成员和用途授权，不能通过管理员看板泄露健康资料。

## 决策

只读接口按成员和用途查询三十天运行摘要，repository 从 PostgreSQL Task 时间点、健康任务、已确认草稿与日记快照读取完整时间窗；不复用有条数限制的列表。报告需要 report_view，饮食需要 diet_edit，与授权撤回共用成员行锁；管理员没有旁路。失效源及草稿不计入摘要。任务按创建时间取队列及执行样本，复核按确认时间取样，返回窗口、分子、分母和耗时样本数。P50/P95 使用最近秩定义；缺少或颠倒时间点不计入耗时，不补零。响应只返回计数、稳定错误代码与时间窗，不返回健康正文、原图、对象键或 Task 原始错误。

报告仅比较原始 OCR 项与确认项的名称、代码、结果、单位和参考范围；日期与空腹补充不当成识别纠错。饮食比较原始菜品名称与确认名称，食品映射、份量填写不当成识别修改。排除、删项和人工新增另计；未确认修订不计。份量来源和营养缺失从已确认日记快照统计。页面在报告及饮食任务区域提供折叠摘要，按需读取；切换成员或用途立即清除旧数据，拒绝迟到响应。

费用保持未知，模型识别准确率需要独立标注样本；成员摘要不批准真实云处理、模型采购、临床规则或食品许可，也不取代部署预算控制、全局报警及供应商账单验收。

## 替代方案

统计最近列表会截断样本；只用草稿版本号会把日期补充和失败页重识别误认为人工纠错。单独保存统计表会复制现有事实并增加同步和删除恢复负担。跨成员管理员统计需要额外的隐私及运营权限契约，成员摘要不扩展现有管理权限。

统计单元十二项通过，两项专属真实 HTTP / PG 通过；修订及确认使用真实接口，识别初始候选和 Task 时间点由合成 PG fixture 显式准备，不冒充实际 OCR 或 worker 结果。相关健康单元与完整 HTTP 文件联合一百项通过，耗时 56.36 秒；扩大到报告表格、坐标、重识别、OCR 恢复及份量回归后三百七十三项通过、一项报告隔离 E2E 明确跳过，耗时 65.06 秒，两次均有四条既有 psycopg_pool 弃用警告。相关前端三十七项通过，lint 及 build 退出零；build 保留既有大块提示。独立 Reviewer 复测十二项 Python 与七项前端用例；六项进程内负控证明补零、错误分母、人工来源入样、正文泄漏、失效源和迟到响应会被正确原因拒绝。Reviewer 未独立复跑共享 HTTP fixture。

真实浏览器检查无成员、空样本、撤权后刷新错误及窄屏单列；窗口恢复默认。只创建无真实身份的合成成员，验证后回读零上传、任务、草稿及正式记录，精确清理该成员与唯一授权，不删除原账号或其他数据。主题偏好没有修改授权，深色视觉为 Not run；使用既有语义 token 不能替代实际深色验证。命令由[统计测试规范](../../testing-guidelines.md#健康识图运行统计验证)维护。

## 后果

个人修改可能是偏好或补充，不能代替专业标注准确率。三十天按创建和确认分别取样，页面展示口径，二者不代表同一批任务。删除资料后摘要随当前可见性变化。当前没有完整供应商计费账本，不能估算成功业务成本或将费用填成零。读取无需外呼或新增 Schema；真实供应商质量、部署报警、预算和专业知识引用仍需独立交付及批准。这里只交付成员侧运行摘要，不宣称完整设计的全局运营监控与真实质量验收已完成。
