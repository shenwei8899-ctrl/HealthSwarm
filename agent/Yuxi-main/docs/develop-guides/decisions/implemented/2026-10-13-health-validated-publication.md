# 健康解释正文在校验提交后公开

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/chat_service.py

运行中仅展示固定进度的限制由[校验后的句段流式展示](2026-10-27-validated-health-answer-stream.md)部分取代；本记录继续拥有原始候选关闭、权威结果事务与最终读取边界。

## 问题

普通营养咨询与血糖、血脂、血压三个记录助手在最终来源和引用校验之前，将模型正文、推理或工具内容送入普通流。最终拒绝发布不能收回客户端已看到的内容；重新订阅 Redis 事件、恢复 Agent 状态或读取 Run 进度也可能再次取得这些未校验内容。设计要求这四个教育角色只公开当前有效的权威结果。

本项对应本地计划 TODO12.6.3，改变公开时序与普通读取边界，复用当前授权、处理同意、来源版本、引用和事务校验。医学准确性、专业领域规则、真实供应商质量和正式微信客户端接入分别由其原任务验收；本项不将引用有效性描述为专业正确性。

## 决策

### 实现方案

`chat_service` 拥有普通执行及恢复执行的事件生产，四个教育角色只允许固定进度与独立校验后的句段预览，私有模型和工具审计继续经过独立受控接口。普通流不透传原始模型 delta、推理、工具输入输出、模型填充状态或自由错误文本。完成路径执行完整来源与引用校验，持久化同 Run 权威 Message、输出指针及完成状态，并提交 owning transaction；完成通知之后，客户端从结果、健康 Task 或普通历史接口读取正式正文。

`agent_run_service` 拥有 Run 事件、进度、状态及终态公开投影。在普通与精简模式、旧 Redis 事件重连和状态恢复中施加同一范围的公开白名单，不能用 `verbose=true` 绕过。完成通知不复制正文进 Redis，当前结果读取仍重验权限与来源；状态面板只保留确定的执行事实，模型填充的状态不能成为另一条解释发布通道。`run_worker` 保留实际首模型输出计时：内部进度只携带确认输出已经开始的有限标记，公开投影不透传这个执行标记，队列或普通运行进度不能提前记为模型输出。

`conversation_service` 的公开教育历史只读取当前有效的同 Run 权威正文，移除模型审计推理、工具候选及自由元数据。Run 与结果中的用量只投影非负整数、完整性标记和已批准模型配置，旧 PG 用量也经过这条投影。Worker 的异常或取消用量补偿沿内部 checkpoint 读取，核对当前用户、线程、Run、健康授权与 `current_run_id`，不会恢复模型填充状态到公开接口。`subagent_task` 传入实际角色，使共享进度包装沿相同公开边界。

独立审计接口保持超级管理员、会话归属与当前成员健康授权三项条件。完成事务失败不发送成功通知；未完成教育 State 缺失审计时跳过普通 AI Message 保存，有审计时仅对账审计，均不设置公开输出指针。两种 `verbose` 直接使用教育最小载荷，保留请求、Run、线程标识与进度阶段。

前端继续沿现有 Request/Run/Task 关联和终态历史回读补偿，预览始终让位于正式结果。不新增 Run 状态、数据库表、队列或平行事件引擎。非健康角色的流式协议与通用审批行为保持其原 Owner；教育角色的失败与中断只能公开固定分类，未校验候选只保留在受控私有审计中。

## 替代方案

仅在前端隐藏正文无法保护其他 API consumer、旧 Redis 事件及状态恢复。仅拦截 message delta 会遗漏推理、工具、状态和异常字段。将正文复制到新类型 Redis 事件会增加来源变化后的另一份公开真源。使用既有 PostgreSQL 权威输出和查询接口保持单一发布点，代价是等待校验结束后一次展示正文。

## 后果

客户端依赖终态通知后回读权威结果，网络故障仍需沿既有有界恢复。运行审计与普通输出有不同用途，公开过滤不能删除受控排障所需审计。旧事件需要在读取边界处理，单纯改变新生产者不足以关闭重连旁路。来源和引用校验不承担自动医学诊断或完整语义审核，生产知识与真实专业题集继续独立验收。
