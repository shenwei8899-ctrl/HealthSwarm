# 本人档案关联与咨询页面闭环

状态：implemented
类型：feature
Owner：web/src/components/health/HealthFamilyProfile.vue

## 问题

本人确认档案和健康对象使用独立成员 ID，需要用户从页面明确确认同一身份，并辨别未关联、待确认或已变更的档案。今日咨询沿用每日线程，档案来源改变后需要明确的新咨询恢复入口。

## 决策

### 实现方案

在健康后台当前成员下增加本人档案分区。API 封装复用现有关联 POST/GET 和档案 GET；候选来自当前账号家庭接口中的 is_self 成员。用户明确确认同一身份后关联，结果重新读取服务端事实；关联不自动签署模型处理同意。展示来源名称、确认版本、缺失字段和修改入口，完整营养安全语义继续单独待交付。

当前健康对象必须是本人且有相应健康权限，后台仍执行最终身份和授权检查。成员切换或组件卸载清空私有状态并丢弃迟到响应。关联和刷新保持幂等；已有来源只展示和刷新，不开放改绑。

进入咨询沿用独立用途、处理方和政策同意。今日咨询保留现有每日入口；来源失效时提供明确的新建咨询操作，通过已有幂等咨询接口创建新线程。未知响应重试及入口切换保留同一新建请求 ID；新建接口明确返回来源失效后，撤销该请求和旧同意，用户明确重建并重新同意。每日接口失效不推定未知新建请求失效。成员变化和卸载清空咨询状态，并拒绝旧回执导航。

该页面接续[本人档案受控读取](2026-10-08-family-profile-agent-read.md)。页面只保留来源、版本和缺口，详情使用既有家庭档案入口；服务端继续拥有身份、字段授权、处理同意、版本和最终结果检查。

## 替代方案

继续人工调用接口无法满足页面闭环。按姓名自动关联无法证明同一身份。所有咨询都改成新线程会丢失每日会话重入行为，因此保留每日入口并增加明确的新建操作。

页面与本人档案组件定向行为测试 30 项通过；咨询重放协议和营养师 unit 40 项通过。隔离合成槽位的实际浏览器通过家庭页面填写并确认身高 171 的版本 2、明确身份关联、独立用途同意以及真实 Agent 输入提交。Worker 输出与 PG 依赖均关联版本 2。页面改为身高 172 并确认版本 3 后，旧每日咨询返回 410；用户明确新建并重新同意，新 Worker 回答及 PG 来源依赖均采用版本 3。PG 独立核对唯一映射、两次 Run、最终消息、旧历史不可读及重复关联幂等。测试使用本地严格重放服务，不证明真实外部模型质量。

现有前端测试源码读取统一 CRLF→LF，适配 Windows 检出；原业务断言保持。三个原有失败测试文件定向 10 项通过。异步边界经独立只读复审，已核对未知响应键保留、卸载清理和明确失效后重建；真实接口权限沿用上游验收。

全量前端 unit 快照 469 项通过、零失败；后续新增的明确新建失效恢复用例包含在上述 30 项定向结果中。前端 ESLint、生产构建、修改范围 Ruff 及文档构建通过；工程检查核对 95 项 decision 与 230 页文档。实际浏览器/Worker/PG 同一独立场景两次均通过，失败的浏览器选择器探测不计为验收证据。桌面浅色及折叠导航后的窄屏截图已检查；深色加载过渡截图不作为稳定视觉通过证据。

## 后果

本阶段支持本人描述性咨询，完整临床安全编码、管理员代他人模型读取、独立测量与配餐安全映射继续待做。前端权限检查只控制体验，最终事实由现有后端拥有；真实外部模型质量独立验收。
