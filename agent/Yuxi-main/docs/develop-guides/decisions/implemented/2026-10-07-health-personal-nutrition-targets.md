# 外部批准公式驱动的个人营养目标

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_personal_target_service.py

## 问题

单成员三餐质量和重生成消费批准的通用每日范围，尚未计算基于当前确认档案的个人目标。配餐工程需要明确目标所用字段、公式、批准版本及缺失项，并在现有检查和重生成实际使用该目标。

## 决策

外部档案投影增加明确体重、身高、性别编码与活动编码。批准规则提供按人群、性别与疾病组合选定的公式、活动系数，以及五项营养的范围系数和常数。所有系数均由外部批准资料明确提供，代码不内置临床公式或默认系数，不从自由文本猜字段。

个人目标只按当前确认投影和当前批准规则计算，返回实际输入、公式选择、全部范围、档案/规则版本及依据。必须参与的字段缺失、编码/疾病组合未支持、公式结果超出计算域或源失效均明确不可用。零系数不强制收集未使用的字段。

规则提供个人目标条款时，质量检查将目标范围与通用条款及同时生效的医嘱求交，未知目标不能继续宣称通过。安全单菜候选与整份重生成使用相同检查Owner，实际修复个人目标冲突。没有个人条款的历史规则仍表达通用计划，不把它伪装成个人目标。

## 替代方案

直接内置常用热量公式会把尚未批准的专业口径变成代码默认。只展示计算结果而不约束实际计划会留下无法验收的孤立接口。使用批准投影及共享质量Owner将目标计算和计划使用闭合，保持历史通用检查契约。

复现入口由 `test_health_personal_targets.py`、`test_health_personal_targets_http.py`、`test_health_quality_replay.py` 和 `test_health_quality_e2e.py` 拥有；实际HTTP在隔离API进程执行，独立worker消费Run，PG回读检查、历史修订、专业状态及采用失效。独立复核通过；检查结果按现有规则允许提交专业复核，只有通过当前工程检查才可批准及采用。没有Schema变更。

## 后果

这是[六Agent目标](../proposed/2026-10-07-health-agent-engineering-completion.md)的个人目标阶段，家庭逐餐参与者还需消费同一目标及源版本。家庭计划、批准初始生成、控糖、采购与配餐Agent目标工具/协作仍按完整目标继续；红阳真实档案及专业生产公式未交付。数值目标就绪不替代配料安全字段齐全及完整计划检查。工程合成数据仅验证计算与门禁，不作为生产医学资料。
