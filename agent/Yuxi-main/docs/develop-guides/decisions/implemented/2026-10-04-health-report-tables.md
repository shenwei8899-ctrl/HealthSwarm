# 报告表格行证据

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/health_vision_provider.py

## 问题

本记录面向维护报告解析接口的开发者与 Reviewer。设计要求解析表格、逐行核验结果与单位、遮蔽身份资料，并保留原文证据。[PaddleX 表格产线](https://github.com/PaddlePaddle/PaddleX/blob/release/3.7/paddlex/inference/pipelines/paddleocr_vl/pipeline.py)将表格预测转换为 HTML，[结果序列化](https://github.com/PaddlePaddle/PaddleX/blob/release/3.7/paddlex/inference/pipelines/paddleocr_vl/result.py)保留该块内容。整表文本不满足指标行白名单；含身份行与两条指标的独立合成输入证明，未分行的表格外发指标数为零。

结果列不固定在第二格。参考范围、结果及单位可以调换顺序，同表再次出现未知表头时也不能继承旧列映射。HTML 解析器的容错还可能吞掉损坏尾部、声明及注释；有文本或已有闭合行不能证明整个表格结构已核验。

## 决策

真实解析适配器使用标准库读取单一 HTML 表格，解码实体、折叠单元格内部空白，以制表符保留同一行的单元格边界。上标与下标保留 `^` 和 `_` 文字标记，不进行单位换算。证据 ID 带页面、原块及原表行号；每行沿用整张表的处理页坐标，不推算单元格位置。原始 HTML 继续留在私有原始 JSON。

明确表头生成 name、value、unit、reference 的内部列位置，随后每条模型字段按指定单元格精确核验。列序可以变化；缺少可判定的名称或结果列、整个表头缺失、角色列重复、跨列合并或新的未知表头没有可信列映射。仅缺单位或参考列时，相应字段保持缺失并标记待补充，名称与结果仍可按明确列核验。含 `th` 的混合行只有当前明确名称列仍属于现有指标白名单且列宽一致时视为指标数据，全 `th` 行重新判定表头。未经核验的候选保留原文与待复核标记，数值为空；不借用相邻行、参考值或旧表头的结果列。内部 `table_columns` 参与脱敏和字段核验，不进入公开 Evidence DTO 或确认快照。

redactor 沿用相同指标白名单与身份遮蔽，表头只用于解析列含义，非指标身份行与独立注入行不外发。指标行中的文字仍按不可信资料处理；字段模型不装配工具。解析器不请求 URL 或执行 HTML，拒绝截断、错闭合、嵌套表、跨行合并、注释、声明、处理指令、主动标签、全空表及块与单元格超限。拒绝使用已有页级解析失败，用户可重传、排除或人工录入。现有纯文本协议、公开 Schema 和历史已确认记录保持不变。

## 替代方案

维持现状会继续漏掉 HTML 表格；把整张表连同身份资料发送给字段模型违背最小外发要求。使用正则去掉标签后连接全部文字会丢失行边界，并允许错行字段组合。通用 HTML 渲染、浏览器执行及自动修复损坏结构增加无关依赖和隐式推断。

## 后果

本地合成链路不证明外部模型准确性、真实患者资料脱敏完整性或复杂表格召回。缺少明确表头的候选不能获得经列核验的数值；跨行合并及不支持的 HTML 结构需要用户人工处理。复杂表格的供应商契约、召回和准确率仍为 Not run，需要获批云供应商、脱敏样本及预算。生产云能力维持关闭，不增加付费调用、专业规则、临床字典或食品数据；历史指标不重写。
