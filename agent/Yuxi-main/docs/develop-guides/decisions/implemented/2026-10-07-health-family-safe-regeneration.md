# 家庭餐单逐人安全换菜与共同重生成

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_family_safe_plan_service.py

## 问题

家庭核心已经保存逐餐参与者和个人份量，现有单成员安全换菜与重生成入口仍拒绝家庭对象。后端维护者需要一个保持个人份量、逐人检查且保存时再次核对来源的家庭消费者，完成六Agent工程计划中的家庭安全重算范围。

## 决策

家庭使用专用选择协议，明确对象版本、批准规则版本和全部参与者的档案版本。候选替换共同菜谱，只转换该菜的个人参考份量为已知绝对克数，保留其他菜品和参与关系。批准菜品类型、餐次、配方摘要与营养差异约束逐人执行，最多返回三道通过全家庭质量检查的候选。差异排序使用各食用者的归一化差异之和，未知量不能均分或当零。

整份重生成探索批准目录的共同组合，逐槽保留成员克数并检查个人差异与配料限制，最终逐人检查覆盖餐次的全部营养目标。复用既有有限组合搜索，区分预算耗尽与穷尽无解；原方案不作为新方案返回。确认摘要绑定对象、所有档案、规则、配方及食品来源，提交时重算摘要并复用同一安全修订事务：新版本、新检查、旧专业决定及采用失效共同提交，末次检查失败全部回滚。

原单成员协议继续拒绝家庭对象。[家庭参与者调整](2026-10-07-health-family-participation-revision.md)及[共同正式采用](2026-10-07-health-family-plan-adoption.md)由各自用例拥有；安全修订历史重放检查当前与历史成员并集的授权及排序锁。多成员模型同意、Agent工具及前端交互仍属于后续六Agent工程范围；安全改版不修改Schema或外部资料归属。生产专业条款与完整档案由外部负责人交付，隔离合成资料仅验证工程。

## 替代方案

按家庭总量筛选会掩盖个人过敏或份量差异。先逐成员生成再拼接会改变共同菜品且难以共同修复三餐冲突。专用家庭协议复用确定性计算、质量Owner与保存事务，保持已有单成员调用契约。
