# 设置中的产品反馈与账号头像

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/product_feedback_service.py

## 问题

设置重复列出家庭成员、地址和本人健康档案。用户需要提交产品意见与截图，并修改个人账号头像；现有饮食反馈属于饮食分析，保留其语义。

## 决策

### 实现方案

任务类型为 feature。设置提供头像、产品反馈、隐私与账号和退出登录。头像复用账号资料及头像接口，保持账号隔离并刷新“我的”页；首页导航图标保持原样。产品反馈限制正文 1–200 字、最多三张图片、每张原始图片不超过 5MiB。截图经过图片解码和重新编码，存入私有对象桶，账号与提交状态由 PostgreSQL 拥有。客户端固定提交编号使上传与提交可重试；服务端锁定同账号编号，并在事务提交后返回成功。普通用户只能访问本人反馈，管理员可查询反馈及鉴权图片。新增业务 schema 迁移，不使用健康成员或 AI 流程保存产品意见。

## 替代方案

覆盖饮食反馈会破坏现有记录分析。复用公开头像桶会公开反馈截图。将截图存入数据库会增加业务库体积，采用既有对象存储。使用单个多文件 multipart 请求受微信 uni.uploadFile 单文件能力限制，因此逐张上传后提交反馈。

## 后果

小程序主包接近项目预算，安装前必须通过按实际包体积的检查。后端需要业务迁移后方可接收反馈。微信原生头像选择和真实设备体验须单独验收。部署与微信发布不属于源码实现完成的证明。

后端定向验证包含产品反馈、业务迁移和 schema 兼容检查，共 73 项通过；产品反馈 HTTP 测试在独立 PostgreSQL、MinIO 和 TCP 服务上执行。前端账号、反馈草稿、登录、导航与既有页面定向回归共 171 项通过，H5 与小程序构建通过。浏览器合成接口验证反馈图片选择、失败保留、同编号重试成功和头像返回刷新，并验证 H5 使用完整同源头像地址。独立 Reviewer 未发现阻断问题。正式服务部署、微信上传和真机验收未执行。
