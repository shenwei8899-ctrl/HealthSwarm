# 菜品记餐进入已有拍照页

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_vision_service.py

## 问题
菜品详情的拍照补充留在半屏里，未给已有拍照页或识别任务明确的菜品来源。

## 决策
跳转现有拍照页，以账号和家庭隔离的本地草稿及不透明路由标识交接。隐藏的来源页停止写入，同一草稿和保存请求仅由可见页面持有。返回恢复草稿或已保存回执。
服务端在建任务事务校验来源家庭、餐单日期和版本、餐次与菜品身份，再冻结服务端名称给识别器。来源提示不构成照片证据或本人摄入量。无来源请求保持原指纹和识别行为。

## 替代方案
继续内嵌补充会重复拍照页；只传名称无法核对来源；把计划重量带入会混淆计划与实际摄入。

## 后果
新增可选任务字段，无数据库迁移。服务端需先支持字段。来源失效明确报错，不悄悄丢失来源。取消、失败、重试不自动保存。

## 验证
前端回归覆盖草稿交接、成员份量、失效来源、名称不同的显式合并、未吃原菜品及账号切换。构建后 H5 在 320、390、430 三种宽度验证跳转、返回、照片核对、保存回执与响应丢失重试。合入线上基线的 API 和 Worker 候选各有 65 项相关测试通过，包含 63 项单元测试、真实 TCP HTTP / 隔离 PostgreSQL，以及真实任务执行器 / MinIO 场景。执行器场景用确定性模型替身核验收到来源提示，再回读任务、草稿和原始结果对象。正式部署后核对两角色镜像、五个源码哈希和公开就绪状态，数据库版本不变。未做真实云模型、微信模拟器或真机验收。
