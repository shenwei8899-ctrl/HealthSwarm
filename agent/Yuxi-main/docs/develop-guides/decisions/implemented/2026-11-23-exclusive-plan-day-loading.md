# 专属计划按日读取及版本绑定校验

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/exclusive_plan_browse.py

## 问题
浏览第一天等待整档原谱逐条复核，返回页面会清空已见内容。列表、详情和补图重复校验，使21天计划难以快速浏览。

## 决策

### 实现方案

[浏览服务](../../../../backend/package/yuxi/services/exclusive_plan_browse.py)拥有目录、按日读取及轻量列表摘要。数据库投影由独立 repository 负责，只向应用返回日期元数据、选定日内容或三档已存小计；列表摘要不表示采购价格已重新核定。旧完整读取和购买接口保持原契约。

每次读取先核对当前权限和整体依据，两个批量查询取得来源文件与有序分片并计算内容指纹。目录不下载对象原文；按日读取对当天对象执行有界并发 HEAD，校验记录未命中时才下载当天原文。独立 PostgreSQL 日校验记录绑定内容、来源、对象元数据、展示译文、依据及校验器版本。服务端核验通过后，条件读取才可返回版本未变化标记。

完整发布仍执行连续日期和跨日多样性检查；浏览使用单日原文、限制及三餐组成检查。历史浏览单独校验中文展示，缺译且禁用的来源保持隐藏，新发布仍要求合格译文。来源变更拒绝旧快照，不替换成新菜谱。

前端页面缓存隔离账号、家庭、推荐组和档位。返回保留当前日期和餐次，后台核对期间禁止采购；单个来源失效清除相关日期，撤权、计划不可用或整体依据失效清除全部内容。仅预取下一天，预取不递归，迟到响应不替换当前日期。

## 替代方案
保持整期串行读取会保留原等待；仅按时间缓存不能覆盖来源删除和分片变化；把缓存写入 progress 会放大整份 JSON 写入与并发覆盖风险。

## 后果

健康 Schema 版本升级至 41，幂等创建小型回执表。部署顺序为迁移、后端、前端；旧数据首次访问时按需校验，无需重新生成。数据库来源仍逐次检查分片内容，对象存储仍执行当天 HEAD，因此返回缓存不代表免除存储依赖。校验记录不写入生成 progress，避免放大整份 JSON 的写入。生产部署、实际网络耗时和微信真机操作单独验收。
