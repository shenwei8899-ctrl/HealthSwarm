# 本人家庭档案接入营养咨询

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_family_profile_service.py

## 问题

正式家庭档案与健康 Agent 使用独立成员 ID、授权和用途同意，需显式关联来源并受控读取；直接按姓名或账号合并会把既有健康对象误认为本人。正式档案自由文本也不能替代批准的营养安全编码。

## 决策

### 实现方案

普通健康接口由本人显式关联自己已认领的正式成员与自己维护的“本人”健康对象。独立映射表保存唯一、不可改绑的来源；旧成员、记录和外部安全投影保留。关联不生成新的授权或模型同意。

营养咨询的固定成员工具读取已确认、当前授权内的原始档案。仅支持本人；其他操作者须等待本人模型处理同意接口。未绑定、未确认或必填信息不全返回明确未就绪状态。空值保持未知，返回营养安全编码尚未就绪，不自动生成适用人群、疾病编码、目标或测量。

工具结果摘要及档案版本写入当前 Run 的依赖表。会话请求、历史读取、每次模型调用、checkpoint 重用及最终结果发布重新验证当前来源和健康授权。最终发布还要求冻结的模型处理审批快照与当前同意一致；没有新增工具读取的派生轮次也受整线程来源依赖约束。失败后的 partial 不保存普通回答，中断只保存清空正文的安全状态。来源变化使使用该来源的线程失效，用户建立新咨询读取新版本；本阶段接受这一恢复方式。

家庭写入仅持家庭锁，健康读取采用既有健康锁后家庭锁；家庭写入不反向获取健康锁。处于 Conversation 锁内的只读历史授权不申请成员或家庭写锁，也不追加读取审计，避免反向锁序。工具读取和最终发布采用锁定的当前事实校验。

health schema 增量创建两个表，版本 15→16，仅由正式迁移器执行。HTTP 用例由 service 拥有事务，查询和依赖验证由 repository 拥有。

本人独立实测体重及其冻结范围、测量版本和更正失效由[体重读取决定](2026-10-08-member-weight-agent-read.md)拥有；实测不继承基础档案确认或营养安全就绪。

本决定接续[上游档案合并](../implemented/2026-10-08-upstream-family-profile-integration.md)中的本人 Agent 对接范围；完整营养安全投影及配餐失效传播仍由其业务 Owner 拥有。固定业务提示通过[营养师 Skill](../implemented/2026-10-06-family-nutritionist-builtin-skill.md)发布并冻结版本。

## 替代方案

按姓名自动连接无法证明身份。管理员字段访问授权不能证明本人对外部模型的处理同意。把自由文本转换为专业编码缺少批准字典。全面接入个体化配餐需额外专业接口，本阶段先完成可验证的描述性咨询读取。

独立合成 Compose 中真实 API、Worker、SSE、checkpoint 和 PG 两项 E2E 通过。重放模型检查实际确认的身高原值与固定 Skill 内容；第二轮没有新的工具调用也使用历史数据。档案改版和撤回处理同意后，迟到回答使 Run 失败且没有普通消息或 output_message_id，最终发布守卫直接读取 PG 也拒绝发布。来源改变后旧线程请求返回 410、历史不可读取，且没有新增模型外呼。来源撤回时 SSE 可被当前权限校验关闭，终态核对以 PG Run 为准。

首次 E2E 的 SSE 终态预期及清理顺序已修正，失败批次不计为通过证据；该批留下的精确合成成员与测试部门已清理。两个开发数据库先完整逻辑备份，再由正式迁移器升级至 health16；业务10、知识2保持。本人前端关联交互由[页面闭环验收](2026-10-08-family-profile-consultation-ui.md)接续；真实外部模型质量、管理员代他人、小程序、生产迁移、完整营养安全映射和全量后端回归未运行。

## 后果

本人关联和咨询恢复的前端入口由[本人档案关联页面](2026-10-08-family-profile-consultation-ui.md)接续。管理员代他人外呼、专业安全编码及配餐来源自动失效传播继续待交付。现有外部投影仍是配餐安全事实 Owner。真实模型质量与小程序验收独立待做。
