# 餐后反馈关联与撤回闭环

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_meal_feedback_service.py

## 问题

家庭营养师需要把偏咸、没吃完及餐后不舒服等体验关联到已确认餐次，在后续咨询中读取并尊重修改和撤回。读者为健康业务维护者；后台显式选择餐次解决日期和主体歧义。完整健康档案由红阳提供，配餐及小程序属于独立任务。

## 决策

DietLog 确认快照拥有餐次身份和原营养数据，反馈按账号与餐次唯一保存单餐用户自述、当前版本和不可变修订。写入检查当前 diet_edit 授权、有效确认来源、请求幂等键和显式版本；成员锁串行修改与撤回。撤回保留收据，重放旧请求只返回当前状态；新请求可显式重新填写。其他可见同一成员的账号维护各自反馈，管理员没有私有数据旁路。

家庭营养师固定工具 get_meal_feedback 只读取服务器绑定成员及当前账号的有效反馈，返回餐次时间、版本、自述范围及未专业审核标记。工具和模型调用前依赖由 PG 提交。长期记忆与反馈历史在同一 Run→成员锁事务先共同过滤，再传播最终可见轮次的版本依赖；任一旧依赖失效时整轮退出模型与日终摘要。模型返回时再次核对当前依赖并拒绝已变化的运行，最终检查不重新传播原 checkpoint 的已过滤依赖。

后台入口位于健康识图的已确认饮食日记，每餐提供餐后反馈弹窗及修订查看。成功操作回读当前状态；未知保存或撤回结果保留原请求以便重试。当前对话工具只读取反馈，填写、修改、撤回在后台完成。吃完程度不用于重算营养，单次反馈不写成长久限制、诊断或正式档案。

健康 Schema 7 由 storage-migrator 增量创建反馈、修订及依赖表，支持版本 1—6 的幂等升级；API 与 worker 只检查版本。该决定扩展[营养师后端](2026-10-06-health-nutritionist-skills.md)、[内置 Skill](2026-10-06-family-nutritionist-builtin-skill.md)与[成员记忆及每日对话](2026-10-06-health-memory-daily-conversations.md)的餐后反馈范围。

## 替代方案

把反馈直接存成长期记忆会把一次体验变为持续限制；仅保存在 checkpoint 缺少后台版本管理和撤回事实。模型自动选餐引入日期与主体歧义，当前采用后台明确关联。模型历史的两种过滤器保持各自数据 Owner，在同一事务两阶段联合筛选和依赖提交，避免先传播一种依赖再被另一种过滤的误伤。

## 后果

一次反馈只有单餐自述效力；完整档案、专业内容审核及个人方案保持各自职责。列表读取有界并显式标记截断；失效按整轮处理，也会移除同轮其他内容，原始消息和反馈修订保留供查看。最终校验和 Run 终态提交保持既有时序边界，已流出的文本不会追溯删除，失败运行按既有错误投影展示。

确定性回放证明真实 API、worker、模型协议及持久化装配，真实供应商的自然语言识别和医学回答质量未验证。原开发槽位咨询模型审批保持未启用，需要按既有用途审批完成真实模型联调。窄屏验收覆盖反馈弹窗，既有全局侧栏页面不属于小程序验收。发布 Skill 后 API 和 worker 需重新加载冻结快照。
