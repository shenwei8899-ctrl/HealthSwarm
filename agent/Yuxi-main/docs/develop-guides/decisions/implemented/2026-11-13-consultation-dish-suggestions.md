# 普通咨询菜品建议与餐单操作

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_dish_suggestions.py

## 问题

聊天规则会将无餐次的饮食建议提交为全天配餐，旧建议卡依赖正文格式，普通加餐咨询还会出现独立商品卡。

## 决策

普通咨询的 Agent 在同一次最终调用中生成正文及可选菜品建议。每项包含正文中的菜名和理由。服务端解析并校验后，将卡片随该答复保存，最终结果与已授权历史使用同一数据。缺失或格式无效的可选卡片允许正文继续发布。

「今晚吃什么」进入今日晚餐安排。新建餐单缺范围时追问，查看读取对应计划。聊天中的换菜请求返回餐单调整指引。普通咨询停止查询和选择可购买商品。聊天结果与历史省略旧采购标记和商品卡。餐单生成仍可在后台核对食材。

## 替代方案

扩展前端正文解析规则容易受模型措辞影响，且不能由 Agent 明确选择出卡。额外调用模型会增加一次推理成本。同一次调用提交可选结构化数据使最终答复和历史共享语义。

## 后果

建议卡与最终答复共享发布结果。可选卡片校验失败时正文仍可发布；采购操作继续由餐单及商城入口承接。

## 验证

分流与菜品数据使用定向单测覆盖。前端回归覆盖当前回复、历史读取、发送恢复和既有餐次卡。真实供应商和微信真机需在发布验收时验证。
