# 参考餐单生成可靠性与候选分散

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/reference_recipe_index.py

## 问题

生产合成家庭验收五次生成中三次成功、两次失败，成功仍需81至94秒。原谱待核对章节进入候选，商品引用由模型重复抄写，纠错仅指定tool_choice却保留其他工具，导致保存后纠错失败。三个家庭都选择同一热门菜，采购覆盖率优先于曝光降权。

目标为减少不可保存候选、无意义模型往返、商品引用错误以及跨家庭/跨天重复。保留真实原谱、授权、硬限制、实时商品、事务判重与最终发布核验。不接入营养计算或专业审核，不承诺全站永不共享任何一道菜。

## 决策

### 实现方案

检索剔除无法完整解析和含待核对章节的原谱。健康限制仍优先，采购缺口可以明确展示；在相关候选中提升家庭偏好、近期历史与公共曝光排序，再按采购覆盖率是否达到50%分档，档内使用家庭与日期的稳定散列，细粒度覆盖率和命中数随后比较。由此可优先选择50%覆盖的做法而非100%覆盖的做法，代价是更多明确的自行购买缺口，换取家庭和日期差异。保留相邻日单菜与整套餐单保存时硬判重。

商品工具不接收模型分类编号，程序从本轮真实分类优先选择主粮、蔬菜、禽肉蛋、水产等主要食材，并明确展示范围。上下文成功后进入商品读取；非空检索回执后先打开原谱再判断，避免仅看菜名反复检索。未显式指定商品时，只从本轮回执与当前合法匹配交集中稳定选择一个同类商品，多个合法候选的选择不形成订单、规格或数量决定。首次正常保存拒绝非法显式选择；既有采购纠错允许丢弃无法证明的选择，重验合法推荐或保留自行购买缺口，不接受非法商品。不扩大商品匹配词义或忽略过敏限制。

保存纠错只暴露保存工具；最终仍调用真实模型，但仅传本轮用户请求与已核对回执指令，避免重读整个流水。压缩模型可见菜谱和商品资料，持久化审计及来源重验保持完整。没有用伪造最终回复或共享最终餐单缓存换取速度。

译文校验一次汇总全部菜品的字段错误，保持唯一一次修正预算，不隐藏换算、漏译或数量修改。半圆环的英文half-rings不作为分数量词；厘米、毫米同时支持中英文单位并绑定数量。通用鱼虾词只扩展召回，不扩展商品身份或限制核验。清淡、微辣等偏好使用烹饪词作软排序，来源国家和菜名不成为硬性准入条件。

中文译文中的一包、四个、四分之一等明确用量在签名校验时转为相同数字；三文鱼等非用量菜名不转换。原文与译文数量不等仍拒绝。该修正针对生产验收中真实保存回执误拒的译文，不放宽原谱引用和来源核验。

## 替代方案

仅加提示词无法阻止不可保存的原谱或纠错工具误用；全站硬禁单菜复用会在家庭增多时耗尽候选，因此采用合格候选内分散排序和既有家庭历史硬校验。

2026-11-11：隔离镜像挂载当前源码运行相关unit 168项通过；独立PostgreSQL 16上的`test_reference_meal_plan_http.py`及`test_reference_variety_pg.py`共69项通过。`python -m pytest test/unit -m "not slow" -q --disable-warnings --show-capture=no`全量5892项通过；最后调整采购覆盖分组内散列顺序后，相关检索、商品与工具31项复测通过。工程契约检查及63项自身测试、Ruff改动文件检查、`git diff --check`、`pnpm run build`文档构建通过。

生产只读校准读取3687份公共原谱，其中1290份可完整解析。末尾散列不能改变真实首选组合，因此散列提前到相近采购覆盖分组内；三个合成家庭的首选组合随后出现差异。这是排名校准，不代替真实模型、Worker及每日计划落库验收；提交时后者尚未执行。

第二轮发布前证据：首轮真实模型和Worker六次合成生成全部失败，耗时53.71至204.66秒，暴露分类编号抄错、反复检索、无协议终止以及译文多处错误只反馈首处的问题。该结果不满足线上验收；后续修正须重新部署并核对每日计划实际落库，不能沿用本地测试结论。

第二轮在生产镜像中运行候选测试86项通过并部署，API/Worker均healthy。其后模型供应商原密钥401失效；保持模型标识、端点、处理方指纹和政策版本不变，使用同端点已验证有效的现有密钥更新供应商配置。真实Worker随后完成上下文、商品、检索和原谱读取，在87.57秒的保存调用中反馈中文数量词误判；修正调用时供应商返回402余额不足，最终餐单未保存。费用状态属于外部阻塞，不能以工具成功次数声称生成耗时或跨家庭、跨天重复问题已经解决。

## 后果

生产验收必须保存全部成功与失败记录，分别报告检索、完整任务耗时及每日计划回读结果。少量样本不能证明长期失败率或延迟SLA。同名商品默认推荐不决定购买，当前资料发生变化仍由保存/发布校验拒绝。

本决定补充并部分取代[参考配餐检索提速与家庭日期差异](./2026-11-11-reference-variety-latency.md)中的候选可用性、同类商品默认推荐和排名优先级；原有缓存失效、来源核验和事务判重继续适用。
