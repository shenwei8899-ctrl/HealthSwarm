# 配餐前按成员指出待补齐资料

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/reference_meal_plan_service.py

## 问题

历史成员资料不完整时，配餐入口仅返回第一位成员的问题；前端在创建任务失败时丢失错误，显示通用读取失败，用户无法定位资料。

## 决策

### 实现方案

档案保存与预检共用完整性规则，日期使用同一类型契约解析。预检独立检查无效字段并继续收集其余必填问项，返回成员标识、名称、版本、可编辑状态及不含原值的字段问题。参考配餐服务先完成全部所选成员的授权核对，再聚合问题，在创建线程、模型任务前以 profile_incomplete 返回结构化列表。

HTTP 适配和客户端保留问题列表。普通成员资料投影提供 readiness 问题供前端提前展示；提交时仍以服务端校验为准。今日餐单保留既有餐次，提供逐成员补齐入口；成员页进入允许编辑的分类并定位首个问题。补齐后重新读取资料并核对原名单、日期和单餐调整版本，由用户点击继续配餐。切换身份清除全部问题和补齐上下文。聊天来源失效恢复只在相同身份和日期保留待补齐意图，重新读取选中成员的 planningCanRead 和问题投影。权限变化清除旧名单、旧问题，仅保留当前身份日期下需手动重新安排的暂停状态，避免页面重载自动配餐。

## 替代方案

仅显示原错误消息无法一次处理多人问题或定位字段。自动移除成员会改变用户选择。放宽完整性要求不能满足配餐来源约束。

## 后果

历史缺失字段不再继承“本人已完成建档”的资格。无权编辑的成员显示联系本人或有权限家人处理；无权读取的成员在返回问题前拒绝。网络故障维持独立语义，已有餐单不因资料补齐流程丢失。补齐后的成员版本必须重新读取，旧名单请求和旧任务结果不能替代新核对。
