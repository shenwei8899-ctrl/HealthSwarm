# 专属计划采购使用一次读取初始化页面

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/exclusive_plan_purchase.py

## 问题

点击购买后，前端先读取完整计划，再读取采购回执，子组件挂载后再次读取同一采购回执。三次串行网络请求均复核计划来源；采购还扫描并解析不参与商品汇总的候选菜谱库，延迟商品展示。

## 决策

### 实现方案

采购 GET 在完成既有计划、成员授权和商品校验后返回 `tier_name`、`members` 与采购回执。App 的计划采购页直接读取该接口，普通计划详情保留完整计划读取及图片流程。采购子组件仅在挂载时使用父页面刚读取且 scope_hash 一致的回执；显式刷新、结算、报价和提交继续使用既有来源与交易核验。父页面负责页面再次显示时的重新读取。

后端获取成员限制时使用 `load_documents=False`，保留完整计划的已保存来源复核与成员上下文校验。商品目录继续读取当前商城事实。没有引入跨请求缓存、数据库迁移或订单副作用。

## 替代方案

并行读取计划与采购仍重复计划校验。跨页面缓存完整计划会增加账号、家庭、授权和来源失效管理。延长超时不能减少等待。采用一次采购读取以及仅挂载复用回执，保持改动范围和失效规则明确。

## 后果

前端和后端需要配套交付，新增元数据为采购接口的兼容字段扩展。页面首屏仍需等待一次真实采购校验和商城读取，实际耗时受商城响应与网络影响。结算阶段继续拒绝变更或撤回的来源。

## 验证

相关 unit 覆盖一次入口读取、首次挂载不再读取、手动刷新和结算重新核验、失效响应丢弃，以及后端不扫描候选库。真实 HTTP/PG 测试覆盖采购元数据、跨账号不可见、原谱变化和授权撤回；执行结果和构建证据记录于本任务交付记录。
