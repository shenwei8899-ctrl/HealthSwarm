# 健康识图重试与视觉 JSON 包装

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/health_vision_provider.py

## 问题

饮食识图失败后，页面重试事件直接引用模板未绑定的 `crypto`，编译后读取组件属性而非浏览器全局。冻结视觉快照不支持供应商 JSON 模式，裸 JSON 解析会拒绝完整代码块包装。现有失败日志只证明 JSON 转换失败，无法恢复该用户任务的原始模型返回。

## 决策

重试事件调用页面脚本方法，由脚本生成请求编号并沿既有 API 刷新任务。仅非 JSON 模式调用接受一个完整的无语言或 `json` Markdown 代码块，随后执行原有 JSON 对象及领域校验。正文混合解释、多块、截断、非法结构及营养或份量字段仍拒绝；不补造字段，不自动发起纠正调用。权限、费用、审批及持久化规则不变。

## 替代方案

保持裸 JSON 限制会拒绝可完整验证的包装；任意截取首个对象会掩盖解释、多结果或截断；追加云纠正会扩大费用及数据传输。选择有界包装解析，不推断实际失败返回的具体内容。

## 验证

实际编译的重试按钮事件和页面脚本测试在旧模板下因零请求失败，修复后产生有效 UUID 并刷新当前成员任务。前端相关五文件 35 项通过，页面脚本单独 14 项通过；lint、生产 build 通过。浏览器使用实际 HealthVisionView 与完全禁用真实 API 的明确合成替身，点击后 DOM 从失败变成排队中，有效 UUID 已被替身核验；截图只证明该本地交互，不代表用户任务云识别成功。

SDK wire、DTO、领域和协议相关集合 81 项通过；补充 JSON 模式拒绝包装的负控后，wire 与 replay 51 项通过。独立 Reviewer 移除 `not json_mode and` 后两项拒绝测试准确失败；破坏重放起始包装后响应 oracle 失败。隔离槽位实际 HTTP、独立 worker、私有对象、草稿修订、营养计算与确认日记回读的 E2E/wire/replay 共 56 项通过，不使用真实模型或健康照片。命令由[测试规范](../../testing-guidelines.md#健康识图重试与-json-包装验证)维护。

真实云识别、原失败任务的原始响应和真实菜品准确率为 Not run：该返回未保留，本修复不自动追加收费请求。Ruff 与工程契约检查通过；契约检查单元测试 62 项通过。无配置、Schema 或审批变更，原开发 worker 在没有活动任务时刷新。

## 后果

本地包装重放不能证明用户原任务的实际返回、真实图片识别质量或所有供应商格式。浏览器验证使用明确的合成 API 替身，不点击用户收费任务。相关源码既有未提交功能必须保留；本修复不更改云配置或上传健康照片。
