# 参考餐单保留未选餐次

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/health_consultation_service.py

## 问题

本文面向维护参考配餐提示与发布候选的开发者。参考提示需要保留既有的单餐修改约束，防止替换提示文件时丢失“只修改所选餐次，不改写其他餐次”的行为。当前仓库 `get_reference_context` 不提供 `current_daily_plan` 字段；保存 Owner 已要求提交餐次集合等于 `selection.meal_types`。提示不能声称每个版本的工具一定返回当前计划。

## 决策

### 实现方案

固定参考提示在工具实际提供 `current_daily_plan` 时，将它解释为所选日期的当前计划。用户只修改某个选定餐次时，仅为 `selection.meal_types` 提交修改，不改写其他餐次；工具未提供该字段时不臆造当前计划。保存 Owner、原文引用、授权和回执校验保持现状。

组装提示回放使用包含三餐当前计划、仅选择晚餐的合成上下文，检查实际模型输入与工具提交范围。独立负例执行原保存函数，证明夹带未选餐次仍返回 `reference_meals_mismatch`。脚本模型回放不证明真实模型或持久化的整日合并语义。

## 替代方案

- 无条件声称上下文包含当前计划：与未提供该字段的版本不兼容。
- 放松保存餐次集合检查以接收整日重写：扩大用户选择范围。
- 为保留提示而替换参考保存 Owner：发布覆盖面超出本次提示兼容需求。

## 后果

提示与提供或未提供 `current_daily_plan` 的工具上下文兼容，只把实际返回的当前计划作为资料。模型修改范围继续受 `selection.meal_types` 和原保存集合校验约束。保存服务不随提示保留变更而替换；真实模型遵循、部署版本的当前计划构建和整日持久化合并仍需各自证据。
