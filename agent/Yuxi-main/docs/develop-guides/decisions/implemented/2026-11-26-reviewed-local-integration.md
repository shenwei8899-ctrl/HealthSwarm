# 近期小程序及业务服务增量整合

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/meal_dish_service.py

## 问题

现用小程序工作区基线早于GitHub主线，直接覆盖会撤回计费关闭模式、当前采购限制检查和数据库菜谱能力。新增编辑器和引用功能需要同时纳入持续回归。

## 决策

### 实现方案

以数据库菜谱已接入的主线为基础，整合饮食日历编辑、逐菜份量、家庭就餐成员同步、归档图片、正文引用、好友邀请和配送采购确认。HTTP路由沿用认证依赖，服务负责授权和事务，PostgreSQL记录业务事实，Task在事务提交后发布。

预算服务保留off默认及咨询和识图豁免。咨询每次构图和模型调用前同时核对服务声明、处理授权和引用依赖；追问等待预算后再次核对授权。采购首次选包和商城回源保留当前成员、记忆及最终SKU限制检查；成员更新或已有记餐时拒绝重排。数据库菜谱来源、严格商城采购及缺项说明沿用主线。

饮食日记组件移到records分包，测试挂载器同步新路径及采购依赖。默认前端测试纳入新增独立单测；依赖独立商城HTTP夹具的测试保留明确命令。邀请表通过business schema18迁移注册。支付未开放的配送采购由服务端阻止实际支付。

## 替代方案

整体覆盖现用目录会引入旧实现回退；只提交UI文件会遗漏接口、持久化和任务装配。保留主线并成套整合功能，使原有安全边界和新入口共用同一事实来源。

## 后果

历史副本、运行数据、构建产物和凭据留在本机。源码整合不触发生产部署、主线合并或微信上传。真实模型、Worker完整链路、支付及真机结果不能由单元测试或构建结果代替。

## 验证

本次命令及结果写入PR。前端完整单测与H5、微信构建已执行；后端完整单测、隔离HTTP/PostgreSQL及独立Review用于界定剩余问题，失败和未验证项必须明确记录，存在缺口时PR保持Draft。
