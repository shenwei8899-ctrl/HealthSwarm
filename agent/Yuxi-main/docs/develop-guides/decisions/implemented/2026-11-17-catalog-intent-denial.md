# 普通咨询中的商城拒绝回执

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/health_consultation_service.py

## 问题

普通咨询误调用商品工具时，商品守卫返回正常拒绝，但下一次模型调用前的来源校验将其视为商品来源失效。当前回答及携带这条历史回执的追问因此中断。

## 决策

### 实现方案

商品守卫继续在执行前核对当前请求及购买意图。拒绝回执保留 error 状态，增加原因及所属请求标识；共享协议模块拥有拒绝文案、意图判断及回执识别。咨询服务仅跳过严格匹配的拒绝回执，不将其作为商品来源。

识别必须结合所属用户轮次及对应 AI 工具调用，核对工具名、调用 ID、无购买意图、固定文案及请求标识。历史无标识回执只在相同结构约束下兼容。其他错误继续拒绝，成功回执继续执行原来源校验。既有权限、用途配置和运行 lease 校验先于回执处理；不改变当前普通咨询的授权规则。

不修改数据库、小程序、购买意图规则及商品来源验证，不清除或改写生产会话。

## 替代方案

- 跳过所有商品工具错误：会掩盖真实来源失效，拒绝。
- 将拒绝标为 success：会把无商品数据的回执混入成功来源，拒绝。
- 删除整个会话：丢失历史且不解决新请求，拒绝。

## 后果

拒绝继续标记 error，不能被成功商品回执逻辑采用。旧回执兼容受固定文案及完整调用结构约束；信息缺失保持拒绝。数据库和公开接口没有变化。
