# 小程序专属计划的单日生成与确认

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_initial_meal_plan_service.py

## 问题

用户确认先验收单日三餐生成、确认保存与回读。专属计划页需要提供既有初始配餐 Agent 的单日入口，并保留主线的21天计划、档位和同意流程。现有后端已拥有固定来源线程、Run回执、营养计算校验、幂等保存和专业检查。

## 决策

增加只读单成员初始选择接口，使用服务端 HEALTH_DAILY_RULE_CODE 和当前成员档案版本，返回固定日期、三餐及来源。缺资料或批准规则时返回明确未就绪状态。客户端复用健康任务入口、轮询和恢复机制；模型生成结果仍由既有业务校验后展示，用户明确确认后调用已有初版保存接口。保存请求在账号隔离存储中保留幂等键，未知结果只重试原请求。离开页面、切号、撤权及来源变化清除可见结果。

单日入口复用既有配餐引擎及程序计算结果，保留专业审核及正式采用语义。21天计划、支付与配送保持主线现有行为，其完整验收独立推进。生产规则缺失时不使用合成数据替代正式批准。

## 替代方案

直接让页面拼装批准规则和档案版本会复制服务端来源选择逻辑，版本失效也难以统一处理，因此由只读服务提供选择。新建配餐引擎会重复已有 Agent、计算校验和持久化服务，因此复用既有任务协议。自动保存模型结果缺少用户确认，因此预览和保存保持两个操作。
