# 首次建档填写日常活动量

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/miniapp_profile_types.py

## 问题

首次建档无法填写日常活动量。营养咨询可读取已关联档案，但缺少该字段时个人方案仍未就绪。

## 决策

### 实现方案

在建档第 1 步的身高和体重后，为每位建档成员提供无默认值的活动量单选。沿用档案编辑的久坐、轻度、中等、较高四档。

新版建档通过 `onboarding_version: 2` 提交 `members[].activity_level`。服务端校验每位提交成员，按已有字段权限保存至家庭成员档案，并回读为 `activityLevel`。无版本的老请求省略活动量时保留已有值。计算保存指纹时跳过旧请求未发送的新增字段，以便重放已受理的老请求。

营养咨询按档案工具的状态区分未关联、待确认和资料不全，缺项以工具实际返回的数据为准。

## 替代方案

把活动量纳入全部档案的建档完成判定会改变老账号登录分流。新版请求独立要求该字段，历史档案延续原建档完成规则。参见 [11 月 11 日建档规则](2026-11-11-complete-onboarding-body-data.md)。

## 后果

历史档案可以从健康档案页面补填，留空时仍会由咨询的完整档案检查报告缺项。发布时先更新后端，再发布发送新版请求的客户端。

## 验证

App 默认单元测试 1771 项、H5 API 和微信小程序源码构建通过。隔离 PostgreSQL 的真实 HTTP 建档准备测试 13 项覆盖新版必填、保存回读、幂等重试、同键改值冲突、老请求保留活动量、首次 AI 用途绑定和授权撤回。跨模块整合及未执行范围由[源码整合决定](../proposed/2026-11-16-reviewed-source-integration.md)记录。
