# 饮食固定快照的 JSON 请求边界

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/health_vision_provider.py

## 问题

饮食识图使用方案冻结的 `qwen3-vl-flash-2026-01-22`，返回的菜品通过本地 JSON 和领域 Schema 校验。饮食调用若继承报告字段的 `response_format=json_object` 参数，会形成与快照能力表冲突的请求；合成视觉重放需要区分两种契约。阿里云官方模型页的快照版本表将该版本的结构化输出标为不支持，系列入口却标为支持，协议测试不能据此声明实时供应商兼容。记录面向后端维护者，不批准新增云处理或付费探针。

## 决策

饮食调用通过共享调用函数的内部参数关闭供应商 JSON 模式，提示词继续要求 JSON，模型版本、图片、无工具、非思考和单次调用策略保持不变。报告字段调用保留供应商 JSON 模式。视觉重放拒绝 `response_format` 参数，独立 HTTP 协议单测检查实际 SDK 请求体与返回结果校验；普通输出、数组、额外营养或份量字段继续显式失败。真实供应商兼容性与识别质量保留为未验证，后续需要单独授权。

本决定部分取代[饮食独立 worker 验收决定](./2026-10-04-health-meal-e2e.md)对 JSON 请求模式的要求；隔离槽位、合成图片、确认、权限及持久化验收范围保持不变。

## 替代方案

保留参数需要真实快照探针消除官方文档冲突，当前饮食云处理尚未获准。改用系列别名或其他快照会偏离已冻结方案，并需要同样本模型对照。收到错误后静默切换请求或模型增加调用次数及费用，不能作为首版兼容策略。省略可选协议参数并保留严格本地校验，不新增模型、自动重试或客户端配置。

## 后果

饮食观察字段、来源定位和 `health-meal-v2` 提示词绑定由[饮食照片观察决定](./2026-10-05-health-meal-observations.md)补充；本记录继续拥有固定快照请求是否使用供应商 JSON 模式的决定。

提示词要求 JSON 不保证真实模型始终遵循，解析失败仍提示人工录入；本地协议通过不构成真实模型准确率或调用成功率结论。官方能力依据为 [Qwen3 VL Flash 模型页](https://help.aliyun.com/zh/model-studio/qwen3-vl-flash)，核对日期 2026-10-05。整体验收仍需要称重照片、授权食品数据、专业审核、生产预算与小程序衔接，不能由本修复代替。
