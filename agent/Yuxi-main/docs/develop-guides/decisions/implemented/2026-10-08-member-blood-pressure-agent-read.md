# 本人血压实测记录的 Agent 读取与来源失效

状态：implemented
类型：feature
Owner：backend/package/yuxi/repositories/health_blood_pressure_repository.py

## 问题

家庭档案的独立血压测量拥有自己的更正版本，基础档案确认版本不能识别其变化。咨询需要追溯当前实测来源，并在血压更正或字段授权变化后拒绝旧输入、旧历史和迟到回答。

## 决策

本人咨询读取已授权的血压原值及来源。范围固定为近30个北京时间自然日、最近20条记录；缺失与未关联返回明确状态，独立实测不要求基础档案已经确认，也不提升营养安全就绪状态。

### 实现方案

固定本人读取工具复用本人关联、家庭字段授权、独立模型处理同意、当前 Worker attempt、冻结处理审批和咨询绑定。HTTP 普通读取与 Agent 工具分别进入 service；repository 查询正式测量并输出成对收缩压和舒张压、mmHg、测量时间、来源、记录ID和独立版本。模型没有可填的成员或日期参数，工具省略备注、测量条件和更正历史；非法持久值按缺失或冲突状态处理。

体重与血压共享相同的冻结范围、原值校验、摘要和回执核对流程；体重 API、投影与既有持久回执保持兼容。新增血压回执仅保存范围、可见记录引用ID和版本以及投影摘要，健康 Schema 从17增量升级至18。咨询历史、checkpoint、派生轮次和最终发布点重读实际来源；可见记录更正、选中集合、截断标记、关联或授权改变时返回明确失效状态，新咨询读取当前数据。始终未进入最多20条投影且不改变截断标记的记录变化不使既有回答失效。角色状态、内置 Skill 与处理同意说明同步声明实际读取范围。

咨询页面的并发初始化共同等待同一次加载完成，路由同步与未初始化状态使用既有发送禁用入口。初始化失败后可以重试；reset 清空等待引用，旧初始化的 finally 不清除新等待。默认智能体详情加载结束后再选择成员咨询，避免首次进入时默认选择覆盖已经绑定的健康线程。

处理同意身份沿用成员、操作者、用途、处理方和管理员审批政策版本；入口披露血压处理范围，Skill版本不替代政策版本。同处理方及政策的既存有效同意仍可使用，系统没有为每个Run重新签署同意。

## 替代方案

复制完整体重实现会使同一授权和失效策略在两处独立漂移；共享当前两类测量使用的流程可保持最小维护面。一次接入血糖和血脂会扩大测量条件与不同字段结构的验收范围，采用分阶段交付。通过通用家庭测量 service 直接读取会引入其内部提交事务，无法保证模型外呼前回执与当前 attempt 同一事务。

后端相关unit 187项、独立咨询协议回放72项通过。真实HTTP/PG及Schema共34个独立案例通过：血压接口8及迁移2、体重接口9及迁移2、档案接口11及迁移2。严格校验整份工具正文并重算摘要后才读取回执；object、list、bool、null摘要及实际PG引用版本1→true均返回410，恢复整数版本1后恢复可读。固定旧体重投影摘要保持兼容，第21条未读记录更正且截断标记不变时旧回答继续有效。

实际Worker共15项通过，包含血压8、体重4、档案2及既有咨询1。血压覆盖当前读数、更正后新咨询、空集新增、撤字段授权以及直接/派生迟到输出；同一Run的回执、checkpoint和最终业务结果均回读。删除失败/中断发布路径的血压依赖SQL分支，4项负控均在缺失约束处失败。

真实浏览器、API、Worker及PG的一个独立场景通过：家庭指标表单录入设备来源120/80 mmHg版本1，咨询读取成对原值；表单更正122/82版本2，旧每日咨询及历史返回410；用户明确新建、重新勾选当前入口同意后，新咨询使用版本2。两个Run具有不同来源摘要，原基础档案仍为空且未确认；测量更正保留原测量时间、来源及历史。浏览器核对实际提交的健康Agent、线程及后台批准模型策略，并对照最终输出。稳定失效模态及最终回答截图覆盖披露、恢复入口和当前读数；初次模态动画截图不单独证明稳定视觉状态。

实际Pinia/Vite的4项初始化测试及页面模板/直接发送guard行为检查通过。恢复旧store源码后，同一oracle有3项按等待、角色覆盖和reset缺陷失败；实际延期默认详情复现第二调用提前完成且最终选择被覆盖为默认Agent。测试fixture关闭自动依赖优化并先替换API边界，再加载真实store及核对模块身份，原业务断言保留。

前端全套476项通过，零失败、零跳过；ESLint、生产构建、相关Ruff检查与格式检查通过。工程检查核对97项decision和232页文档，门禁63项单测及文档构建通过。实际服务恢复健康，隔离场景无活跃Run和残留血压回执；临时页面入口已清理。

## 后果

来源回执与更正写入共享家庭锁，保持当前Run→健康成员→家庭的事务顺序。健康Schema 17→18通过正式migrator新增血压引用表，API与Worker只校验兼容性；本地默认槽位及隔离合成槽位在备份后实际升级，既有业务表和体重回执保留。

范围仅包含本人实测血压的描述性读取。血糖、血脂、其他成员代读、专业诊断、个人营养目标及配餐安全映射保持各自待做范围；完整角色继续标为部分完成。严格本地模型回放证明工具装配和持久链路，真实外部模型质量、专业判断及云端生产迁移未验收。旧账号成功响应在reset后的深层隔离，以及既有发送await期间快速切换线程不属于此修复验收。

本决定接续[本人实测体重](2026-10-08-member-weight-agent-read.md)；体重与血压共享必要流程，API与既有摘要保持各自稳定契约。
