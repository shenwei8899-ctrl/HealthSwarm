# 餐单草稿工作台

状态：implemented
类型：feature
Owner：web/src/components/health/HealthMealPlans.vue

## 问题

后台用户需要为授权成员生成、核对、保存和换菜，并查看餐单历史。已有配餐服务缺少可操作页面。任务类型为 feature，前端交互与异步结果投影需要浏览器和相关 unit 证据。目标是单成员单日三餐草稿管理；个体适配、专业审核、采购、实际摄入和小程序页面继续使用原有边界。

## 决策

健康工作台提供餐单草稿页签，复用当前成员选择和健康 API。AI 生成通过固定配餐线程与既有 Request/Run 接口，只展示完成 Run 的权威结果；网络中断提供原请求重试及状态恢复。服务未启用时保留手动菜谱选择和服务器预览。保存与换菜使用服务端回读版本，未知响应保留冻结的幂等请求；成员或授权变化清空私有结果并拒绝迟到响应。

## 替代方案

备选为跳转通用 Agent 对话后人工搬运餐单回执。专用页面直接展示服务器草稿并操作版本，减少用户转录和选择错误。页面使用现有组件与样式变量，不增加依赖或修改后台状态机；未保存草稿离开页面后需重新生成。

## 后果

完整档案与专业配餐规则尚未接入，结果保持未个体适配、未专业审核；AI 生成取决于独立 meal_plan 用途审批与成员处理同意。真实模型质量和小程序验收仍为后续范围。后台保存只记录计划草稿，实际饮食和正式采纳继续使用各自的业务边界。

配餐组件拥有交互与异步结果投影，快照组件展示服务器营养与版本，健康 API 封装请求头。预览表单变化使未保存预览失效；保存后回读当前版本，历史版本只读。换菜冲突清除可编辑旧版本。取消生成时，已分发请求使用 Run 取消；提交结果未知且线程已创建时保留恢复入口。后端权威与事务语义由[基础配餐师与餐单草稿](./2026-10-06-health-meal-planner.md)拥有。
