# 饮食日记表格与来源统一

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_diet_journal_service.py

## 问题

饮食日记需要按日期和成员统一展示聊天、照片确认和人工记餐，支持直接修改描述、粗略份量、实际克数和删除。按入库时间分页后在客户端筛日期会遗漏历史记录。

## 决策

日历与表格读取同一套 DietLog。日历接口按北京时间读取所选自然周，复用已确认来源验证，返回当天记录与有效记录日期。服务端的窗口上限继续适用，超限明确报错。

未提供餐次的对话记录采用 unknown，保留日期归档占位与 time_known 元数据。客户端显示未注明，用户可补充餐次。已明确餐次的原文继续验证餐次一致性。

编辑以每行一种食物保留描述，未修改的项目保留证据及映射。改名项目作为人工项目保存，重量和营养映射保持未知。实际克数以本人重量保存，用户修改重量后清除旧参考规格。照片与位置证据遵循原更正校验。

更正和撤销保留 ID、版本和幂等键。前端冻结未知结果的请求，明确冲突后重新读取。撤销保留修订与失效反馈。原聊天撤销端点继续限定本账号创建的对话记录，通用撤销按成员饮食权限和来源访问权执行。

聊天原话只返回当前账号拥有的有效会话消息，家庭饮食权限不扩展为私人对话权限。照片使用现有鉴权预览接口。

## 替代方案

客户端遍历所有历史分页会随记录增加产生大量请求。按实际日期读取周窗口使日历标记与表格共用来源。自由描述保留用户措辞，具体营养值取决于仍可验证的食物映射和重量，未知值继续为空。

## 后果

API 与客户端需要同时更新以提供日历和通用撤销。旧的日记分页、详情、更正和聊天撤销接口继续兼容既有调用方。

## 验证

前端用例覆盖跨年日历、个人重量、原照片证据、描述变更后的旧映射清理、请求重试及账号切换。纯 DTO 用例覆盖未注明餐次、明确餐次冲突和计划语气。数据库事务与 HTTP 验收需要运行中的独立 PostgreSQL 测试环境。
