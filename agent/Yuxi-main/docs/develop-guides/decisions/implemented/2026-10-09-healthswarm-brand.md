# HealthSwarm 产品品牌

状态：implemented
类型：feature
Owner：backend/package/yuxi/config/static/info.template.yaml

## 问题

HealthSwarm Agent 的产品页面、默认品牌配置与助手身份需要采用同一个产品名称。

## 决策

### 实现方案

默认组织名、产品名、版权、页面标题、品牌回退、欢迎语和默认助手身份采用 HealthSwarm。组织名与产品名相同时，登录页只展示一次名称。系统发现接口返回 HealthSwarm，知识库类型展示与 CLI 授权页同步产品名称；技术类型和协议标识保持兼容。

品牌 YAML、前端展示和默认助手提示词分别拥有各自运行时事实。用户介绍文档采用产品名称，保留 Yuxi 上游归属、链接和许可证说明。Python 包名、环境变量与持久化数据标识继续保持兼容。

前端在本地构建，版本化应用镜像复用现有依赖层。发布只替换 API、worker 与 web；保存原镜像和部署配置，等待后端与网页代理就绪后读取实际页面、接口和运行时提示词。

## 替代方案

只修改部署配置无法覆盖页面标题、欢迎语和默认助手身份。批量替换技术标识会影响导入、协议或存量数据，超出品牌需求。

## 后果

用户通过不同入口识别同一个平台；上游技术标识和已有用户数据保持兼容。应用容器替换期间有短暂不可用，应用验收失败时恢复保存的原版本。真实模型回答仍取决于供应商可用性，品牌身份通过实际加载的提示词验证。

## 验证

前端 lint、生产构建、文档构建和工程检查通过。前端全套 495 项首轮通过 494 项；旧品牌断言更新后，相关 4 项复测通过。工程检查单元测试 63 项通过。Windows 工作区的前端全套测试在内容一致的 LF 副本中运行，避免源码提取测试依赖换行格式。

真实首页、侧栏和欢迎语展示 HealthSwarm；独立访问环境中的登录页品牌标题数量为 1，截图保存。实际品牌与发现接口、新管理员登录、API/worker 发布文件哈希及实际加载的助手提示词均验证通过；数据库记录与用户文件指纹、非目标容器身份及启动时间保持一致。

后端 pytest 未执行：本地 Docker 不可用且本地缺少后端测试依赖；对应公开接口通过真实部署实例验证。模型对话未重测，供应商余额限制与本次品牌修改无关。
