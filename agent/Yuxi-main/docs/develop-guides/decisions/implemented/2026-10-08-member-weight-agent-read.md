# 本人实测体重接入营养咨询

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_weight_service.py

## 问题

家庭档案维护独立的体重测量记录，但营养咨询只能读取基础档案和报告指标。体重更正只推进测量版本，基础档案确认版本保持不变；直接混入档案会使历史模型输入与迟到回答继续采用旧值。

## 决策

### 实现方案

新增固定本人咨询的体重读取工具，模型没有身份或查询参数。用例复用健康成员权限、显式本人来源映射、正式家庭字段权限及当前独立咨询处理同意。普通体重查询与模型读取共用 repository，模型路径还检查当前 Worker attempt，并持久化引用回执。

读取近 30 个北京时间自然日最多 20 条实测记录，返回固定日期范围、截断说明、记录 ID、原体重值、kg 单位、测量时间、来源和独立版本。返回值不携带备注、旧值或其他指标，不计算医学结论、BMI 或个人目标。未关联、无记录和可用记录有明确状态；实测不继承基础档案确认，也不提升完整营养安全就绪标志。

独立体重依赖表保存 Run、固定日期范围、来源成员、记录 ID/版本引用和投影摘要，不复制测量正文。空结果也保存回执。线程请求、历史访问、每次模型调用、checkpoint 重用及最终结果发布重查冻结范围的当前来源；已引用更正、范围内选择变化或授权失效阻止旧输入和旧回答，用户明确创建新咨询读取当前事实。

使用既有健康锁后家庭锁，测量写入持家庭锁与读取/发布排序；Conversation 只读授权不反向申请家庭写锁，也不追加读取审计。失败和中断路径同样识别体重线程依赖，禁止将旧体重写成普通回答。health schema 16→17 通过正式迁移器新增依赖表，保留原成员、测量、授权和咨询事实；API/Worker 只校验 schema。

## 替代方案

从聊天记忆或报告推测体重缺少独立来源。从基础档案确认版本校验实测无法检测测量更正。直接调用家庭 service 的读取方法会引入其内部 commit，破坏当前 Run 的事务边界。采用独立读取及引用表能复用现有授权和测量接口，同时保持两种版本的语义。

相关后端 unit 144 项通过，包含体重读取 56 项、checkpoint/工具及失败/中断输出 13 项，另有咨询、Skill 和迁移回归 75 项。独立咨询回放单测 45 项通过。JSON 类型篡改即使保持 Python 相等和真实摘要，也须重新计算正文摘要后拒绝；以真实 PG 回执为凭据篡改 checkpoint 版本 1→true 同样返回来源失效。

新增真实 JWT/HTTP/PG 9 项、正式 health16→17 及未来18拒绝迁移 2 项通过；既有本人档案 HTTP 11 项和迁移回归 2 项通过。实际 Worker 4 项证明读取60/v1、更正61/v2后新咨询读取、空集新增失效及直接/派生迟到回答均无普通输出；既有档案 Worker 2 项回归通过。合成协议回放检查实际模型输入，不证明真实外部模型回答质量。

咨询入口披露本人独立实测体重、固定范围和必要字段，来源失效提示使用当前资料版本。同意身份沿用成员、操作者、用途、处理方和管理员审批政策版本；Skill版本不替代政策版本。相同处理方和政策的既存同意仍有效，每个Run不自动重新签署同意。

真实浏览器、API、Worker 和 PG 的一个独立场景通过：从家庭健康指标页面录入设备实测60kg/v1，今日咨询实际读取；同一表单更正61kg/v2，旧今日入口返回410，用户明确新建咨询并独立勾选当前入口同意后读取61。PG核对原测量时间、设备来源、更正历史、两个Run依赖和消息输出，空基础档案v1从未确认且不因测量更正推进。浏览器截图核对字段披露、失效提示及最终回答；初次选择器定位诊断失败不计入通过场景。

前端470项全套测试通过，同意说明更新后的页面20项定向回归另通过；ESLint、前端构建、相关Ruff检查与格式检查通过。工程门禁96项决定/231页文档、门禁63项单测以及文档构建通过。独立审查的摘要类型核验及同意说明问题已修正并验证。

## 后果

范围仅包含本人实测体重的描述性读取。其他指标、管理员代成员模型处理同意、临床安全编码、个人目标与配餐映射独立待做。当前记录保存语义与专业规则由家庭业务 Owner 拥有；模型不对记录真实性作额外确认。严格本地重放证明工程装配，真实外部模型质量另行验收。

本决定接续[本人档案关联](2026-10-08-family-profile-agent-read.md)和[咨询页面](2026-10-08-family-profile-consultation-ui.md)；基础档案确认与测量更正由各自来源版本拥有。本人显式来源关联和专业安全边界继续适用。

[本人血压读取](2026-10-08-member-blood-pressure-agent-read.md)接续独立实测来源校验，并将体重与血压的必要查询、摘要及回执流程复用到同一repository基类；体重API、旧投影摘要和既有回执保持兼容。当前健康Schema为18，血压增量迁移接续本记录的16→17；上文迁移与测试数量保留体重首次交付阶段的实际证据。
