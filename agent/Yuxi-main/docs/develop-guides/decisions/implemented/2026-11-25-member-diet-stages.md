# 成员阶段目标、行动与自动复盘

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/diet_stage_service.py

## 问题

成员的静态饮食目标、实际饮食记录和报告缺少持续执行闭环；用户在“我的家”管理个人阶段目标及可勾选周行动，并由模型根据已有资料整理复盘。

## 决策

### 实现方案

阶段服务拥有日期、目标、修订和用户确认，周行动独立版本计次；确认目标与兼容档案摘要在同一事务提交，旧入口不能单独覆盖。健康分包承载页面，首页只批量读取进度。日常饮食反馈维持原有范围。

生成建议与总结复用持久任务、模型配置、现有用途边界、费用预算和任务lease，网络调用不持有家庭事务。读取、发布及展示校验成员和实际来源；源撤回或更正后旧正文不可读。已采用草案有独立状态，恢复时跳过失效候选。轮询在切阶段、切账号和离开后失效。

阶段默认三个自然月，行动连续七天。扫描按检查时间轮转；失败有30分钟退避和同来源24小时两次失败限制。到期准备总结，确认后才开始下一阶段。结束正文冻结，新报告提供补充；没有新报告也能回顾执行。

当前和七天参考餐单读取实际参与者目标，明确可支持的行为方向参与软排序。既有硬限制及专业营养数值Owner不变。目标修订不倒算旧周，勾选不使档案或菜单失效；历史菜单仅行为目标变化时可读，其他安全依据仍严格校验。

### 自述读取与操作恢复

阶段分析通过每日会话、咨询绑定、账号、成员与活动项目的联合查询读取用户原话，继续过滤失败执行、撤回记忆和失效反馈。原话属于用户自述；商品卡片、工具审计和旧模型答复不进入执行事实。当前成员与AI用途授权在来源读取及发布边界复核；采购和咨询结果沿用其原有来源校验。

前端仅为结果未知的写入保存原请求。明确拒绝解除阻塞并保留表单；读取失败可恢复原任务，不清除另一笔待确认提交。成功写入后的刷新故障恢复读取，避免重复写入。首次目标选择直接呈现，阶段目标、本周勾选和可折叠复盘共同组成成员页面；显示周末使用不含结束日的日期契约。

## 替代方案

仅扩展health_goals数组缺少行动身份、幂等和历史修订；把原反馈窗口改成90天会破坏1/7/30天契约。跨请求合并生成需要额外映射，因此保留每个明确请求的独立持久身份，原键在完成后也能重放。复用队列避免额外调度设施。

## 后果

health schema为42，迁移器先执行，API和Worker共同更新。旧档案不自动开启阶段。行为目标不替代专业医学目标，字符串输出不允许用药指令或临床数值处方。报告原始差值不构成改善、恶化或饮食因果结论。
