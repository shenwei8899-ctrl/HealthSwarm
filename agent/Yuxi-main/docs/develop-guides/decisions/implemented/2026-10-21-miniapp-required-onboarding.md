# 小程序建档必填信息

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/miniapp_profile_types.py

## 问题

完整建档需要明确的出生日期、健康状态和偏好，避免保存成功后仍缺少这些已约定的必要信息。

## 决策

### 实现方案

客户端逐步校验出生日期、基础病、口味、菜系、目标、过敏、不耐受、忌口和医嘱，最终提交复核全部建档成员。菜系使用独立选择区；状态只提供确认没有和有具体内容，初始状态保持未作答。明确不限偏好及饮食均衡属于有效选择。选择有时要求具体内容。

云端在小程序完整建档输入模型校验同一必填集合，再进入保存事务。共享 DietaryDetails 保持兼容草稿和其他档案编辑接口，不将所有用途变成完整建档。身高、体重和性别维持现有可选语义。配餐与商城的其他依赖不属于本次变更。

## 替代方案

仅隐藏暂不填写不能阻止旧草稿和直接 API 提交；将共享 DietaryDetails 全部改为必填会改变局部档案编辑契约。选择在完整建档入口执行严格校验。

## 后果

旧草稿需要补齐已列必填信息；现有已完成档案不批量改写。完整建档输入收紧，同一输入模型的整档保存同样要求完整。其他局部编辑接口继续使用允许未知的共享 DietaryDetails。后续配餐仍依赖模型、批准规则、权限和商城等既有条件。
