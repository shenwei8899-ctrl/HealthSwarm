# 饮食照片观察与来源定位

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_vision_types.py

## 问题

饮食识图详细设计要求返回可见食材及位置标记。现有菜名候选无法帮助复核者在多个照片视角中找到对应食物，也不能区分看到的食材与隐藏食材的不确定性。

## 决策

菜品包含有限长度的可见食材列表及至多三个归一化位置框，每框绑定一个零起始照片序号。模型可以留空未知位置，不能生成上传标识、份量、营养或数据映射。worker 按实际外发顺序附加私有上传来源；DTO 拒绝不存在的照片、重复序号和无面积或越界框。新饮食任务固定 `health-meal-v2` 提示词版本，旧版本排队任务在授权与同意检查后、外呼前拒绝，不改变报告提示词。[固定快照请求](./2026-10-05-health-meal-snapshot-json.md)继续省略供应商 JSON 模式参数并严格校验返回值。

修订保留服务器来源及模型原位置，人工补充项没有模型位置。可见食材允许人工纠正并使营养预览失效，但不参与营养计算或自动过敏判断。复核界面经现有鉴权预览接口查看原处理图与位置框，明确观察仍需人工核实。旧草稿通过空列表默认值读取，不增加数据库迁移。

## 替代方案

保留只有菜名的结果缺少设计要求的复核信息。仅展示文本方位容易在多个视角中混淆。为用户增加画框编辑器会扩大一期交互范围；本方案保留原模型标记，用户通过菜名、可见食材及排除操作纠错。

## 验证

Passed：按[饮食照片观察验证](../../testing-guidelines.md#饮食照片观察验证)执行的相关 unit 与实际 HTTP 回归 136 项通过；隔离联合链路 147 项通过，回读 HTTP 草稿、实际模型 wire、worker Task 与清空的 lease、私有原始对象及确认后的 PG 日记。篡改来源和原位置、新项附加位置、人工伪造来源均拒绝且原草稿不变。归一化框、重复视角、缺失来源、有限食材及禁止营养的边界用例由 DTO 和 provider 各自拥有。

Passed：39 项相关前端测试，lint、生产 build；真实 MealReview 组件的本地合成浏览器验证覆盖可见食材编辑的 changed 事件、位置框、加载关闭、错误和只读预览。请求逆序、关闭与卸载的迟到 Blob 不发布并回收已有 URL。浏览器截图与 DOM 实测覆盖浅色和暗色、768 及 1023 CSS 像素，并在 375 附近的 374/376 像素核对单列布局，无横向溢出；测试替身不写数据库、不上传或调用云。

Passed：独立 Reviewer 的正常 wire 7 项与 DTO/wire 28 项、MealReview 7 项。仅在测试进程恢复旧提示词后，wire 因缺少 `visible_ingredients` 正确失败；实际 system 文本的观察字段、坐标、视角及隐藏食材约束由独立断言校验，固定响应不能掩盖提示词退化。

Not run：真实视觉模型的位置和食材质量、称重误差、医学或过敏判断；需要另行授权云探针及具有真值的质量样本。当前全部云识图及咨询审批保持关闭，没有新增云费用。

## 后果

位置框由模型产生，只作为复核辅助，不证明菜品或食材真值。原照片继续受成员权限、撤权和删除源检查保护。本地合成 replay 不能证明真实模型位置质量；本任务不新增云调用、不使用真实健康资料、不扩展此前一次性两元测试授权。
