# 健康科普检索兼容专题助手与营养业务

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/health_family_kb_service.py

## 问题

健康指标助手按真实 Run 角色读取专题知识库，初始配餐和管理员营养候选导入共用固定家庭营养库的检索与来源校验。同步代码时整文件采用任意一方都会丢失另一方已有的消费路径。

## 决策

### 实现方案

咨询入口从已授权 Run 读取角色和知识库清单，在检索完成后重验当前授权、角色与配置。营养业务入口保持单参数的固定家庭库接口，由各自业务服务执行配餐或管理员授权。两种入口共用有界检索与 PostgreSQL 当前分片核对，继续分别返回 `kb_id` 或 `kb_ids`。公开来源校验默认限定家庭库并保持来源共享锁；专题咨询按真实角色校验。咨询提示同时保留指标科普工具与初始配餐依据引用要求。

App 以本地版本为准，本项不修改外层小程序、商城、数据库或部署环境。

## 替代方案

- 整文件采用远程：丢失初始配餐和候选导入所需的公开函数。
- 整文件采用本地：丢失三指标专题库范围、审计归属和发布校验。
- 为营养业务复制完整检索实现：重复维护检索限制和来源失效规则，增加后续漂移。

## 后果

检索范围由实际业务入口确定，共同检索实现只处理已经确定的知识库清单。咨询的事后授权复核发生在资料返回之前；营养业务消费者继续拥有其配餐或管理员授权。来源消费的锁、审计及发布语义分别保持在原有 Owner，没有新增配置、数据库迁移或写入入口。
