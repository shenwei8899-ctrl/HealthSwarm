# 健康审批读取当前跨进程模型视图

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/health_vision_service.py

## 问题

健康服务审批指纹包含模型端点及请求配置。管理 API 更新供应商后，独立 worker 的 5 秒进程内缓存仍可保留旧模型视图，导致新审批被误判不可用，也延迟发现供应商配置变化。饮食与咨询联合 E2E 已在真实 worker 中复现前一种失败。本记录面向健康接口维护者，只处理审批检查的当前视图，不改变通用模型消费者的缓存契约。

## 决策

模型缓存提供显式刷新操作：先丢弃进程内视图，再读取既有 Redis 投影；读取失败保持空视图，不回退旧数据。健康配置探测、管理员审批与独立 worker 在读取模型信息前刷新。通用模型读取保留既有 TTL。刷新不承诺消除核对后发生的并发配置修改。健康外呼的数据库权威核对与已构造参数绑定由[健康模型配置决定](./2026-10-04-health-model-authority.md)补充。

## 替代方案

测试等待 TTL 到期会掩盖真实审批延迟。删除所有消费者的缓存扩大性能及兼容影响。健康入口的数据库核对保留现有 Redis 运行投影，共用模型展开与凭据解析，其代价与拒绝语义由[健康模型配置决定](./2026-10-04-health-model-authority.md#后果)拥有。

## 验证

|---|---|---|---|---|---|
| 当前供应商视图立即覆盖进程内旧视图 | 新审批被旧缓存拒绝或旧端点仍通过审批 | model cache / health configuration | cache unit 与健康配置调用测试；连续运行饮食、咨询真实 worker E2E | 预热旧缓存后更换或移除 Redis 模型 | Passed |

2026-10-04 模型缓存 6 项、健康逻辑 26 项、饮食协议及清理 29 项、咨询协议 22 项、真实 HTTP 16 项和真实 worker E2E 2 项联合执行：101 passed，59.42 秒。连续切换无需等待本地 TTL。原槽位相关集合 96 passed、1 个合成 E2E 隔离 skip。联合命令及环境由[测试规范](../../testing-guidelines.md#饮食识图与咨询联合合成-e2e)维护，数据流与手算 oracle 由[饮食验收记录](./2026-10-04-health-meal-e2e.md)说明。

## 后果

健康配置核对新增一次同步 Redis 读取，使用现有缓存 wire 路径。管理 API 与 Redis 发布之间的并发窗口、以及审批核对后的配置竞态仍存在；刷新只消除当前进程的 TTL 旧视图。本地合成 E2E 不代表真实供应商质量或已获云处理批准。
