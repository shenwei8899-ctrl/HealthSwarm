# 次日提议与正式餐单采用

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_plan_adoption_service.py

## 问题

配餐师生成的预览及用户保存的餐单都是草稿。用户需要独立的次日提议和明确的正式采用，采用须消费当前专业批准。本文供健康后端和小程序接口维护者使用，承接[六Agent工程目标](../proposed/2026-10-07-health-agent-engineering-completion.md)。

## 决策

当前单成员三餐按预览、次日提议、已保存草稿和正式采用区分。用户可以把明日预览登记为次日提议；提议保留北京时间来源日、预览版本内容与来源摘要，生成不自动保存正式餐单。来源日须为服务器今天，预览日期须为明天；读取复算来源，失效或日期已过不继续显示为可用。

正式采用明确携带餐单版本、专业审核对象与档案版本。服务在同一成员锁事务中复核工程检查、当前档案/规则/配料、独立专业资格及成员审核授权，保存采用快照与动作收据。每账号、成员、日期最多一个有效采用；更换须显式携带被替代采用及版本，同日并发不能静默覆盖。取消采用携带采用版本，不改草稿、饮食记录或原快照。

专业流程失效时在相同事务中使关联采用失效；自然到期在读取/消费时复核。恢复来源或授权不能复活失效采用。普通草稿接口保留原语义，模型没有采用/批准工具；未来采购和今日来源消费同一采用Owner。商城拥有已支付订单快照，这个接口不写商城履约或已支付内容。

替代事务只取得新计划的规则/资格来源锁，然后以FOR UPDATE读取旧采用的当前占用状态及版本，不在新来源锁内取得旧规则/资格锁。普通消费按来源锁复核当前批准后刷新采用状态；快照、成员、日期须与选定计划一致。规则/资格撤回写入和显式替代通过采用行锁串行，失效与替代不能覆盖旧版本。

本文拥有单成员采用和次日提议语义。[家庭采用](2026-10-07-health-family-plan-adoption.md)拥有共同参与者占用、多旧对象替代与逐成员读取；[安全换菜](2026-10-07-health-safe-meal-swap.md)和[整份修复](2026-10-07-health-safe-plan-regeneration.md)拥有批准限制下的改版。次日提议的Agent固定工具及日终业务联动、21天/采购消费者和页面仍属于完整目标。

## 替代方案

把保存草稿视为采用会跳过专业批准和当前来源复核。只返回approval-state后另开采用事务会留下来源变化窗口。提议直接写正式计划会让生成动作产生未经用户采用的计划。复用当前事务门禁并独立保存采用及提议对象可以保留明确动作和来源。

## 后果

采用归属于当前账号，家庭采用逐一检查实际参与者的当前授权；账号归属不授予家庭权限。外部档案投影不代表红阳完整档案交付。专业生产资料、真实模型与商城联调保持外部TODO。当前阶段保留已有模型工具与草稿输出；次日登记和正式采用由明确用户API动作触发，日终和Agent次日提议联动继续待交付。
