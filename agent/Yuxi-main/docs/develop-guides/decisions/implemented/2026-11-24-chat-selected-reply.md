# 对话正文选取与引用追问

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_reply_quote_service.py

## 问题
用户需要长按当前AI正文直接选取部分文字并引用追问，原页面与旧引用按钮保持原样。原生selectable不向业务返回正文选区。

## 决策

### 实现方案

`AiAnswer` 保留原正文节点和样式，长按实际文字后仅为活跃回复生成字素测量节点。原位浮层和手柄调整同一正文区域的选区，业务卡片和空白处不建立选区。`CloudNutritionChat` 将选中文字保存为独立引用草稿，发送、历史恢复和失败重试保持引用来源与问题原文。

后端引用服务依据当前用户、目标成员、正式回复及当前公开正文核对片段。用户原问题仍存入 Message.content，引用放入消息元数据并作为明确分隔的模型上下文。Run 发布和公开读取持续核对依赖；无 Run 的分类追问在正式回执中保存实际使用的助手来源，分类调用、回执落库、重放、历史和再次引用均沿用同一来源校验。依赖查询排除未执行的旧输入，当前输入继续参与核对。持久化沿用现有消息与回执，不新增表。

## 替代方案
原生选字无法提供可控选区回调；独立选字页与已确认原位交互不符；拼入输入框会覆盖草稿并失去来源结构。

## 验证

前端全量回归 2033 项通过、3 项跳过；选区、草稿和失败编辑的定向回归通过。320、390、430 像素宽度的现有页面通过空白负控、跨段选取、保留草稿和引用发送。微信开发者工具隔离组件通过真实原生字素矩形、编译事件、手柄调整和确认引用；完整手指操作与真机仍未验证。

隔离后端在当前服务依赖镜像中应用功能增量，223 项单测和真实 HTTP/PostgreSQL 用例通过，覆盖保存、伪造片段、同键重放、越权、来源失效后的 Run 与分类派生结果隐藏、分类上下文过滤及未执行输入排除。新增模块及修改模块的 Ruff 检查通过。三个候选角色各通过 223 项单测，兼容咨询角色复用已测试的主 Worker 镜像。完整 API/ARQ/SSE E2E 未运行。

H5 和小程序构建通过，关键 WXML 经微信编译器校验。候选包保留现用运行库和其他页面，仅替换功能文件；本地主包源码 1903835 字节，超过项目 1.8 MiB 预留预算，用户选择不上传微信预览，官方实际编译体积未验证。功能增量已安装到现用目录和同名ZIP，配套后端已部署；三个角色健康、公网就绪，数据库版本保持18/41/2。

## 后果
活跃回复先测量文字分块，只为当前可见块生成逐字测量节点。4500 字原生回复测量 576 个字形，回调约 621 毫秒。引用片段限制为 1200 字，来源依赖链最多 32 层。未持久化的路由提示用同会话request_id定位真实消息，不伪造服务器消息ID。
