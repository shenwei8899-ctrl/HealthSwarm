# 建档时可选择体检报告

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/miniapp_profile_service.py

## 问题

建档第三步的体检报告是静态提示。未保存成员没有报告关联，直接打开上传接口无法确定归属。

## 决策

### 实现方案

复用报告页面。已关联成员使用现有上传和核对流程，未关联成员只选择本机临时文件。保存建档后，前端按本次幂等回执的临时编号映射和服务端回读的健康成员 ID 交接文件。用户可以选择直接完成建档。

## 替代方案

提前创建草稿成员会新增生命周期和清理职责。使用保存回执可以复用现有建档事务。

## 验证

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 未关联成员可以先选后传 | 无 ID 跳错成员 | 保存回执及报告入口 | 编译版 H5 双路径、前端回归及隔离 PostgreSQL 保存服务 | 缺映射时不可上传、同名成员不会串档 | Passed |
| 报告可跳过 | 无报告无法完成 | 建档页面 | 前端建档回归及编译版 H5 | 选择文件后仍可直达首页 | Passed |

相关前端回归 289 项通过。H5 和微信小程序构建通过，编译版 H5 用合成文件验证选完继续上传和跳过两条路径。隔离 PostgreSQL 直接调用生产保存服务，核对两个同名成员的独立报告关联及并发请求共用一份回执。完整 HTTP 测试在本机镜像收集阶段受依赖版本不匹配阻塞，未计为通过。

2026-11-12 服务器候选镜像复核了同名成员和同键回执。API 与 Worker 切换后，镜像、文件摘要、匿名访问拒绝及公网就绪状态均已核对。小程序以现用导入目录为基线合入报告流程及现网建档校验。报告组件位于健康分包，99 项合入相关回归及包体检查通过。现用目录、ZIP 和记录均已更新，首页提问等其他编译文件通过摘要核对。微信平台上传、真机与真实报告上传待验。

## 后果

临时文件只在当前页面流程传递。账号或家庭变化时丢弃交接，报告上传沿用现有授权。
