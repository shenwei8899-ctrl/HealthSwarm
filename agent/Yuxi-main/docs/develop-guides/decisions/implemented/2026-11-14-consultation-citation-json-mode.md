# 咨询最终答复的 JSON 格式约束

状态：implemented
类型：bug-fix

Owner：backend/package/yuxi/agents/middlewares/health_final_answer.py

## 问题

用户提问“聚餐可以吃啥”已被分类为普通咨询，Run 也已创建，但最终答复失败。线上咨询模型在取得本轮知识来源后输出了普通中文正文；最终答复阶段要求解析为带 `answer` 和 `citations` 的 JSON，因而返回 `citation_invalid`。原实现只在提示词中要求 JSON，实际模型请求未设置 JSON 对象模式。

## 决策

本轮存在家庭资料或审核证据引用候选、且模型使用 OpenAI 兼容接口时，在最终无工具调用上显式设置 `response_format: {"type":"json_object"}`。继续校验 `ConsultationAnswer` 的结构和每个引用 ID 的本轮归属；纯文本、伪造 ID 或无效结构仍拒绝公开。不需要引用候选的普通咨询保留现有文本流。

本次同时将已部署的结构化咨询引用实现与当前生产源文件对齐至 Git，避免后续镜像构建回退到旧的正文标记协议。生产发布只在现行镜像上叠加最终答复中间件，API 和 Worker 使用同一候选镜像。

## 替代方案

直接接受普通正文会绕过本轮来源引用校验；单靠提示词要求 JSON 已在真实运行中失败。保留严格解析，并在供应商请求上启用格式约束。

## 后果

有引用候选的咨询需要供应商支持 JSON 对象模式；无引用候选时仍使用纯文本流。模型若继续返回不合法结构，本轮仍报错，不公开未经核实的来源主张。

## 验证

隔离 Linux 镜像中的中间件、引用、答复流、任务投影及 Run 服务定向单元测试 235 项通过。新增请求载荷测试直接确认 JSON 对象模式，并确认模型仍输出纯文本时继续拒绝。生产就绪和真实问答结果另按发布回执记录。
