# 专属计划读取只准备已选菜谱

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/exclusive_plan_service.py

## 问题

已保存计划的读取仍扫描并解析全部候选菜谱，冷启动和并发时超过小程序15秒请求时限；首页还返回全部63天采购缺口，约1MB。网关出现客户端断开的499，页面显示网络暂不可用，后台计划本身已ready。

## 决策

只读已有计划时保留家庭、成员、授权与来源依据准备，跳过候选索引加载；所选菜谱继续逐一读取完整原文并严格核验。生成与恢复仍加载候选索引。首页费用摘要保留真实部分小计、未计价数量和不完整估价提示；逐日采购缺口继续由档位详情提供。

## 替代方案

单纯延长客户端超时仍重复处理无关候选。缓存整个计划验证结果会削弱实时授权及来源校验。读取跳过候选准备保持既有校验边界，并兼容当前体验版，无需更换小程序包。

## 验证

真实HTTP与PostgreSQL测试覆盖生成63天、暂停恢复、读取时禁止扫描索引、摘要体积、档位完整缺口、来源变化及授权撤回。生产只读验证记录保存在独立发布证据中。

精确发布镜像定向单元31项、三档63天真实HTTP/PostgreSQL集成通过；前端既有提交恢复与授权15项回归通过。上线后最新成功计划公网摘要1.63秒、1681字节，指定组1.51秒，三档详情3.43至4.03秒，均200且no-store。源失效及授权边界由真实集成负例验证；未执行体验版真机验收。

## 后果

只读上下文中的documents为空，仅用于已保存内容的严格验证；新菜单生成默认仍加载完整候选。摘要不再内联完整未计价食材列表，明细消费者使用既有档位详情接口。
