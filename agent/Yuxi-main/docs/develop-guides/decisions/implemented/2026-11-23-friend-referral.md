# 好友邀请与首次建档归因

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/referral_service.py

## 问题

普通用户从“我的 → 邀请好友”分享专属入口，朋友完成注册及本人首次建档后产生一条匿名成功记录。页面使用已确认的 C 版餐桌图。无奖励、佣金、客户管理权限或家庭自动加入。

## 决策

### 实现方案

邀请码属于账号。注册前首次有效邀请保留七天，以服务端签名收据固定邀请码、来源和有效期；客户端时间不决定收据有效性。新账号创建与邀请关联共用登录事务，已有账号不补绑。本人完整建档保存与成功时间共用建档事务，成功时间只写一次。匿名编号使用该邀请人成功记录的稳定序号。受邀人后续改档、换家庭不重复计数。

邀请码与邀请关系放在业务库，唯一约束限制一位新用户的一条关系。邀请人查询仅公开成功记录的匿名编号和完成日期。分享封面与海报使用相同餐桌素材，海报不包含邀请记录。微信真实小程序码来自服务端，获取失败保持失败状态。

## 替代方案

采用注册即计数会违背建档条件。复用家庭邀请会扩大家庭权限。前端自行计数无法保证事务及并发。当前使用签名收据而不建立点击事件表，匿名访问统计不在范围内。微信发布环境及相册权限需要真机验收。

## 验证

## 后果

真实 PostgreSQL/HTTP 注册建档联调已在隔离 Ubuntu 测试库通过。现用小程序目录和 ZIP 已增量合并，配套后端已部署，真实微信码生成、权限及公网就绪验收通过；微信真机分享扫码保存尚未验收。主包低于 2MiB，已有 1.8MiB 预留预算仍不通过。WECHAT_REFERRAL_ENV_VERSION 默认 release，可由部署人员设置为 trial 或 develop；微信后台需核对合法网络域名、版本页面和保存相册隐私说明。

二维码按客户端运行版本选择release/trial/develop，服务端只允许固定欢迎页。check_path=false允许该固定页在未发布阶段生成码；码生成成功不代替微信版本上传及真机验收。
