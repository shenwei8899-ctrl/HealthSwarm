# 家庭档案的监护、结构化资料与行动入口

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/family_service.py

## 问题

家庭档案具备成员、字段授权和四类测量，但儿童没有监护流程，关键资料只能写成自由文本，概览无法引导补充与确认。咨询来源把明确空数组计为未知，测量列表无法直接查看当前备注。家庭共同生活安排缺少持久化入口，家庭名称无法通过正式接口维护。

## 决策

### 实现方案

家庭路由经 family service/repository 维护 JSON 档案、授权、版本和历史。18 类资料包含结构化目标与复盘、病史、药物、医嘱、过敏、用餐及生活信息；记录保留事实、来源、日期和未知状态。家庭设置维护备餐、采购、用餐、预算及口味，家庭名称和设置更新校验版本。概览只汇总当前可见资料，处理入口跳转具体成员和面板。

监护申请绑定当前家庭成年成员、具体儿童、声明生日和有效期。独立管理员审核后产生有期限的代维护与确认权限，审核队列显示申请人账号及 UID。申请人不能审核自己，家庭角色不产生监护权。撤销、停用、成年或期限届满使权限失效；生日变更在同一事务内撤销相关监护，改回生日不恢复旧权限。审核批准重新核对当前身份、生日、年龄和期限；失效申请仍可驳回。每个儿童同时保存一名监护人，历史由审计记录保留。

咨询来源 repository 将空数组解释为明确无，将未录入或 null 解释为未知；内置营养师技能采用相同语义。未保存的新结构字段不扩展旧 11 字段来源投影；实际写入的新字段触发档案重新确认及来源失效。采用旧空数组错误语义生成的来源回执返回 410，用户建立新咨询后获得正确来源。来源回执不被静默重写。本人档案提供关联营养咨询入口，继续使用明确成员关联、字段授权和模型用途同意；临床安全编码与专业目标仍由批准数据拥有。

健康指标增加带测量日期的身高记录，与档案基础身高及其版本独立。详情显示当前备注、来源、录入人、版本和作废原因。Vue 面板处理版本冲突、失权清空、切换成员与迟到响应，编辑长表单在弹窗内滚动。正式 v012 migrator 拥有业务 schema 12 的演进，旧档案和既有授权保留，服务请求不执行 DDL。

## 替代方案

仅补界面无法闭合权限和持久化。按父母称呼自动开放儿童资料无法证明监护权限。建立另一套档案会重复身份和版本来源，均不采用。

## 后果

家庭共同安排、个人事实和儿童监护拥有可持久化入口及明确版本。旧字段保持可读，新增字段逐项保存；明确无与未知的区别进入咨询来源。监护审核记录是平台内的审核事实，资料真实性由审核者核对。家庭管理员、本人授权、监护权限和模型用途分别生效。

本地家庭预览使用隔离数据库、正式身份验证与家庭路由，保存七名虚构成员及个性化结构资料，覆盖两个儿童和不同年龄的成年人。其他导航的完整后端和云模型未在该预览启动。合并主线后保留其新增的本人血糖、血脂读取工具及独立营养任务入口；多成员 AI 处理及专业临床编码自动生成仍不属于当前实现。合并后的营养师技能版本为 `2026.10.10.2`，同时保留主线工具依赖与本次结构化字段语义；旧档案未保存新增字段时继续保持原有咨询投影。

直接负向案例覆盖自审、越权、过期、已成年、生日变更后改回、失效申请驳回、旧版本覆盖、失权和迟到响应。迁移测试覆盖业务版本 7 至 11、重复升级及失败路径。身高集成测试验证创建、读取、更正、授权和与基础档案版本独立。咨询兼容测试验证旧 11 字段投影、明确空列表、来源 410 及新咨询可用。
