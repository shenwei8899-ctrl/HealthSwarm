# 配餐师增加菜谱资料库

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_family_kb_service.py

## 问题

配餐师只绑定一个菜谱资料库。独立的「菜谱」库已经入库，但当前配餐检索和参考餐单均无法使用其中的原谱。

## 决策

### 实现方案

保留 `HEALTH_RECIPE_KB_ID` 的现有单库语义，为配餐师增加可选的 `HEALTH_RECIPE_EXTRA_KB_IDS`。服务端把主库与附加库组成有序、拒绝重复、最多五项的固定清单。现有知识检索、管理页和参考餐单检索均读取同一清单；原谱读取仍核对来源文件与分片。此决定扩展[原有单库绑定](2026-10-21-planner-recipe-knowledge.md)。

生产 API 与 Worker 配置相同的附加 ID。其他健康角色和营养设置的主库配置保持现状。绑定变更会使按旧清单哈希创建的参考餐单线程失效，用户需重新生成。

## 替代方案

把两个 ID 写入既有单值环境变量会被配置校验拒绝，也会影响其他依赖单库的服务。把两个知识库内容合并会改变资料归属和管理边界。

## 后果

参考菜谱候选增多，首次解析耗时增加。旧参考餐单绑定按旧清单哈希生成，绑定变更后明确失效并要求重新生成。

## 验证

配餐管理页的相关 unit 验证主库与附加库同时可见，并验证重复、空项和超限配置会被拒绝。生产只读探针核对两个库均存在，并在同一查询中读取到 123 与 2051 份候选文档；首次解析约 4.3 秒。部署后的 API、Worker 配置及实际检索另行回读。
