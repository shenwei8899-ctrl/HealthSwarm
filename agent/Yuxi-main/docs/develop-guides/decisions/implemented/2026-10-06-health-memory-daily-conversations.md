# 家庭营养师的成员记忆与每日对话

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_memory_service.py

## 问题

用户授权继续完成成员长期记忆和每日对话。现有健康咨询固定成员并保存消息，缺少可管理的长期自述、北京时间每日入口、历史及日终摘要。目标是在现有健康后端完成可回读的持久化和模型工具链路，保留红阳正式档案与其他配餐角色的职责。

## 决策

记忆按账号和成员隔离，PG 保存当前事实、不可变修订及运行版本依赖。工具写读与依赖提交共用事务；模型调用前将有效历史依赖传播到当前运行，修改或撤回后整轮旧来源及派生回答退出模型输入和日终摘要。服务器请求标识随用户消息保存到 checkpoint；写入提交后缺少工具收据也能按 PG 依赖失效。当前请求自己写出的新版本替代同轮旧读结果，管理页面的外部修改仍拒绝当前旧引用。记忆不写入红阳的正式档案。

自动写入引用本轮真实用户原文，原文以绑定成员及明确持续性谓语开头；临时体验直接拒绝。疾病保留用户自述和未专业审核标记。修改、删除／撤回保留版本及幂等收据，重复请求不会复活旧事实。管理页面在成功响应后回读服务器数据，未知响应重试复用原请求、内容与版本。

每日入口以账号、成员及北京时间日期唯一绑定现有 Conversation，按天展示私有成员会话。当天删除返回明确的 409，日终归档后允许删除历史会话；旧日期拒绝新请求，已开始的请求可完成。worker 分钟 cron 抽取实际成功消息形成带来源的日终消息摘录，晚到结果和失效来源改变 fingerprint，旧摘要隐藏后补跑。PG 唯一日记录与成员锁串行更新；扫描时间轮转避免历史积压饥饿，失败由后续扫描或页面补跑恢复。

健康 Schema 版本 6 的 migrator 增量创建记忆、版本依赖和每日会话表，支持旧版本 4、5，保留原记录。本决定扩展[营养师后端](2026-10-06-health-nutritionist-skills.md)及[内置 Skill](2026-10-06-family-nutritionist-builtin-skill.md)中的记忆与每日入口范围。

## 替代方案

直接接入通用账号记忆无法保留成员归属和健康授权；仅保存提示文本没有修改、撤回及幂等事实。每个家庭共用一个执行会话会扩大私有消息范围。日终另调用模型增加审批和外呼恢复表面，当前采用可追溯消息摘录，复用现有 worker cron 与 PG 原子事务。

## 后果

服务器只接受明确持续性表达，其他自然语言需先澄清，真实模型识别质量仍需样本评估。当前账号可管理自己维护的成员自述；多个账号的记忆与执行线程分别保存。依赖失效按整轮过滤，包含同轮其他内容，原始消息仍保留供用户查看。引用检查与模型外呼之间仍有时间边界，已经发出的响应不会被撤回操作追溯删除。

日终摘要呈现成功消息摘录；单餐反馈、修改撤回及模型依赖由[餐后反馈决策](2026-10-06-health-meal-feedback.md)拥有。正式餐次提议、红阳完整档案和专业内容仍需独立实现。原开发槽位咨询审批保持未启用；真实模型验证使用独立合成重放服务。发布 Skill 源码与快照需要重新加载 API、worker，新的 Schema 由 storage-migrator 发布后才能启动运行进程。
