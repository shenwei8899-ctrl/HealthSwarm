# 建档完成必须具备个人计算所需基础资料

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/miniapp_profile_service.py

## 问题

用户要求完成建档即已明确姓名、出生日期、性别、身高、体重及既有必答健康与饮食信息，不新增活动水平必填项。当前前后端刻意允许身体资料后补，与个人目标计算的输入不一致。

## 决策

小程序完整建档的基础字段全部必填且数值有效；部分字段更新仍是 patch，但已完整的档案不能被更新为不完整。历史不完整资料保留并由当前服务端完整性判断要求补齐，不迁移或伪造值。已保存体重继续使用 dietary_details.statedWeightKg，不新增第二份存储。读取、完整性判定、分析启动复用同一 DTO 重建函数。规则/编码配置错误与用户漏填分开，不将系统配置缺失描述为需要用户补资料。建档保存与首页进入不依赖配餐规则是否配置。

## 替代方案

只改星号不能阻止 API 绕过；只收紧 DTO 会因读取时遗漏 weight_kg 将完整用户误判为不完整；将通用档案 patch 的每个字段设为必填会破坏局部更新与历史资料补齐。

## 后果

历史不完整资料留待补齐，局部编辑继续沿用既有接口。

## 验证

缺失/空值/非法基础字段前后端均拒绝；完整数据保存与重读一致；旧档案保留原值但不再声称完整；成员修改不能清空必填字段；有身体资料但缺编码返回配置错误；出生日期及健康限制既有校验保留。相关前端回归、双端构建、后端 unit 和隔离 HTTP/持久化验证分别记录。测试只使用合成资料，不更改线上业务配置及用户数据。

本地验证于 2026-11-12 完成。前端全量 1709 项通过，H5 和微信小程序构建成功。后端在本机独立 PostgreSQL 与真实 HTTP 路由环境运行 96 项，包含 82 项 unit 与 14 项集成用例。真实接口验证了缺字段拒绝、并发保存回执、体重重读、局部编辑与邀请认领。测试使用锁定的 Anthropic SDK 修复测试镜像依赖冲突，应用依赖配置保持原版本。ruff 和改动空白检查通过。后端证据见 `agent/.tmp/onboarding-body-20261111/backend-result.json`。
