# EveryDay 菜谱资料暂存导入

状态：implemented
类型：feature
Owner：backend/package/yuxi/repositories/knowledge_file_repository.py

## 问题

Word 提供 1005 道菜及配图，需要保留逐菜来源与图片对应关系。原料存在模糊用量，营养值和素材权利尚未完成审核，不能作为专业菜谱版本发布。

## 决策

### 实现方案

操作脚本使用既有 KnowledgeFileRepository 注册每道菜的 Markdown，文件状态为 uploaded；processing_params.recipe_reference 保存原始数组、来源 ID、哈希、审核状态及图片对象引用。原始数据快照、许可证、原图和按 Word 裁剪的 WebP 存入私有 knowledgebases 桶。正文遵循现有参考菜谱解析格式。采用来源与版本派生的稳定文件 ID，冲突时核对已有内容并拒绝覆盖。

对象先写入且回读校验，再注册数据库记录；失败可按相同包续跑。批次清单和入库前文件元数据快照存入私有对象，回执记录逐项绑定。现有检索由 reference_recipe_index 的 indexed 条件隔离暂存资料；不创建 chunk、不触发索引或部署、不插入专业 RecipeVersion。

## 替代方案

新增菜谱暂存表需要 schema 和新 consumer；当前上传状态与 JSON 元数据足够承载。直接发布会把未审核内容混入餐单检索。合并大文档会丢失逐菜版本绑定。
