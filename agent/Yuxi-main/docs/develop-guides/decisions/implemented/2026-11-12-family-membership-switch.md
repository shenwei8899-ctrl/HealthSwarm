# 家庭切换、管理员交接与稳定成员编号

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/family_invitation_service.py

## 问题

自动建家后，接受邀请会叠加家庭归属。原家庭有其他账号时，直接退出会留下没有管理员的家庭。家庭档案与健康服务还使用不同的内部记录键。

## 决策

- 一个账号只有一条有效家庭归属。保留首次自动建家，接受其他家庭的邀请前确认原家庭。原家庭退出、归档或交接和加入在同一事务内提交。
- 有其他有效账号的家庭由原管理员指定接手人，接手人确认对应成员关系版本。旧家庭所有其他档案保留。未使用的邀请和面向旧管理员的额外字段授权失效。
- 由 `family_members.person_id` 保存稳定人员编号。已有来源优先沿用健康编号。切换只传递人员编号，各家庭继续保存独立的资料、报告及咨询记录键，保留旧接口和历史引用。

## 替代方案

禁止已有家庭的账号接受邀请会拦截自动建家的用户。移动整份旧健康关联会扩大对历史报告的共享范围。

## 后果

采用事务内切换和家庭内独立的资料引用，迁移遇到既有多家庭归属时报告冲突数量，由业务确认保留的家庭。

## 验证

隔离 PostgreSQL 中通过四个真实家庭 HTTP 场景，覆盖旧家归档、其他档案保留、本人编号延续、交接后目标邀请撤回、并发切换和多家庭旧数据迁移拒绝。使用仅注册家庭路由的验证入口，完整 API 的测试镜像依赖与当前源码不一致。
