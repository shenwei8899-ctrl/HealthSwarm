# 换菜入口独立加载与目标范围计算

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/daily_dish_swap_service.py

## 问题

已核对的当前餐单等待聊天恢复才能读取候选；整日串行候选和图片存储探测推迟入口出现，用户无法区分尚未读取、无候选和读取失败。

## 决策

当前账号家庭下已核对的今日餐单独立控制换菜。入口先显示，弹层区分加载、空结果与失败。按当前展示餐次预取、点击目标菜优先读取，同目标请求去重并合并分片结果。接口保留整日读取调用，新增可选餐次和菜品范围；提交只重验目标候选，保留整日占用菜、成员权限限制、版本锁和幂等回执。单次请求共享原文、商品索引和食材匹配结果；公共菜谱准备按内容缓存，媒体地址不探测对象存储，图片由组件异步读取。

## 替代方案

只删除入口总开关仍被卡片和点击守卫阻断。延长请求超时不会减少重复计算。跨请求缓存家庭候选难以可靠反映授权和成员限制变化，因此仅复用公开菜谱准备、请求内计算与页面中已校验的短期状态。

## 后果

本地服务与生产服务存在既有差异，发布需要分别合入增量并核对生产已有的限制和恢复逻辑。并行 HTTP 请求各自使用数据库 Session，不并发共享 Session。图片延后上下文仅在换菜入口内有效，普通请求和严格存在性检查保持原行为。候选选择后的未知写响应冻结候选与幂等键，迟到的预取不能改写重试内容。

相关前端305项、后端19项通过；独立复审的41项换菜测试及未知写响应竞争复现通过。真实本机HTTP验证当前候选路由的范围参数、旧调用兼容、非法参数422和内部快照不公开，使用合成业务适配及身份，不访问真实数据库。微信构建、Ruff检查通过。

完整前端回归2160通过、10失败、3跳过；10项失败与已有基线相同，涉及已移除的饮食日志组件和旧采购夹具的缺失依赖。全仓工程契约检查仍有27项既有文档问题；检查器63项单测有1项受Windows符号链接权限限制；本机Compose缺少运行密钥，后端容器全量单测未执行。真实PostgreSQL事务、生产对象存储故障和微信真机验收未运行。本次不部署、不上传微信，不触发图片生成。
