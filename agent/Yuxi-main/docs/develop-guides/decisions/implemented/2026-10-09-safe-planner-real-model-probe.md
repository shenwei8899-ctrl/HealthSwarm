# 单成员安全配餐真实模型探针

状态：implemented
类型：testing
Owner：backend/test/e2e/test_health_safe_planner_live_e2e.py

## 问题

安全配餐需要直接验证供应商能否按固定工具及严格最终回执完成中文换菜、三餐重生成和未就绪分支。已有固定聊天模型的配餐用途须独立审批与验收，合成探针与主服务用途配置分别执行。探针验证工程协议与业务链路，生产专业资料和模型质量另行验收。

## 决策

### 实现方案

明确开启的真实模型E2E复用独立健康数据库、合成账号、发布菜谱与专业规则、业务绑定和API/Worker链路。独立live Compose覆盖层仅给API与Worker增加出网网络，原合成internal网络保留。测试从显式模型参数创建本轮临时供应商，配置合成meal_plan用途和用户同意，执行固定中文任务；预览通过同Run权威Message、持久回执、工具审计和独立PG事实证明。仅对一个成功预览显式调用普通安全确认接口并重试原幂等键，核对唯一修订和专业状态。运行步骤由[测试规范](../../testing-guidelines.md#单成员安全配餐真实模型探针)维护。

维护者可通过已配置供应商的正式Owner解析凭据，经内部管道传给测试进程；不输出到控制台、不生成宿主凭据文件，不复制主槽的处理方审批指纹。临时供应商按现有Owner在独立PG及Redis暂存配置与凭据，结束后精确删除并使缓存失效。入口明确选择供应商及固定模型，拒绝默默使用默认模型或本地回放。测试结束先收敛Run及租约，保存有界的本轮合成模型诊断，再恢复独立槽配置、删除本轮临时供应商与合成对象，回读残留。合成探针保持主槽配置原样；主槽用途启用由管理员在独立审批后通过现有健康服务配置接口完成。

### 回执展示约定

单成员已保存餐单模式的发布Skill规定：目标工具已经返回回执时，最终返回该回执ID，包括无候选、规则未就绪和搜索预算耗尽。只有用户意图或菜位尚不明确、未生成对应回执时使用补充问题。服务端的严格JSON、当前Run归属、来源重算与发布校验继续拥有结果，不追加模型输出修复。真实探针在断言前和清理前保存有界的本轮合成结果与诊断，使completed但验收失败的运行也可定位。

## 替代方案

在现有回放fixture中增加live分支会混合本地协议标记、处理政策与真实云模型语义。直接使用主槽真实成员无法满足合成验收及业务事实隔离。独立opt-in测试和网络覆盖层使外呼与日常回归有明确边界。

## 后果

已有回执优先返回ID属于发布Skill的行为约定。服务仍接受严格合法的补充问题结构；模型偏离该约定时，真实探针的回执、工具审计及实际状态断言失败。诊断区分model_audit正文、服务端发布投影和工具持久回执，全部限制为本轮合成成员，结束后精确清理事件、取消键及临时模型缓存。

真实外部模型有用量费用、延迟和协议漂移，四个合成任务不能证明生产专业资料、医学质量、长期准确率、性能或小程序完成。主槽配餐用途配置与其处理政策、费用限额审批独立维护；探针临时审批不复制为生产审批。成员仍须各自明确同意meal_plan用途，业务档案、规则和授权门禁继续执行。出口网络只在显式live覆盖层启用，验收后移除。
