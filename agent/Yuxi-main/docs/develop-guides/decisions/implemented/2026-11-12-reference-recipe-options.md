# 参考餐单按本次已读菜谱选项保存

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/reference_meal_selection_service.py

## 问题

模型保存餐单时把同一个段落编号填入了文件和段落字段，已读菜谱因此无法通过来源校验。

## 决策

读取原谱成功后返回一个 `recipe_option`，由本次运行和原谱身份生成。同一次运行重复读取同一原谱得到相同选项。保存、替代菜选择和译文修正使用这个选项。保存服务从本次运行已完成的工具回执解析来源，并核对原谱、就餐成员、餐次和商品。

## 替代方案

继续提交两个编号会保留误填路径。按段落编号推断文件会削弱来源校验。

## 后果

模型只复制一个标识，文件和段落编号由服务端恢复。旧内部提交仍按原始编号对核验，已保存的餐单来源继续使用原始编号。无效选项可根据本次成功读取的回执修正一次。

## 验证

隔离容器的 305 项相关后端单元测试通过，覆盖真实保存工具的单选项契约、原始编号回填、其他运行的选项拒绝、替代菜和译文修正。

隔离 PostgreSQL 的两项 HTTP 集成测试通过，覆盖菜谱读取与餐单发布，以及按选项保存三餐后单独替换晚餐。集成测试使用合成资料和商品，未调用真实模型。
