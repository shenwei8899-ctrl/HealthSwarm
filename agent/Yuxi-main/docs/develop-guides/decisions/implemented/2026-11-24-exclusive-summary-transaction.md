# 专属计划概览兼容读取的事务边界

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/exclusive_plan_browse.py

## 问题

概览读取在锁定家庭行后调用拥有独立事务的完整读取。旧21天参考计划进入该兼容分支时，内层事务等待外层事务持有的同一家庭行锁，客户端超时后请求仍占用连接，后续家庭访问排队。

## 决策

### 实现方案

当前周计划摘要在同一授权事务内返回。其他计划在外层事务退出后调用既有完整读取，并固定第一次选中的推荐组ID；完整读取重新检查当前访问权限，负责旧参考版本失效状态及历史正式商城契约。家庭行锁与原有权限校验保留。两个summary HTTP入口共用该服务；旧参考版本由完整读取返回stale，历史正式计划沿用原契约。异常或取消通过原session上下文释放连接，兼容读取按当前权限失败，不复用外层授权结果。

## 替代方案

延长客户端超时不能解除事务互等。移除家庭行锁改变授权撤销的串行边界。复制旧版本状态判断会与完整读取的版本语义分叉。串行事务可直接复用现有读取行为。

## 后果

修复仅改变概览服务的事务边界，无schema变更。旧21天快照不改写，GET不生成新计划。现有前端支持stale状态，用户明确操作才发起周计划生成。已挂起的旧请求须在API更新时释放连接。

## 验证

真实HTTP/PostgreSQL回归覆盖最近和指定推荐组的summary接口、两个旧参考版本、重复并发、其他账号拒绝及21天快照保留。测试对真实数据库事务设置有界lock_timeout，使旧实现因行锁等待失败，修复后能再次立即取得家庭行锁。当前周计划及原来源失效回归继续执行。
