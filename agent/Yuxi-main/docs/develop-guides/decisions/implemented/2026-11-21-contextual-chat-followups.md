# 当前答复的情境追问与参考输入样式

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_followup_service.py

## 问题

小程序普通咨询缺少由本轮问题及答案生成的后续问题；首页问题入口会覆盖输入草稿，不适合复用为情境追问。用户同时要求参考图的透明淡紫消息气泡及胶囊输入框，保留自然换行、五个快捷入口、语音状态和既有整理餐单条件。

## 决策

### 实现方案

正文成功后，小程序对权威最终消息发起独立可选 POST。服务端重验所属账号、线程、当前用途授权及有效引用后，在 Message 元数据中一次认领；短事务提交后，复用已审批模型及预算生成至多两条 label/question，重验来源与审批再保存。模型外呼有超时，无业务工具，不修改正文和 AgentRun 终态。并发读取返回 pending；API 中断的 pending 在时限后视为 unavailable，不在 GET 或历史读取时重新生成。该有界请求由 API 请求协程持有，不另建后台任务或队列。失败不影响已完成正文。

GET 和历史公开投影只返回经过结构及答案摘要校验的建议，不透传原始元数据。前端只对最新普通咨询答案请求建议，以账号、线程及答案标识拒绝迟到结果；点击复用独立文本发送通道，保留输入草稿及图片，执行已有意图识别和服务端业务校验。归档会话、失败及生成中的答复不显示建议。`mealReplyActions` 保持原判定。

气泡与输入框由 App 的 CloudNutritionChat 及 AppIcon 拥有；首页和对话共用外观，分别使用已确认占位文案，不改变 VoiceInput 的录音、松手发送或取消协议。

## 替代方案

- 前端关键词模板无法保证针对当前答案，不采用。
- 修改最终正文流的输出格式会耦合正文解析、引用与失败发布；不采用。
- 独立 durable worker 对单次短可选调用增加任务注册与恢复表面；当前不需要，改用有界 HTTP 请求及已保存的一次认领。

## 后果

新增受鉴权的追问 GET/POST，复用 Message JSON 列，无 schema 迁移。每个有效答案最多一次额外受预算控制的模型请求；中断或失败后不自动重试模型。后端未部署时旧服务器返回无建议，正文继续可用。
