# 家庭档案统一入口与独立分析同意

状态：implemented
类型：simplification
Owner：backend/package/yuxi/services/miniapp_profile_service.py

## 问题

普通用户需要在重复资料页面中手动建立健康成员关联。单人成员编辑复用全家建档保存，并携带从配置读取的分析政策，混合了资料修改与用途同意。

## 决策

### 实现方案

家庭档案中的成员详情拥有查看、修改、当前资料确认和分析同意入口。单人编辑复用成员字段更新接口并校验成员版本，保留修改历史。家庭整体建档保持独立入口。创建者可编辑家庭成员资料，但成员本人确认和 AI 处理同意仍由服务端独立验证。

现有 miniapp-profile POST 兼容接受明确的开始分析动作，使用已保存的成员及版本，在一个事务内确认本人资料、建立唯一来源关联、记录当前用途同意和幂等收据。普通保存不产生同意；重复请求回读收据，不恢复撤回记录。历史关联冲突返回明确状态，普通读取不修复数据。

建档页的明确用途同意仅覆盖当前账号本人；监护人通过儿童档案单独确认，来源消费时再次检查监护授权。历史本人对象按账号和明确身份复用；多个候选、已有其他来源或专业快照均要求核查。已有访问范围的撤回记录不会因分析同意自动恢复。

## 替代方案

仅隐藏按钮不能解决缺失关联和普通保存携带同意的问题。前端串行创建健康成员和绑定来源会留下半完成状态。服务端事务复用现有关系表，避免增加第二套档案。

## 后果

单人编辑和建档使用不同字段投影，未编辑字段、实测记录与历史均保留。旧字段按字段补充投影，编辑体重不会隐藏原有过敏和医嘱。冲突后重新读取会退出旧草稿，避免以新版本提交旧完整副本。个人资料确认与 AI 用途同意保持独立；服务不可用时仍提供撤回入口。

接口沿用原路径并增加兼容的明确确认输入，需要配套发布小程序与后台。源码验证不代表服务器或微信发布完成。
