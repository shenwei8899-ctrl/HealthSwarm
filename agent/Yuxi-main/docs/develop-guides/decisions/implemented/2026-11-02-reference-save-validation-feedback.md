# 参考餐单保存校验反馈与一次纠正

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/toolkits/meal_planner.py

## 问题

普通合成账号的真实三餐请求完成了检索与原文读取，但保存参数把一种食材重复映射到采购决定。`ReferencePlanDraft.complete_day` 正确拒绝；工具库却过滤掉位置为空的模型级错误，给模型留下空原因，最终没有保存餐单。

## 决策

### 实现方案

保存工具为三项已知模型级校验错误提供固定错误码与修正说明，不返回异常、输入或档案正文。其他校验错误保持失败，不引导模型填写运行身份。Schema、来源、饮食硬约束、商品事实和服务端重新校验保持原样。

配餐中间件只接纳当前请求中由真实已声明保存调用产生的失败回执，允许一次指定保存工具的纠正；该次数与既有引文纠正共享。空保存调用标识或当前轮重复声明同一保存调用标识直接拒绝；后续声明不能抹去已有失败。纠正失败、调用其他工具或直接作答均不能伪装成保存完成。成功后仍由既有服务重新核验并装配结构化餐单。

当前 main 已包含旧轮工具流水与商品营销字段的上下文裁剪；本次不修改其实现。测试继续核对当前轮来源回执、checkpoint、完整商品保存核验及既有权限边界由原 Owner 负责。

## 替代方案

把模型级校验改为字段级校验可避开工具库过滤，但会改变校验组织且仍把完整参数放进默认错误。删除采购覆盖约束会允许漏项或重复采购，因此拒绝。

## 后果

固定反馈不能证明供应商模型会生成正确参数；实际普通账号端到端验证仍是交付条件。服务器已出现外部版本替换，发布必须以新核实的容器、镜像和配置为基线，不复用失效的部署回执。
