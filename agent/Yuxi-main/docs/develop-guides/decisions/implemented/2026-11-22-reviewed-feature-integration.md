# 小程序功能增量保留现行主线边界

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/daily_dish_swap_service.py

## 问题

现用小程序的后续功能与主线修复来自不同检出。直接覆盖共享模块会丢失过期餐次保护、采购限制、计费模式及邀请审核，旧测试也会删除对应负向断言。

## 决策

### 实现方案

服务声明、情境追问、记餐拍照来源、菜品去重和专属计划交互沿既有入口、服务、repository 和持久化模型装配，具体边界由各功能决定和源码拥有。服务声明确认使用业务库增量迁移，不推断既有用户已确认。

换菜缓存保存当前账号、家庭、日期和餐单版本，并携带服务端过期餐次状态。过期餐次不返回候选，替换写入拒绝执行；其他餐次保持可用。重复菜检查使用来源身份和规范菜名，在候选筛选及写入处分别执行。

采购回源继续核对当前档案、记忆限制和最终商品成分。计费模块保留关闭应用内审批的模式及现行识图调用协议。邀请审核、本人确认兼容路径及餐单归档入口继续由已有 Owner 执行。历史副本缺少的主线文件保持存在。

## 替代方案

整目录覆盖无法区分新增行为和旧实现回退；仅提交界面会遗漏服务端协议及迁移。按功能提取增量并保留主线负向测试，使共享边界在最终装配树中得到验证。

## 后果

新功能与主线保护共同生效。服务声明要求配套迁移和服务端接口；前端通过不代表真实模型、生产部署或微信真机验收。功能分支保留未验证范围，发布由独立发布流程负责。

## 验证

前端默认测试覆盖交互、声明、追问、记餐和换菜；HTTP 与隔离 PostgreSQL 验证声明确认、来源版本及过期餐次拒绝。工程规范、检查器自测和后端非慢速单元测试在最终整合树执行，具体结果以对应提交的验证记录为准。真实模型、支付和微信真机不属于本决定的已验证事实。

检索回归分别使用多来源同名菜验证候选去重、未返回来源不可读取，以及不同菜名验证候选数量上限。参考餐单 HTTP 验证隔离外部成品图查询；真实 PG 仍拥有菜谱、菜单、确认与版本结果，图片生成不属于该测试的已验证范围。
