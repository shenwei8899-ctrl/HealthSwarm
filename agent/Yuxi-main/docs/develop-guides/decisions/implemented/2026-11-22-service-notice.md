# 账号级服务声明确认

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/service_notice_service.py

## 问题
注册与健康 AI 使用需要确认个人理解服务边界；成员健康数据用途授权无法表达账号级声明。订单、账号管理和已保存历史仍需要可访问。

## 决策
### 实现方案
声明正文、版本与内容摘要由 service_notice_service 拥有。公开读取接口不要求登录；认证确认接口仅操作当前账号。PostgreSQL 的 service_notice_acknowledgement 以账号 UID 和版本作为复合主键，重放保留首次服务端时间，既有用户迁移后保持未确认。微信新用户注册、身份关联和明确声明确认在同一事务提交；既有账号登录及会话返回确认状态。

欢迎页在微信登录按钮下方展示默认未勾选的确认项，保留服务端完整确认文案。点击独立声明标题只读查看全文，关闭不勾选、不保存确认；登录前的查看不依赖账号确认状态接口。用户明确勾选当前版本后，才显示微信原生手机号授权按钮；取消勾选、切换账号、离开页面或收到版本拒绝后清除本次确认。已登录但未绑定手机号的账号保存已经勾选的确认，无需再弹同一声明。首页异步补确认继续使用带勾选的共用弹层，不阻断档案、历史或导航，短提示无点击行为；设置页复用只读正文。Presenter 使用注册栈恢复嵌套历史预览下方的宿主，H5 Teleport 与微信 root-portal 保证弹层不受导航层级遮挡。

新健康请求、意图分类、独立生成、显式失败恢复和后台模型外呼边界核对账号声明；公共历史读取授权不增加声明门槛。服务端明确拒绝声明后，客户端完成确认并仅沿原请求重试一次；切换账号或家庭不重放旧操作。确认回执丢失先回读服务端事实。声明更新必须增加 NOTICE_VERSION，不得改写已占用版本的正文。健康档案用途同意独立保存。

正式 API 构建排除仅供模拟交易使用的五张食材包插画；演示构建保留资源，正式对话使用的燕麦图片仍在主包。

## 替代方案
成员用途同意具有不同身份与用途语义；前端持久标志无法证明服务端接受；全局路由拦截会阻断账号和订单访问；在公共咨询读取校验中增加门槛会影响历史。

## 后果
业务 Schema 版本为 17。部署时先迁移再升级 API 与 Worker，最后启用配套小程序。旧客户端未携带声明时不能注册新账号，旧会话仍可读取既有资料。迁移前未确认账号的后台任务不能启动新模型处理，账号确认后可明确重试。正文及政策版本变更需要重新发布。确认不自动授予任何成员健康数据访问权。

## 验证
前端完整 Node 回归通过；后端相关 unit 与独立 TCP/PostgreSQL 验证当前账号隔离、重复迁移、注册前拒绝、版本和摘要错误拒绝、确认幂等及意图认领前拒绝。浏览器以 320/390/430 宽度验证默认未勾选、关闭不登录、勾选继续、首页短提示、设置只读、老用户保存后重开不重复和声明故障时历史仍可读取。H5 与正式 API 小程序构建完成，微信 root-portal 编译产物已核对。真实微信手机号授权、真机和生产部署分别验收；本地证据不替代这些检查。
