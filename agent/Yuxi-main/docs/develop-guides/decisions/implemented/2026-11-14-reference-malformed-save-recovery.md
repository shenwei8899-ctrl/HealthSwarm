# 参考餐单保存工具参数无效时的单次恢复

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/buildin/health_meal_planner/graph.py

## 问题

参考配餐已成功读取当前 Run 的档案、商品和原谱，模型最终返回 `save_reference_meal_plan` 工具调用，但参数不是合法 JSON。工具调用被解析为 `invalid_tool_call`，正文为空；原恢复分支只处理普通正文，随后业务结果校验收到空字符串并报 `planner_output_invalid`。生产审计显示本次调用的参数尾部多一个右花括号，且字段未装入工具要求的 `read_selection` 对象。

## 决策

仅当本轮成功回执已具备档案、商品和原谱，且模型没有有效工具调用、正文也不是合法的补充问题或预览回执时，再请求一次保存工具。重试前重新检查授权，并将首次模型调用的用量快照带入第二次调用。重试只绑定 `save_reference_meal_plan`，明确顶层 `read_selection` 结构和合法 JSON；第二次仍无唯一有效保存调用时，以 `reference_tool_parameters_invalid` 明确终止。工具节点和参考餐单服务继续校验来源、餐次、食材、商品与保存回执；不把畸形参数修补后直接提交，也不接受模型正文作为餐单事实。

## 替代方案

直接裁剪多余花括号并补上 `read_selection` 可处理这一次字符串，但无法证明其他畸形参数的语义，也会把模型数据改写后送入有副作用的保存工具。放宽最终正文校验会绕过真实保存回执。受限的单次模型重试保留原有信任边界。

## 后果

一次畸形保存调用最多增加一次模型调用；重复畸形结果明确失败，不反复消耗预算。成功恢复时两次规划调用的用量都会计入 Run；再次畸形而抛错的失败 Run 仍可能缺少该次用量快照。重试仍可能因供应商或真实来源校验失败而不能保存，生产就绪状态不能代替同题真实 Run 的结果。

## 验证

`test_reference_meal_finalization.py` 覆盖已读真实回执后的畸形保存调用、受限重试成功与再次失败、授权撤销拒绝重试、真实工具节点保存及三次模型调用的累计用量；原有补充问题、缺原谱、不合法来源及保存后的结果校验继续通过。真实供应商与 Worker 同题结果在发布后核对。
