# 营养咨询按校验后的句段流式展示

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/chat_service.py

本决定部分取代[健康解释校验后公开](2026-10-13-health-validated-publication.md)中仅固定进度的运行展示限制；原始候选关闭与正式结果事务沿用原 Owner。

## 问题

小程序只能等待最终咨询结果，长时间没有正文反馈。直接开放模型消息会暴露推理、工具内容及尚未核对来源的候选；完成后拆分文本不能改善真实生成期间的体验。

## 决策

### 实现方案

四个教育角色的执行图保留原业务工具，在准备阶段要求显式工具调用。准备完成后通过内部 `finalize_health_answer` 进入当前 Request 专属的最终阶段，随后只调用一次不绑定工具的模型生成正文。该阶段仍经过原授权、预算、用量与最终引用中间件；不会先生成完整答案再重写，也不能沿用上一 Request 的阶段标记。准备轮的普通文本、推理与工具前言始终不公开。

`HealthFinalAnswerMiddleware` 仅在这次无工具调用中产生带当前 Request、Run、线程及消息身份的专用 custom 增量。`TrustedHealthFinalAnswerStream` 累计正文，在引用括号闭合后的完整句段处尝试公开前缀。`chat_service.validate_health_stream_prefix` 先核对当前执行所有权，再复用档案、处理用途与证据发布校验。引用未完整时继续缓冲；其他校验失败按原任务失败路径处理。配餐等结构化业务输出继续使用校验后的业务回执。

通过校验的增量使用独立 `yuxi.health_answer_delta` 事件，公开字段限定为当前 Run、Request、线程、消息、Unicode 码点 offset 与正文增量。Redis 内的累计前缀仅供读取校验，不进入公开事件。`agent_run_service` 在实时发送和断线重放时再次核对当前来源；撤回后返回固定错误并关闭流，不能重放旧正文。

前端将增量用于生成中的临时展示，重复帧去重，缺帧从头恢复。取消、离页、换号与失效授权清除临时正文，最终内容仍由既有持久化和结果接口决定。流式段落不代替正式配餐批准，不改变消息持久化或终态事务的 Owner。

## 替代方案

- 保留仅阶段事件：能说明处理状态，但无法逐段阅读实际答复。
- 直接开放原始模型流：不能保留来源及内部消息的公开边界。
- 完成后使用定时器拆字：不是真实生成期间的增量输出。
- 等普通模型消息结束后公开：可以排除后到的工具调用，但无法在生成期间阅读正文。

## 后果

引用位于较后位置时，首段会等到完整引用通过校验后才出现；页面仍展示真实阶段。准备结束动作增加一次按实际用量结算的模型调用；供应商必须支持工具调用策略，不兼容时显式失败。每次公开与重放增加当前权限和来源读取。单条前缀上限为 32,000 个 Unicode 码点，避免无界缓存。已显示的段落不能等同于最终完成结果；后续校验失败时前端清除临时内容。

## 验证

`backend/test/unit/middlewares/test_health_final_answer.py` 使用真实 `create_agent` 与 v3 协议，用门闩阻止最终模型生成第二块，直到测试已经消费首个 custom；同时覆盖原业务工具、实际用量中间件、同请求恢复、跨请求阶段重置、规划文本失败及回调错误不能完成。

`backend/test/unit/services/test_health_answer_stream.py` 将真实执行图事件接入前缀校验与公开投影，验证首段早于后续输入和完成事件、句段边界、累计校验、Unicode offset、未闭合引用与其他请求隔离。

`backend/test/unit/services/test_health_answer_stream_publication.py` 对实际函数做隔离边界测试，验证增量窄投影、同轮身份、每次传输前重验、证据撤回停止重放，以及执行所有权与来源校验顺序。数据库和来源依赖为测试替身，这些结果不能代替真实 PostgreSQL、Redis、Worker 和微信真机验收。

本地 H5、微信构建与前端行为测试分别验证编译及客户端行为。真实服务端到端与正式发布必须另外执行，不能以本地替身测试或默认 mock 构建代替。`test_health_validated_publication_e2e.py` 的独立回放使用真实 HTTP、Worker、PostgreSQL 与 Redis，并要求最终模型完成前首段已公开；只有实际执行后的回执才证明该链路通过。
