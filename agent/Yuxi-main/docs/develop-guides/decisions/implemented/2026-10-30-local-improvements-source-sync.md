# 本地客户端与服务端改进回存

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/daily_meal_plan_service.py

## 问题

已安装客户端的聊天、档案、餐单交互与本地语音、失败工具恢复、商城界面不在同一可重建源码版本。主线的就餐者与餐次选择、完整工具参数处理、微信编译兼容及男孩形象拥有当前产品行为。

## 决策

### 实现方案

客户端在 App 内整合本地交互，并保留 NutritionistCharacter 的男孩形象和分状态动作、referenceSelection 的明确成员及餐次语义和任务入口的函数作用域绑定。用户草稿、服务端任务、当前滚动位置和详情显示分别由既有客户端 Owner 管理；未知提交只回读原请求，取消超时在成功核对后恢复显式停止和流式接收，不自动重复写入。

语音路由复用 JWT 认证，以用户和请求键隔离 Redis 锁及结果，凭据只从服务端环境读取。参考采购通过 daily_meal_plan_service 校验当前家庭、日期、每日版本和来源中的非空去重餐次子集，来源证明再次执行同一校验。模型适配器仅在发送边界将历史未完成工具调用转换为失败说明，当前轮调用、已完成配对与 checkpoint 保持原语义。商城 console 接入既有导入预检、确认和批量发布后端。

## 替代方案

整目录覆盖会撤掉主线配餐、模型和 schema 更新；仅回存旧提交会遗漏后续交互。逐文件三方整合保留当前业务 Owner，并由正式测试入口覆盖新增导航与餐单测试。

## 后果

源码回存不改变运行中的服务、数据库 schema 或微信安装包。参考单餐购买依赖配套后端；语音默认关闭，真实录音识别依赖部署环境和供应商配置。

## 验证

- App 正式测试入口 966 项通过；H5 和微信小程序的普通、API 模式构建通过。普通编译包 1,839,530 字节，低于 1.8 MiB 预算。
- 相关后端 unit 203 项与真实 TCP、PostgreSQL、Redis integration 44 项通过，覆盖认证、账号隔离、幂等重放、单餐购买、版本变化与来源替换。完整 unit 的最终结果与所用隔离环境记录在 PR。
- 工程契约检查和 63 项检查器自测通过。浏览器合成接口核对男孩素材、餐单详情、未知营养和窄屏布局；商城真实 JS 在合成接口下核对导入记录、先预检后确认及一次确认。
- 真实微信、付费 ASR、真实模型、支付、生产发布和完整 worker E2E 属于未执行范围；合成协议测试不替代这些验收。
