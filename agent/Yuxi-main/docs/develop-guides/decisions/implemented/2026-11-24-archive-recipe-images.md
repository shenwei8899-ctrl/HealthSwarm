# 餐单归档复用已存在的菜品图片

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/meal_archive_service.py

## 问题

今日餐单读取时会通过 `reference_meal_media` 查询异步生成的图片，而归档仅返回保存时的快照。图片在保存后生成时，归档仍然无图。归档白名单过滤了菜谱来源，直接用归档菜谱重新计算图片键也与生成端不同。

## 决策

- 由 `recipe_image_identity.recipe_image_key` 统一拥有图片身份算法，保持与已发布算法完全兼容。
- 新归档只保存派生的图片键，不复制菜谱来源证明或健康资料。
- 旧归档依据所属家庭、日期、版本和完成状态核对已保存来源，比较原始菜名、食材、做法与文件/分块身份后恢复图片键。无法核对及冻结来源不借图。
- 归档读取仅补充已存在图片到响应副本，不生成图片、不回写历史、不调用当前商品或营养策略。
- 来源批量查询、图片键去重，最多6个并发对象查询，总补图预算1秒。超时保留已有图片和历史餐单。
- 今日餐单的归档回退同样补图，公开响应过滤内部图片键。

## 验证边界

单元测试验证旧键兼容、来源匹配与负向权限条件、冻结来源拒绝、快照不变、晚出图和超时降级。真实HTTP/隔离PostgreSQL验证先保存后出图、旧归档恢复、今日回退同图、无历史写回和非家庭成员拒绝。

部署增量必须保留线上已有的只读归档授权及互锁修复，不把工作区其他未上线模块变更带入。生产餐单数据不属于本次验证范围。

## 替代方案

读取归档时重新生成图片会产生外部副作用，因此只补充已有图片。

## 后果

缺图保持占位；来源和权限失败继续拒绝。

## 验证

归档图片单测及HTTP/PG测试提供回归证据；本次整合的运行结果记录于PR。
