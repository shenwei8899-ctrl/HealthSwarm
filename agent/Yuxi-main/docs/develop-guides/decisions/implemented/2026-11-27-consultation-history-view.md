# 资料改版后的历史回看

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/repositories/health_consultation_repository.py

## 问题

生产只读诊断确认：2026-11-24 的五条营养咨询因 `profile_source_changed` 返回 410，五条参考配餐因成员资料或知识库绑定指纹变化返回 `source_invalidated` 410。会话均为 active；目录把来源版本失效与无权访问合并，导致整条历史无法打开。

## 决策

### 实现方案

目录、正文历史和已读标记使用独立的历史读取授权。当前账号、项目、成员、家庭关系、来源身份和访问授权仍须有效；档案缺失、来源不可见或撤权仍拒绝。已公开答复的引用和记忆撤回继续重验。成员资料或绑定指纹变化时允许历史读取，并返回 `history_read_only`。继续执行、工具审计、引用其他答复和业务动作沿用严格校验。

前端显示历史提示并禁用该对话的续聊及业务动作。缓存先显示正文，当前历史授权刷新完成前不恢复执行。冻结的参考消息独立渲染原快照，不读取或替换成当前日餐单，不请求当前商品状态，不授予采购或采用权限。菜谱文件撤回、正文哈希变化及记忆撤回继续阻止原内容展示；本次不放宽菜谱改版契约。

## 替代方案

- 去掉全部历史来源校验：会绕过成员退出、撤权和引用撤回，不采用。
- 继续屏蔽整条历史：权限边界简单，但资料正常改版会使历史丢失，不采用。

## 后果

历史值与当前健康资料可能不同，因此只读提示持续显示。档案改版不使已保存答复丢失，也不会把旧答复重新认定为当前建议。来源已撤回的派生答复隐藏，线程中仍获授权的用户输入可以保留。

历史读取参数只由这些服务器内部读取入口设置，不进入外呼、执行、引用或采购入口；不修改数据库 schema 或生产记录。
