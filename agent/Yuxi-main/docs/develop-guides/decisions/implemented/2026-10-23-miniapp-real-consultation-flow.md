# 现有小程序咨询主链路的真实服务验收

状态：implemented
类型：testing
Owner：backend/test/support/health_miniapp_consultation_replay.py

## 问题

用户报告聊天首页点击发送没有反馈。协议模拟测试不能证明页面、实际 API、Worker 和 PostgreSQL 的完整链路。用户授权修复 HealthSwarm 根目录既有 App 前端，并要求验证登录建档、咨询、离开重进、切号和撤权。

## 决策

### 实现方案

现有 App 页面连接独立 Compose 槽位内的真实 API、Worker、Redis 和 PostgreSQL。合成普通账号通过页面建档、明确关联本人健康对象、确认基础资料及咨询处理同意。模型使用固定回放；回放适配层只翻译两条固定中文问句和答复，父级 validator 独立核对工具、来源哈希、确认版本、身高和营养安全状态。

页面反馈由 HealthSwarm 的 App/src/components/CloudNutritionChat.vue 负责：资料加载中禁用发送并显示进度；读取失败保留草稿并给出重读入口；未关联本人时提供资料入口；服务未就绪显示原因。失败后用户可以开始新咨询，保留当前编辑的文字和图片；真正授权失效仍清除私有态。SelfAccountDetails.vue 在新建本人健康对象后回读关联状态，使用户可以直接执行已有的显式关联动作。

任务提交、Worker 执行和最终消息由既有后端负责，数据库回读核对同一 Request、Run、Message 和档案采用版本。旧档案 checkpoint 被拒绝时仍要求新建会话，授权和来源检查保持生效。

## 替代方案

仅补组件模拟测试无法证明实际装配。生产账号会引入真实健康资料和外部费用，隔离服务配合固定回放能验证工程链路并保留独立业务 oracle。绕过旧 checkpoint 来源校验会扩大数据访问，因此采用已有新会话入口恢复。

## 后果

该验收覆盖现有 App 的 H5 页面及真实后台工程链路。微信包通过编译仍需正式登录、合法域名和手机验收；真实模型质量及正式政策单独验收。家庭配餐依赖专业来源与用途配置，未就绪时返回明确状态，普通咨询成功不等于家庭配餐完成。

## 验证

2026-10-23，两个合成账号完成页面登录与档案维护。新账号经真实 Worker 返回确认后的 172cm/v3 基础档案，独立 PostgreSQL 回读确认同 Request/Run/Message、档案采用 v3、终态执行 Owner 和 lease 已释放。刷新恢复答复且新增 Run 为零；切回账号恢复本人历史；跨账号读取返回 404，撤回咨询同意后返回 403，页面停止展示原答复。

App 全量 439 项测试通过，H5 和 mp-weixin 构建通过。新增回放负向测试覆盖旧版本、错误身高、多模态 content 和未知答复；组件回归覆盖加载未完成、读取失败、失败重开保留草稿及新建后显式关联。详细命令与未验证范围保存在本轮本地验收记录，合成证据与凭据不进入版本管理。
