# 知识库菜谱导入时转为简体

状态：implemented
类型：feature
Owner：backend/scripts/import_reference_recipe_catalog.py

## 问题

知识库原谱同时使用简体和繁体。新导入的菜名、食材、做法和其他展示文字统一转为简体，便于用户阅读和商城核对。来源 ID、链接、原文哈希、图片及知识库文件保留。已入库菜谱原地迁移和部署另行安排。

## 决策

一次性导入脚本使用固定版本的 OpenCC `t2s.json` 转换展示字段，再校验结构和写入。主表食材和食材明细复用同一个转换结果。去重时以同一转换规则对比新旧资料，已经存在的同内容记录可以核对后跳过。对比仍需检查食材拆分与顺序、图片和来源。

在后端目录执行 `uv run --group recipe-import python scripts/import_reference_recipe_catalog.py 清单路径` 做只读预检，正式导入时显式追加 `--apply`。OpenCC 属于导入脚本的依赖组，API 和 Worker 不需要它。两字形转换仅涉及展示字段，原文及来源参照仍由知识库和导入清单提供。

## 替代方案

在展示时转换会让数据库和商城匹配继续面对不同字形。采用入库转换后，检索和展示可以共用简体菜谱。

|---|---|---|---|---|---|
| 新菜谱导入主表与明细后为简体 | 两表内容或位置不一致 | 菜谱导入脚本 | 在空的隔离 PostgreSQL 用 CLI 导入 15 道试点及 1 道繁体样例，回读同一用量、位置、来源和图片哈希 | 全繁体样例须能区分未转换结果，错误的食材字段类型须拒绝 | Passed |

## 后果

后续新导入的展示字段统一用简体。当前验证使用隔离数据库，服务器已有菜谱和知识库原文没有改动。
