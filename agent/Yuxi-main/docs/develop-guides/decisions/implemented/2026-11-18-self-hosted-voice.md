# 小程序语音由自有服务器转写

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_voice_service.py

## 问题

手机端首次使用语音需要下载约 82 MB 的模型。用户希望服务器安装模型并接收录音，返回可编辑的文本。

## 决策

### 实现方案

微信小程序复用录音上传代码。语音路由继续验证用户、格式、大小及请求标识，服务通过配置选择服务器上的 Paraformer，复用短期文字缓存和限流。模型、词表和归一化参数来自只读目录。ONNX CPU 推理使用独立线程和有界并发。录音只用于转写，临时上传文件随请求关闭，应用不建立录音档案。小程序在录音前说明处理用途，识别后将结果填回输入框。

## 替代方案

手机端推理需要分发模型。第三方识别会把录音交给外部处理方。自托管推理将录音处理和算力成本集中到自有服务器。

## 后果

启用时 API 通过 `HEALTH_ASR_PROVIDER=paraformer` 和 `HEALTH_ASR_MODEL_DIR` 读取只读的固定版本模型。每个 API 进程最多同时进行一次推理，繁忙时提示用户重试。请求超时或取消后，计算真正退出才释放推理槽位。原始音频和完整转写不写入应用日志。

## 验证

语音单元和隔离 PostgreSQL、Redis 的真实 HTTP 集成共 19 项通过。包括公开普通话录音及其 60 秒拼接样本、静音、鉴权、超限、重试去重。前端 1775 项测试通过，验证转写回填保留文字和图片草稿。生产容器回读了配置及真实模型转写。微信手机真机录音和权限行为待验。
