# 家庭营养入口的业务就绪诊断

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/health_readiness_service.py

## 问题

成员能力查询拥有授权、角色、Skill、用途配置和同意事实，但客户端缺少运行依赖与业务目录缺项的统一提示。平台接流量检查不能说明专业方案适用性；对象存储或专业来源缺失也不应停用独立的文本咨询、人工录入。

## 决策

### 实现方案

新增授权后的成员 readiness GET，复用成员能力 Owner 与核心 readiness 探针，补充有界、只读的对象存储访问探针及专业目录存在性。服务返回各入口状态、具体依赖和允许的人工路径，不返回健康正文、处理方凭据或底层异常。普通咨询不依赖专业档案或规则；专业入口缺来源时不可用，明确选择仍由实际业务服务验证。

健康任务创建入口在证明成员可见后检查运行依赖，故障时返回 dependency_not_ready 且不创建线程。已有提交、执行、发布 Owner 继续重验当前授权、所选版本和最终来源。人工录入只依赖自身授权与数据库；平台 readiness 不增加临床或存储条件。

## 替代方案

扩大平台 ready 会使非依赖入口被全局关闭；复制所有专业校验到诊断服务会造成另一套授权和规则真相。使用当前 Owner 的最小摘要，目录存在性明确不表示适用或专业批准。

## 后果

查询只表达当前快照和目录存在性，不能保证下一次写入成功或正式专业适用性。数据库不可用时无法证明成员可见，返回现有服务错误并使用平台 ready 排障；不泄露成员是否存在。外部供应商质量、正式小程序与专业数据交付仍由各负责人验收。

对象存储使用独立签名只读请求，设置连接、读取超时并禁用重试；异步调用者有等待超时。同步 SDK 线程在取消后仍依赖其传输超时退出，诊断不证明写权限或上传完整性。角色版本只比较当前发布 Skill 与数据库登记事实，不能证明所有 Worker 的部署版本。
