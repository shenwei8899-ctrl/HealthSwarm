# 成员餐单草稿列表分页

状态：implemented
类型：feature
Owner：backend/package/yuxi/repositories/health_meal_plan_repository.py

## 问题

成员餐单列表只返回最近 50 份及截断标识，后台无法查看更早的餐单。查询必须保持账号、成员及家庭参与者的当前授权边界，默认调用和现有餐单详情操作需要继续工作。

## 决策

### 实现方案

沿用已有健康列表的 `limit/offset` 请求方式。HTTP 入口校验每页 1 至 50 条、非负且可由数据库整型承载的偏移；默认 50 条、偏移 0。repository 保留 `updated_at DESC, id ASC` 排序，读取请求页加一条以判断后续页，继续重验成员及读取到的家庭参与者授权。service 返回当前页、既有 `truncated` 与可为空的 `next_offset`，查询只读业务事实，不修改餐单、修订、审核、采用或运行记录。

现有后台以固定页大小展示餐单并提供前后翻页。切换成员、授权变化、刷新与保存餐单后重置分页；异步响应只有仍属于当前成员和查询代次时才能展示。加载和一般读取失败清除旧列表；403/404清除全部私有详情及历史。正常翻页保留用户已选定餐单的版本事实，选择框只显示当前页条目。API 参数统一由既有健康 API 封装传递。

## 替代方案

游标方案可避免部分位置偏移，但排序字段在保存和换菜后会变化，不能单靠游标实现跨请求固定快照。本范围采用现有偏移协议，并明确列表变化后刷新首屏的行为。一次返回全部餐单会扩大响应和授权读取范围，维持固定截断则不能访问旧记录。

## 后果

偏移分页分别读取当前数据库事实，餐单新增或更新后列表位置可以变化，客户端刷新首页以重新开始，不宣称跨页快照一致性。此决定补充[餐单草稿工作台](./2026-10-06-health-meal-plan-workbench.md)的列表范围；客户端参数与错误处理由[分页参考](../../../advanced/health-meal-plan-pagination.md)说明。正式小程序可以消费同一协议，页面接入仍由客户端负责人交付。
