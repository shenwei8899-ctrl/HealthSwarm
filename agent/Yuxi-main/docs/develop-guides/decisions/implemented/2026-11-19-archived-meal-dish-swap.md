# 过期餐次的换菜处理

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/daily_dish_swap_service.py

## 问题

成员档案更新可使参考餐次来源失效。每日餐单回退到只供展示的归档，归档菜品没有换菜所需的来源引用。候选服务遍历全天菜品时直接读取该字段，任一过期餐次都可使整个请求返回 500。

## 决策

### 实现方案

候选 GET 复用每日餐单的 `needs_regeneration`。每个过期餐次返回空候选，其他餐次继续按原食材、成员授权与限制生成候选。换菜 POST 在持有餐单锁时重读当前餐单，已有同键回执继续幂等回放，新请求以 `swap_meal_needs_regeneration` 和 HTTP 409 拒绝过期餐次。

客户端按餐单和候选响应显示餐次状态。过期餐次保留归档展示，重新安排入口先刷新今日餐单后复用既有重排流程。弹窗打开后收到该 409 时，客户端撤下对应餐次的候选并提示重新安排。

## 替代方案

给归档补写来源引用会使展示数据参与换菜校验。整日拒绝换菜会同时阻断来源仍有效的餐次。

## 后果

成员资料更新可以在餐单版本不变时使餐次过期。换菜写入依赖本次事务的来源复核。返回过期状态无需改动数据库结构。

## 验证

真实 HTTP 与隔离 PostgreSQL 回归覆盖小程序档案保存、旧候选提交、归档展示和新版本回读。混合餐次回归验证过期餐次拒绝换菜且有效餐次可完成写入。客户端测试覆盖同版本过期提示、正常餐次候选和重排入口刷新。
