# 家庭档案共享与独立 AI 来源授权

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/family_service.py

## 问题

已确认产品范围允许已登录、已认领同一家庭的有效成员账号读改有效成员的档案、姓名、关系及实测记录，包含尚未认领的档案。普通档案需要同时满足家庭共同维护与独立 AI 来源控制。AI 读取、报告原图、聊天和交易维持独立授权。

## 决策

### 实现方案

本决定部分取代[初始档案授权](./2026-10-04-family-archives.md)、[日常维护闭环](./2026-10-08-family-archives-completion.md)和[监护资料入口](./2026-10-10-family-archive-development.md)的普通档案权限范围，保留其版本、审计、监护确认与独立来源规则。

普通家庭接口通过 FamilyRepository 查询和家庭行锁确认访问者的有效成员身份。FamilyService 仅为普通档案开启家庭共享字段计算，保留版本、审计、历史和实测更正语义。授权来源函数默认仍执行原显式字段授权，供健康资料导入及 Agent 读取边界使用。姓名与关系编辑开放给有效成员；家庭管理、邀请、监护审批和本人确认保持各自身份检查。

响应以 `profile_access=family_shared` 标识普通共享；独立字段授权到期不会清空共享投影，访问失败与退出仍清理页面。家庭页面按服务端共享字段提供编辑入口，并说明加入家庭后的共享范围及 AI 的独立授权。已有字段授权接口保留为 AI 来源授权兼容路径，不得把它的撤回描述成普通家庭档案不可见。

## 替代方案

维持现状不能满足已确认共享要求。全局放开字段函数会把家庭关系错误地传播到 AI 来源读取。分别保存一套共享授权会产生重复事实，因此由实时有效成员关系决定普通档案共享。

健康资料集成首轮 16 通过、1 项失败：`test_ordinary_consultation_contract_authorization_and_idempotency` 未取得咨询用途同意却期望列表 200，实际为 `403 consent_required`；加载修改前 HEAD 的 family service/repository 可复现。测试在隔离 schema 登记明确的合成咨询用途同意，并断言未同意和撤回同意均返回 403；成员 grant 撤回使用空 scopes 真正移除咨询所需的 ai_use，列表与幂等重试均须返回 404。2026-10-15 该契约用例定向复测通过，另一个四类科普历史同意撤回用例通过。生产同意门禁、模型和政策配置保持原状。

执行入口：容器内 `uv run --frozen --no-sync pytest` 的上述 test 路径及完整 `test/unit -m "not slow"`，前端 unit、lint、build，工程契约检查及其 63 项单测，文档 build 均有本轮日志。Ruff 使用 `--no-cache`，避免只读挂载下缓存权限问题。浏览器覆盖浅色、深色、移动布局、关系编辑、独立授权到期及失去访问后清理，使用合成响应，未调用真实模型。独立 Reviewer 已审查实现和边界。

## 后果

普通档案接口扩大可见范围，需要同步正式客户端。模型、政策、生产真实账号及正式小程序验收不属于本次工程测试结论。旧字段授权的撤回只限制独立来源读取，普通共享以退出或停用家庭身份终止。
