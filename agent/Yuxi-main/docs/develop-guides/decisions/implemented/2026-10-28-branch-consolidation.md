# 分支整合中的功能保留与来源协议

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/daily_arrangement_service.py

## 问题

历史分支同时包含尚未回存的修复和已被主线继续扩展的实现。仅按提交祖先关系或自动合并结果判断完整性，会遗漏营养来源管理与登录会话保护，也会重复注册接口、路由及导出，或恢复已经被替代的每日采购协议。

## 决策

### 实现方案

每日安排保留当前服务拆分、单日专属计划、准备流程及采购来源校验；三个迟到失败分支重新取得按账号、家庭和日期隔离的事务锁后，先检查并发赢家是否已经就绪，并复验当前来源，再决定返回快照或推进尝试。知识文档身份和正文检索保留已回存的生产实现，并补回缺少的回归测试。管理前端合入营养来源选择、批准规则及准备状态组件，保留当前审核与交接入口。登录请求按发起时的会话处理迟到认证错误，初始化结果隔离退出后的旧会话。重复接口、路由和导出只保留当前装配中的一份。

本决定部分取代[专业来源关联记录](2026-10-16-health-professional-foundation.md)中按整个安排版本和尝试号失效采购包的方案。当前 `daily_arrangement` 来源协议按本餐摘要、原质量依据、成员授权和账号身份判断消费有效性；其他餐次的修改不使未变化的采购包失效。

所有原分支提交保留在合并历史中。旧运行日志、临时操作脚本及字节码保存在可恢复的 Git 历史和本地备份中，不进入当前源码树。原有工作树、stash 和未提交文件不参与源码整合。

## 替代方案

整支选择当前版本会遗漏未回存的功能；整支选择旧版本会覆盖当前流程；逐个摘取提交无法直接证明原分支完整进入主线。使用保留双亲的合并提交，结合逐项语义审查及回归验证。

## 验证

Web 的 lint、928 项 unit、生产构建及当前路由配置核对通过。App 的 692 项测试、H5 与微信构建通过，其中四项参数化用例保留旧服务将依赖故障错误标为可重试时的停止条件。后端可在当前平台运行的知识及营养定向 unit 共 61 项通过；每日恢复的三个迟到失败分支使用真实函数与隔离依赖验证快照、尝试号和原采购依据不变，3 项通过。移除对应保护的负控使这三个用例按预期失败。后端新增或改变的 13 个 Python 文件通过 Ruff 检查与格式检查。

完整后端 unit 在收集到 2444 项时出现 163 个 Windows/POSIX 平台错误，新增 integration 也被同一文件边界依赖阻断；这些检查未通过。当前机器的 WSL 发行版因磁盘路径缺失不可用。真实 PostgreSQL、HTTP、Worker、SSE 和浏览器交互为 Not run，本地 unit、路由核对与构建不替代这些边界的验证。

## 后果

有效修复与后续主线功能共同保留，旧采购测试按当前协议验证来源失效。来源复验、并发与持久化的完整证明仍需要可用的 Linux 和隔离数据库环境。运行日志及恢复备份留在 Git 元数据目录，不作为产品源码或当前业务事实源。
