# 单菜采购衔接商品级餐单

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/meal_dish_service.py

## 问题

参考餐单把商品匹配保存在 `product_matches`，单菜采购只读取旧 `purchase_items`。已经匹配到商品的食材被误判为缺失，购买面板无法读取采购预览。

## 决策

单菜采购在原有用户、家庭、餐次、版本和菜谱来源校验之后，仅将本菜已保存的商品引用转换为当前可售规格建议。商品资料必须仍与保存结果一致，明确的成分限制继续校验。规格价格、库存从当前商城目录读取，不把保存时的规格列表当作现货事实。已知质量按包装净含量计算整包；无可换算净含量的规格不能承接已知质量。数量无法从原文质量换算时建议一包，由现有购买面板调整，不作为个人食用份量。多个可售规格按本次包装总价、规格编号稳定选择。

未匹配食材保留原缺口与自行准备说明，不搜索补造商品，不改写审核状态。跨菜引用被限制到当前菜品，重复覆盖、缺失覆盖及商品与缺口重叠仍拒绝。旧规格级餐单继续使用原校验。读取预览不发布商城商品包、不下订单、不修改原餐单；用户后续确认仍沿用发布、核价和商城交易校验。

## 替代方案

改造前端为独立规格选择器会扩大本次页面范围；把每个规格都加入采购会重复购买同一食材；将全部缺口直接豁免会掩盖真实资料不足。本修复复用现有包装数量调整面板和后端预览接口，不变更页面。

## 后果

建议一包不保证足够完成原谱，用户需结合实际用量调整。纯用水识别、图片模型配置和配送配置不属于本次变更。
