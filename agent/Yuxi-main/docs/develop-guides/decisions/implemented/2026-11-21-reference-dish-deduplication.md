# 参考菜谱候选与本餐添加去重

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/reference_recipe_variety.py

## 问题

同一道菜存在不同来源记录时，换菜列表和旧版菜谱检索会重复占用候选名额；添加到本餐仅比较记录身份，无法阻止同名的不同记录加入。候选身份必须继续准确绑定来源、餐单版本及成员上下文。

## 决策

复用来源文件与规范原始菜名的双重判重规则。换菜按现有排名逐项核对完整原文及限制，通过后才占用去重名额，每个原菜独立保留最多三道。可见检索在截断和跨关键词合并时去重，整餐搭配的内部候选池保留不同配料版本。添加在当前事务中核对版本、来源和成员后拒绝同名不同记录；同一记录重试维持幂等。前端候选接收时去重再截断，并缓存处理后的结果。餐单保存使用同一规范菜名规则。

## 替代方案

只在界面隐藏重复无法保护其他消费者及写入。改候选ID或删除知识库记录会破坏来源绑定；本修复保留既有身份、快照及历史记录。全局提前删掉同名版本会影响整餐搭配，故在各最终消费者处执行。菜名不同的做法不进行语义合并；饮食记录明确追加一份保留。

## 后果

同名的不同配料记录在可见候选中只保留排名靠前且通过既有校验的完整记录，不拼接配料、做法或来源。同名候选并非医学等价声明。未知硬限制仍不提供换菜，不扩大可核对词汇范围。此变更不重写历史餐单、知识库或订单，无数据库迁移；线上生效需要分别发布后端和客户端。
