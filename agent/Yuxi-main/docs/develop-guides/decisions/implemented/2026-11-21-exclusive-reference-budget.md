# 专属计划参考档位与整期采购人均费用

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/exclusive_reference_plan.py

## 问题

三档名称需要明确每人每天的参考区间。逐日分别购买整包装的小计之和，与合并21天用量后实际需要的采购包装总额不同，不能直接作为整份计划总价。参考区间用于选菜偏好，轻微超额仍需提供可行菜单。

## 决策

### 实现方案

经济型、标准型、品质型的参考区间分别为10–20、30–50、50–100元/人/天。小程序卡片仅显示档位与参考区间，营养方向独立于档位；整卡保留查看与生成入口，可访问名称保留当前动作。

[选菜与计价服务](../../../../backend/package/yuxi/services/exclusive_reference_plan.py)先按参考费用偏好排序原谱，在既有有限菜单备选中比较截至当前天的合并采购总额，按天数及本次绑定人数折算，优先采用接近参考区间的组合。排序继续沿用饮食限制、三餐道数和近期去重规则；区间外组合保持可用，不引入超额百分比、额外确认或无限重试。

计划摘要及详情使用任务保存的商品快照重新合并整期包装。[采购服务](../../../../backend/package/yuxi/services/exclusive_plan_purchase.py)使用当前商品事实，并调用同一计价汇总函数。采购总价除以实际天数及本计划绑定成员数，最后舍入到分；价格或包装变化后沿用采购回源校验。已有计划沿用原菜单，无须因为卡片增加参考价而重新生成。

## 替代方案

仅增加前端价格文字无法让选菜参考预算，也无法纠正包装重复计价。把区间作为发布硬门槛会拒绝轻微超额但仍可行的菜单。持续重排直到命中区间增加任务开销，也不能证明当前供给存在满足预算的组合。当前采用有界备选排序。

## 后果

参考区间保持稳定，具体家庭金额允许浮动。已匹配商品的小计继续保留；存在未匹配食材或数量未确认时，完整总价与其人均折算保持空值，采购页面继续允许用户核对和调整包装。家庭份量未核定的既有标记保留，商品报价不替代营养量核算。历史缺少商品快照的计划保留原部分小计，不将其宣称为完整整期总价。记录不引入数据库迁移、购买副作用或线上发布。

## 验证

[费用回归测试](../../../../backend/test/unit/services/test_exclusive_reference_budget.py)验证整期合并包装、绑定人数除法、真实零价、零人数、部分采购缺口，以及区间内优先和小幅超额仍可采用。相关费用、采购与恢复共38项后端单元测试通过。

前端相关34项测试通过；全量1865项中1864项在沙箱内通过，本地图片代理测试因回环网络权限失败，单项在沙箱外复核通过。H5与小程序构建通过；合成数据浏览器在320、390、430宽度验证完整价格、三档跳转、生成入口幂等及无横向溢出。修改的参考计价、摘要服务与新增测试通过Ruff检查。真实HTTP/PostgreSQL/Worker、线上商城价格及微信真机未验证，未部署服务器或上传微信。
