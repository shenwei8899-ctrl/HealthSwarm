# 六个家庭营养业务Agent的工程闭环

状态：proposed
类型：feature
Owner：backend/package/yuxi/services/health_agent_roles.py

## 问题

用户要求完成其负责的六个Agent工程范围。现有营养师、基础配餐师及单餐分析师有独立入口；控糖、采购和质量审核未形成独立执行链路，周期分析、对话反馈和角色协作仍缺交付。目标读者为健康后端维护者及业务接口联调人员。

完成意味着每个角色的Skill、固定资源、审批同意、业务工具、结构化结果、来源版本、权限及实际Run/worker路径均可验证；包括相应计划、反馈、审核和采购用例，不以空预设或返回未就绪代替工程实现。

## 提案

保留既有PG Request/Run、checkpoint和业务表Owner，按明确角色与用例实现以下范围：

1. 饮食分析师提供日、7日、30日确认饮食及有效反馈分析，返回窗口、逐日记录覆盖、营养缺失、来源版本与统计分母；源更正、撤回及反馈变更阻止旧分析继续引用。对话中明确选择餐次与原文，经幂等受控工具写入单餐反馈，用户能修改和撤回。
2. 质量审核提供独立工程检查、批准规则和正式档案适配契约，以及绑定对象/档案/规则版本的专业提交、退回、批准、失效流程；专业决定由明确授权的审核人员写入，模型无批准工具。
3. 配餐师补充规则与档案读取、参与成员、合格候选换菜、次日提议、正式采用及安全重算；批准规则未就绪时保留通用草稿边界。修改与采用保留版本、历史和已支付快照边界。
4. 控糖管理提供21天63餐、经济/标准/品质三个方案档、逐日营养和21批需求、计划版本与打卡反馈、专业提交及使用状态；没有批准的人群规则/目标或完整档案时禁止个体化生成和启用。
5. 采购助手从有效选定菜单计算原料、用户明确库存、SKU包装件数与余量，返回逐批需求和最小商城交接；商城适配拥有外部只读查询及结算前核价核库存契约，真实交易/支付/配送状态由商城拥有。
6. 营养师在服务器批准的白名单内委派分析、配餐与控糖角色，检查最终解析资源、执行归属和来源；保留有审核引用、自述记忆和日常对话，不开放通用工具或工作区规则。

完整红阳档案、专业医学规则与实际商城接口仍由外部负责人交付。AI工程定义版本化只读契约及明确缺依赖状态；独立合成环境可提供真实持久化测试资料验证批准后的完整路径，但不能将合成资料发布为生产资料。真实供应商质量、专业内容生产、小程序重绘、交易实现、数据库迁移方案不属于本次六Agent工程完成定义。

各阶段先验证局部业务与来源保护，再在隔离Compose中运行实际API、worker、SSE及PG回读。当前业务入口需要的管理配置字段与结果接口随角色完成；不通过真实审批或依赖检查的角色入口明确不可用。默认开发worker健康异常需要定位并修正实际探针或服务故障，不能仅扩大超时掩盖无法执行。

## 替代方案

只建立角色和Skill会留下无业务消费者的预设，无法满足用户目标。等待外部资料全部生产完成会阻止接口和工程流程验证。复用现有运行引擎，先实现可用依赖下的真实流程及缺依赖门禁，以合成隔离数据证明工程，不宣称外部交付或专业质量通过。
