# 家庭营养师小程序接入

本工程提供三个页面：现有账号密码登录、真实家庭与本人成员关联、本人营养咨询。用户明确选择家庭中的本人关系和本人健康成员，勾选身份确认后保存，再回读服务端映射与基础档案状态。它不创建账号、家庭、健康成员或授权。

`App/` 原型保持原样。这里只通过 `@prototype` 别名只读复用其导航组件、图标和主题，没有复制原型页面。新增源码、配置、依赖和编译输出均位于 `agent/`。

## 账号与数据准备

账号由 Yuxi 管理员创建，需要设置所属部门。使用账号 UID 或手机号与密码登录，服务端通过 `/api/auth/me` 核对身份。密码只在本次输入与请求期间保留，不写入存储。

账号需已存在可访问的家庭、已认领的本人家庭成员，以及当前账号拥有的本人健康对象。健康对象须具备 `profile_view`、`profile_edit` 权限。首次账号缺少这些数据时，页面说明需要管理员或已有后台准备，不返回示例成员，也不自动建档。

家庭成员 UUID 与健康成员 UUID 分别选择，不能按姓名推断。已有映射不能改绑；唯一性及授权由现有业务服务和 PostgreSQL 校验。页面仅展示成员关系及基础档案状态，不展示健康档案正文。基础档案可读取不代表完整专业档案、营养安全或模型处理同意已完成。

## 安装与本地 H5

需要 Node.js 和 pnpm。依赖版本与原型保持一致，使用本工程的锁文件。

```powershell
Set-Location agent/miniapp
pnpm install --frozen-lockfile
pnpm test
pnpm dev:h5
```

浏览器打开 `http://127.0.0.1:5175`。H5 使用同源 `/api`，开发代理默认连接 `http://127.0.0.1:15050`。可通过进程环境指定独立验收服务：

```powershell
$env:VITE_HEALTH_API_PROXY = 'http://127.0.0.1:15484'
pnpm dev:h5
```

静态 H5 构建由 `pnpm build:h5` 生成 `dist/build/h5/`；部署时须为同源 `/api` 配置反向代理。开发代理不随静态文件发布。

## 微信目标

本工程目前在微信目标上同样使用现有账号密码登录，微信 code 快捷登录尚未接入。将 `.env.example` 中占位的 HTTPS 地址与微信 AppID 换成本地配置，保存为被 Git 忽略的 `.env.local`：

```text
VITE_HEALTH_API_BASE=https://你的实际请求域名/api
VITE_WECHAT_APPID=你的实际小程序AppID
```

`VITE_HEALTH_API_BASE` 是含 `/api` 的完整 HTTPS API 地址。微信目标未配置有效 HTTPS 地址时明确提示无法连接。构建配置将 `VITE_WECHAT_APPID` 注入最终 `project.config.json`，不会改写源码 manifest 或原型配置；AppID 留空仍可检查编译产物，但不构成微信登录、开发者工具或真机验收。

```powershell
pnpm build:mp-weixin
```

微信开发者工具导入 `dist/build/mp-weixin/`。实际服务需支持公开 HTTPS，并在微信后台配置 request 合法域名。本工程保留域名检查。AppSecret、账号密码等凭据不得写入前端构建变量；AppID 是公开应用标识。

## 会话与验证范围

客户端仅保存会话凭据及最小账号投影；家庭列表、选择、映射和档案状态保留在页面内存。退出、401、账号切换会清理旧页面数据；页面与请求层共同拒绝旧请求的晚到结果。重新打开页面时校验已保存会话。

`pnpm test` 覆盖请求适配器与 UI 成员筛选、白名单投影。两目标构建和真实 H5/HTTP 验收分别记录，编译通过不能代替微信开发者工具和真机测试。

## 本人营养咨询

入口只出现在已经从服务端回读真实本人关联、且无读取错误的成员下。进入 `/pages/consultation/index?member_id=服务端健康成员ID` 时，重新核对当前账号拥有的本人健康成员、档案权限与关联，并读取基础档案状态和当前咨询政策；基础档案尚待补充不会被冒充为完整专业档案，也不由前端强制作为普通咨询的前置条件。

页面明确展示 `ai_use`、`report_view`、`diet_edit` 授权、当前模型、处理方和政策版本。缺授权时提示在已有后台准备，不自动 grant。每次进入页面都需要明确勾选本次咨询同意，点击按钮后才 POST `processing-consents`。接口没有读取既有同意的公开契约，所以页面不会声称已恢复后台同意。撤回用途同意阻止新提交与后续模型处理，历史可读性仍由服务端当前成员授权判断。

“今日咨询”沿用服务端北京时间和日线程幂等规则；“独立咨询”使用 UUID 创建键。咨询记录通过 `GET /health/v1/members/{id}/consultations?limit=20&offset=0` 的真实 actor/member 绑定分页恢复，不按通用线程标题或 metadata 猜归属。来源变化返回 410 时清除旧回答，要求用户明确新建，页面不自动换线程。

问题固定提交给 `health-consultation`，白名单仅含问题、线程与请求键，不发送模型、工具或运行策略覆盖。POST 的 `run_id` 和 GET Request 的 `dispatched_run_id` 分别解析。页面用普通 HTTP 每1.5秒读取同一 Request/Run，等待预算90秒；超时只表示本地停止等待，不伪造服务端失败。用户可明确继续读取原请求。提交或创建网络结果未知时保留本页内存中的原正文与请求键，明确重试原包，不自动重发。页面隐藏后这些待确认操作会清除，重新进入以服务端真实咨询记录恢复；不提供跨页面离线草稿或待提交缓存。

历史每次读取都重新鉴权，仅展示当前线程最近20个完成的顶层 chat Run。完成结果需精确匹配账号、固定 Agent、Thread、Request、Run 与最终消息 ID，正文取公开 `result.output`。Message 整数 ID 与十进制字符串统一规范化后精确匹配，非法或不安全数值拒绝展示。工具、系统、子运行、模型审计、失败或未完成的 AI 消息不进入页面。当前公开结果 schema 没有结构化引用，页面明确显示来源为空，不提取正文 URL 或内部工具审计充当来源。中断只展示“待处理”；专属咨询服务在持久化前拒绝审批恢复，用户可明确新建独立咨询后重新提问，页面不自动换线程。

history/run 的 404、授权拒绝、或 result HTTP200 中的 `run_not_found` 均清除旧正文并阻止继续咨询。退出、401、账号切换、页面隐藏及重新显示会废弃旧请求的晚到结果，并停止轮询。健康正文、模型配置、用途选择及问题不会写入客户端存储或日志。

咨询纯投影与生命周期回放测试位于 `test/consultation-*.test.mjs`，本轮输出记录于 `agent/.tmp/miniapp-consultation-20261010/`。真实 HTTP/Worker 与浏览器验证由项目验收记录区分，测试替身只用于边界回放，不作为业务验收证据。
