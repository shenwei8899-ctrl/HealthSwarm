# 家庭营养师 V5 后台改造交付说明

## 1. 本次实现范围

本次只改造 FastAdmin 商城后台、服务端和数据库，不修改 `uniapp`。后台按最终方案展示 5 个一级入口、18 个二级业务入口，原商城功能保留为隐藏兼容权限节点。

已实现商品与食材资料、Agent 商品目录、推荐食材包、菜品换一换版本、采购清单、购物车、结算、普通订单、21 天专属计划、一次支付、每日配送批次、供应商拆单、物流、暂停顺延、恢复前 Agent 重评、例外售后、退款记录、经营指标、权限日志和 Outbox 补偿。

## 2. 上线前必须配置

1. 在插件配置中设置稳定的 `v5_master_key`，生产后不得随意更换。
2. 配置微信支付参数；支付结果只接受微信验签通知或服务端查询。
3. 在“系统配置 / 集成调用方”创建 Agent、供应商和物流调用方，密钥只在录入时显示明文。
4. 在“会员管理 / 外部身份绑定”把 Agent 的 `user_ref` 绑定到商城会员。
5. 完成标准食材、SKU 映射、营养资料、配送区域、配送时段和供应商 SKU 配置。
6. 确认当前生效的不退款政策正式文案。专属计划付款前必须明确确认，付款后个人原因不退款。
7. 一期保持“专业人工审核”关闭；未来有正式审核系统后再启用。

## 3. 自动任务

现有 `Autotask` 会运行 V5 任务：关闭超时未支付订单、释放过期库存占用、补偿已支付但 V5 状态未同步的订单、扫描未来 7 天批次缺货风险、在送达日前 3 天锁定计划批次库存、拆分并推送供应商订单、汇总修复计划送达进度、查询或重试处理中退款、重试 Outbox、清理幂等/Nonce 记录和聚合经营指标。部署后应由系统计划任务稳定触发，不能依赖人工打开后台。

## 4. 未开发平台的本地联调

先在后台创建调用方和外部身份绑定，再生成签名请求：

```powershell
node tests/v5_hmac_request.js POST /api/v1/integration/ai/recommendation-packages tests/fixtures/agent-recommendation.json YOUR_SHARED_SECRET
node tests/v5_generate_plan_fixture.js
node tests/v5_hmac_request.js POST /api/v1/integration/ai/service-plans tests/fixtures/agent-plan-21-days.generated.json YOUR_SHARED_SECRET
```

签名串固定为 `METHOD + 路径（不含查询串）+ 时间戳 + Nonce + 请求体 SHA-256`，各段以换行连接。Nonce 为 32 至 64 个字符，时间偏差默认不超过 300 秒。

## 5. 数据库与升级

安装或升级插件时会自动执行 `database/v5_schema.sql` 和幂等字段迁移。正式环境升级前必须备份数据库，并先在测试库运行一次插件升级。迁移不会删除旧商城数据。

## 6. 验收重点

- Agent 只能读取已发布、资料合格且可售的 SKU。
- 推荐包和计划必须同时通过营养校验与商城交易校验。
- 计划固定 21 天、每日一批、默认提前一天送达，一次支付全部费用。
- 支付后菜单不可修改；暂停会顺延，恢复前必须取得 Agent 重评通过结果。
- 每批提前 3 天锁库存并自动拆供应商子单。
- 个人原因不能取消或退款；平台未履约、错漏发、质量问题和法律强制情形走例外售后审批。
- 第 21 批送达后自动汇总计划和总订单为完成。
- 重复回调、重复创建和重复支付请求不会生成重复业务资源。
- 供应商乱序回调只记录审计事件，不允许把已发货或已完成状态回退。
- 支付同步、批次汇总和退款状态存在定时补偿，不依赖人工刷新页面。

## 7. 当前环境验证边界

当前电脑没有 PHP 和 MySQL 命令行运行时，因此本次已执行完整 PHP AST 语法检查、MySQL DDL 解析、后台字段存在性、菜单、路由、JavaScript 和 JSON 静态检查，但无法在本机连接真实 FastAdmin 数据库、微信支付和供应商测试环境做运行时验收。部署前仍须按 `家庭营养师V5联调测试与验收清单.md` 在完整测试环境执行数据库迁移、接口联调、并发库存和支付退款回调测试。
