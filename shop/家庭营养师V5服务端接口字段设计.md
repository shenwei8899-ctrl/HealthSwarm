# 家庭营养师 V5 服务端接口字段设计

## 1. 文档范围

本文定义商城后端需要提供或对接的 V1 接口契约，供商城后端、营养师 Agent、小程序、专业审核、供应商、物流和微信支付团队联合评审。

本文不要求刘北萍修改 Uni-app，只规定小程序团队应如何调用商城接口。

### 1.1 已确认规则

- 21 天专属计划每天一批，共 21 批，默认提前一天送达下一食用日食材。
- 计划开始时一次支付全部费用。
- 付款后菜单和未来菜品不可修改。
- 暂停会顺延，恢复前由 Agent 重新评估原计划。
- 每批在计划送达日前 3 天锁库存并推送供应商。
- 专属计划付款后不支持用户因个人原因取消或退款；付款前小程序必须警告并取得确认，后端保存确认凭证。
- 平台未履约、错漏发、食品质量问题及法律强制情形仍进入例外售后。
- 专业人工审核为未来可选能力，一期默认关闭。

## 2. 接口域与责任

| 接口域 | 建议前缀 | 调用方 | 主要责任 |
|---|---|---|---|
| 小程序商城 | `/api/v1/commerce` | 小程序 | 推荐包、采购、结算、订单、计划和售后 |
| Agent 集成 | `/api/v1/integration/ai` | AI/Agent | 商品目录、推荐包、换菜版本和计划 |
| 外部供应链 | `/api/v1/integration/suppliers` | 供应商 | 供应商订单和状态回调 |
| 支付回调 | `/api/v1/payment`、`/api/v1/refund` | 微信支付 | 支付和退款结果通知 |
| 物流回调 | `/api/v1/integration/logistics` | 物流方 | 运单节点通知 |

## 3. 通用协议

### 3.1 请求头

| 请求头 | 适用范围 | 必填 | 说明 |
|---|---|---|---|
| `Authorization: Bearer <token>` | 小程序私有接口 | 是 | 现有登录 Token，后端解析用户身份 |
| `X-Client-Id` | 服务间接口 | 是 | Agent 或供应商应用编号 |
| `X-Timestamp` | 服务间接口 | 是 | Unix 秒，默认允许正负 300 秒偏差 |
| `X-Nonce` | 服务间接口 | 是 | 32 至 64 位随机串，防重放 |
| `X-Signature` | 服务间接口 | 是 | 按双方冻结算法签名 |
| `Idempotency-Key` | 所有创建/支付/退款/状态写接口 | 是 | 同一业务重试保持不变，最长 64 字符 |
| `X-Request-Id` | 全部接口 | 建议 | 调用方生成；缺失时后端生成 |
| `If-Match-Version` | 版本敏感写接口 | 是 | 当前资源整数版本号 |

### 3.2 统一成功响应

```json
{
  "code": 0,
  "message": "success",
  "request_id": "req_20260930_001",
  "data": {}
}
```

旧接口可继续使用原成功码；所有新增 V1 接口统一以 `code=0` 表示成功。

### 3.3 统一失败响应

```json
{
  "code": 40906,
  "message": "推荐包版本已变化，请刷新后重试",
  "request_id": "req_20260930_001",
  "data": {
    "resource": "recommendation_package",
    "current_version": 3,
    "submitted_version": 2,
    "retryable": false
  }
}
```

### 3.4 字段规则

- 所有 ID 对外作为字符串返回，避免不同客户端整数精度问题。
- 金额均使用整数分，字段后缀 `_cent`。
- 数量使用十进制字符串，避免浮点误差，例如 `"300.000"`。
- 数量必须带单位代码，例如 `g`、`kg`、`ml`、`piece`、`pack`。
- 时间使用 ISO 8601，时区为 `+08:00`。
- 日期使用 `YYYY-MM-DD`。
- 手机、地址、OpenID、密钥和签名禁止写入普通日志。
- 空值表示未知；营养数据缺失不能用零代替。

### 3.5 分页

后台和小程序普通列表使用：

```json
{"page": 1, "page_size": 20}
```

Agent 目录增量建议使用游标：

```json
{"cursor": "opaque_cursor", "limit": 100}
```

响应包含 `items`、`total`（可选）、`next_cursor` 和 `has_more`。

| `category_codes` | string[] | 否 | 业务分类过滤 |
| `delivery_area_code` | string | 否 | 过滤可配送 SKU |

每个目录项返回：

| 字段 | 类型 | 说明 |

### 5.2 SKU 详情

`GET /api/v1/integration/ai/catalog/skus/{sku_id}`

返回目录项全部字段，并增加配料详情、规格属性、配送限制、固定食材包关系和最近更新时间。不存在返回 `40401`；已下架仍可按 ID 查询，但 `sale_status=unavailable`。

### 5.3 同食材候选

`GET /api/v1/integration/ai/catalog/skus/{sku_id}/alternatives`

查询参数：`delivery_area_code`、`required_quantity_value`、`required_quantity_unit`、`limit`。

返回候选 SKU、可覆盖量、需购买件数、余量、价格和候选原因。该接口只提供交易候选，Agent 仍负责营养适用性判断。

## 6. Agent 推荐包接口

### 6.1 创建推荐包

`POST /api/v1/integration/ai/recommendation-packages`

请求：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `agent_task_id` | string | 是 | Agent 任务唯一号 |
| `family_ref` | string | 是 | 家庭引用，不传健康内容 |
| `user_ref` | string | 是 | 用户引用，与授权关系一致 |
| `member_refs` | string[] | 否 | 适用成员引用 |
| `menu_version_ref` | string | 是 | Agent 菜单版本 |
| `catalog_version` | string | 是 | 生成时使用的目录版本 |
| `meal_date` | date | 否 | 单餐日期 |
| `expires_at` | datetime | 否 | 建议有效期，商城可缩短 |
| `recipes` | array | 是 | 菜品引用、名称、餐次、排序和展示摘要 |
| `ingredient_requirements` | array | 是 | 完整食材需求，不仅是变化项 |
| `items` | array | 否 | Agent 已选 SKU；商城仍会验证和重算 |
| `nutrition_validation` | object | 是 | NutritionValidationRef |
| `callback_url` | string | 否 | 已登记白名单内回调地址 |

`ingredient_requirements[]`：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `recipe_ref` | string | 是 | 所属菜品 |
| `ingredient_code` | string | 是 | 标准食材编码 |
| `required_value` | decimal string | 是 | 所需量 |
| `required_unit` | string | 是 | 标准单位 |
| `is_optional` | boolean | 是 | 是否可选 |

`items[]`：`sku_id`、`quantity`、`ingredient_code`、`covers_value`、`covers_unit`。

成功响应：

| 字段 | 类型 | 说明 |
|---|---|---|
| `package_sn` | string | 推荐包编号 |
| `package_version` | integer | 初始为 1 |
| `status` | enum | `draft/validated/available/blocked/expired` |
| `nutrition_validation_status` | enum | Agent 结论 |
| `trade_validation_status` | enum | 商城结论 |
| `items` | SkuSnapshot[] | 商城重算后的组合 |
| `total_amount_cent` | integer | 当前总价 |
| `trade_issues` | TradeIssue[] | 交易问题 |
| `expires_at` | datetime | 实际失效时间 |

幂等业务键为 `client_id + agent_task_id`。相同键、相同请求摘要返回原结果；相同键、不同内容返回 `40901`。

### 6.2 查询推荐包

`GET /api/v1/integration/ai/recommendation-packages/{package_sn}`

返回当前版本、用户确认状态、营养校验、交易校验、SKU 快照、实时问题、采购清单引用和订单引用。Agent 只能查询由自身应用创建或获授权的包。

### 6.3 创建菜品换一换版本

`POST /api/v1/integration/ai/recommendation-packages/{package_sn}/dish-swap-versions`

请求：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `agent_task_id` | string | 是 | 本次换菜任务号 |
| `swap_request_id` | string | 是 | 小程序发起的换菜请求引用 |
| `base_version` | integer | 是 | 用户看到的推荐包版本 |
| `base_menu_version_ref` | string | 是 | 原菜单版本 |
| `result_menu_version_ref` | string | 是 | 新菜单版本 |
| `swap_type` | enum | 是 | `same_main_ingredient` 或 `same_nutrition_structure` |
| `change_reason` | string | 是 | 用户不喜欢、过敏偏好等代码 |
| `old_recipe_ref` | string | 是 | 原菜品 |
| `new_recipe_ref` | string | 是 | 新菜品 |
| `recipes` | array | 是 | 替换后完整菜品清单 |
| `ingredient_changes` | array | 是 | 仅供差异展示 |
| `full_menu_ingredient_requirements` | array | 是 | 替换后的完整需求 |
| `nutrition_validation` | object | 是 | 整份菜单复核结果 |

规则：

- `base_version` 与当前版本不一致返回 `40906`。
- 营养状态不是 `passed` 不创建可购买版本。
- 每次成功写入一个不可变新版本，旧版本立即失去确认和结算资格。
- 同主食材换做法可复用采购清单内容，但菜单版本和换菜记录仍需新增。
- 跨食材换菜必须重新匹配全部食材并校验全部 SKU。

响应返回新 `package_version`、菜单引用、SKU、价格差、交易问题和 `requires_user_reconfirm=true`。

## 7. Agent 专属计划与可选专业审核

### 7.1 创建 21 天计划

`POST /api/v1/integration/ai/service-plans`

请求主字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `agent_task_id` | string | 是 | 唯一任务号 |
| `family_ref` | string | 是 | 家庭引用 |
| `user_ref` | string | 是 | 购买用户引用 |
| `member_refs` | string[] | 是 | 适用成员引用 |
| `profile_version_refs` | string[] | 是 | 只保存档案版本引用 |
| `plan_name` | string | 是 | 用户展示名称 |
| `plan_days` | integer | 是 | 当前原型为 21 |
| `delivery_frequency` | enum | 是 | 一期固定 `daily` |
| `candidate_rank` | integer | 否 | 多个候选排序 |
| `requires_professional_review` | boolean | 是 | 一期固定 false；未来高风险流程可启用 |
| `professional_review_ref` | string | 条件必填 | 外部审核单引用 |
| `days` | array | 是 | 每日菜单与食材需求 |
| `nutrition_validation` | object | 是 | 全计划校验引用 |

`days[]` 包含 `day_no`、`relative_date`（可空）、`meals[]`；`meals[]` 包含 `meal_type`、`recipe_ref`、`recipe_name`、`ingredient_requirements[]` 和展示摘要。

响应：`plan_sn`、`plan_version`、`status`、`review_gate_status`、`trade_draft_status`、`estimated_amount_cent`、`unmatched_requirements`、`created_at`。

### 7.2 新建计划版本

`POST /api/v1/integration/ai/service-plans/{plan_sn}/versions`

字段同创建计划，另加 `base_version`、`change_reason`。只允许未支付计划创建新版本；计划一旦支付，菜单和未来菜品永久按支付快照冻结。

### 7.3 专业审核回传

`POST /api/v1/integration/ai/professional-reviews/{review_ref}/result`

本接口为未来可选能力，一期默认不调用，也不阻断普通计划购买。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `event_id` | string | 是 | 回调幂等号 |
| `review_ref` | string | 是 | 路径与正文必须一致 |
| `resource_type` | enum | 是 | `recommendation_package/service_plan` |
| `resource_ref` | string | 是 | 包号或计划号 |
| `resource_version` | integer | 是 | 被审核版本 |
| `status` | enum | 是 | `pending/supplement_required/approved/rejected/expired` |
| `purchase_gate` | enum | 是 | `allowed/blocked` |
| `member_refs` | string[] | 是 | 适用对象引用 |
| `summary` | string | 是 | 可展示摘要 |
| `reviewed_at` | datetime | 条件必填 | 审核完成时间 |
| `signature` | string | 是 | 审核结果签名 |

乱序回调按审核版本和发生时间处理，旧状态不能覆盖新状态。已经支付的订单不回滚支付，转风险异常单评估未来批次。

### 7.4 暂停计划恢复前 Agent 重新评估

用户调用恢复接口后，商城先创建恢复申请并通过事件 `service_plan.resume_evaluation_requested` 通知 Agent，状态返回 `evaluation_pending`，不能立即恢复排程。

Agent 回传：

`POST /api/v1/integration/ai/plan-orders/{order_sn}/resume-validations`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `agent_task_id` | string | 是 | 本次重评任务唯一号 |
| `change_request_sn` | string | 是 | 商城恢复申请编号 |
| `plan_sn`、`plan_version` | string/integer | 是 | 必须与支付快照一致 |
| `profile_version_refs` | string[] | 是 | 本次使用的最新档案版本引用 |
| `status` | enum | 是 | `passed/failed/more_information_required` |
| `validation_id` | string | 是 | Agent 重评编号 |
| `rules_version` | string | 是 | 规则版本 |
| `summary` | string | 是 | 可展示摘要 |
| `validated_at`、`valid_until` | datetime | 是 | 校验时间和有效期 |

只有 `passed` 且仍在有效期内，商城才按顺延后的日期重新校验配送能力并完成恢复。`failed` 时保持暂停；由于付款后菜单不可修改且不支持个人原因退款，系统转人工处理但不能改写计划菜品。

## 8. 商城向 Agent 发送事件

事件信封：

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_id` | string | 全局唯一，Agent 按此幂等 |
| `event_type` | string | 事件类型 |
| `occurred_at` | datetime | 业务发生时间 |
| `resource_type` | string | 资源类型 |
| `resource_ref` | string | 商城业务编号 |
| `resource_version` | integer | 资源版本 |
| `data` | object | 最小必要业务内容 |
| `request_id` | string | 原链路请求号 |

事件至少包括：推荐包创建/校验失败/新版本/用户确认/过期、采购清单创建、订单创建/支付/履约/取消/退款、计划创建/支付/暂停/恢复评估请求/恢复/例外售后、批次履约变化，以及未来启用时的可选审核变化。

HTTP 2xx 表示 Agent 已接收；非 2xx 进入 Outbox 重试。回调失败不能回滚已完成支付或订单事务。

## 9. 小程序推荐包与采购接口

### 9.1 推荐包读取与确认

| 方法 | 路径 | 请求关键字段 | 响应关键字段 |

## 11. 普通订单与支付

### 11.1 创建订单

`POST /api/v1/commerce/orders`

请求只接受：`checkout_token`、`client_order_ref`、`remark`。必须带 `Idempotency-Key`。计划订单的 `checkout_token` 已绑定不退款政策确认凭证，创建时再次校验用户、版本和有效期。

响应：`order_sn`、`order_type`、`status`、`pay_status`、`payable_amount_cent`、`expire_at`、`created_at`。

创建时服务端必须再次验证令牌归属、来源版本、价格、库存、优惠券和配送；同一令牌只能生成一个有效订单。

### 11.2 订单查询与操作

| 方法 | 路径 | 请求/响应重点 |
|---|---|---|
| GET | `/orders` | 状态、类型、时间分页 |
| GET | `/orders/{order_sn}` | 金额、商品快照、地址快照、支付、履约、售后 |
| GET | `/orders/{order_sn}/timeline` | 状态事件时间线 |
| POST | `/orders/{order_sn}/cancel` | `reason_code/reason_text/version` |
| POST | `/orders/{order_sn}/receipt` | `version` |
| POST | `/orders/{order_sn}/repurchase` | 返回新购物车或失效项，不复制旧价格 |

### 11.3 微信预支付

`POST /api/v1/commerce/orders/{order_sn}/payments/wechat`

请求：`payer_openid`（后端可从登录态获取）、`client_platform=miniprogram`。响应返回小程序调起支付所需的 `timeStamp`、`nonceStr`、`package`、`signType`、`paySign`、`payment_sn`。

小程序支付弹窗成功只表示客户端流程完成，最终状态以微信验签回调或服务端主动查询为准。

`GET /orders/{order_sn}/payment-status` 返回 `unpaid/paying/paid/closed/refunding/refunded`、微信交易号掩码和最后确认时间。

平台发起查询至少传承运商编码和运单号。物流回调字段：`event_id`、`carrier_code`、`tracking_no`、`status`、`occurred_at`、`location`、`description`、`signature`。

统一状态：`created/picked_up/in_transit/out_for_delivery/delivered/exception/returned`。保存供应商原始状态与统一状态，避免信息丢失。

## 16. 微信支付与退款回调

### 16.1 支付通知

`POST /api/v1/payment/wechat/notify`

处理顺序：

1. 校验微信平台证书、签名、时间戳和随机数。
2. 解密资源并校验商户号、应用号、订单号、币种和金额。
3. 以微信交易号和支付单号执行幂等更新。
4. 在本地事务内更新支付记录、订单和 Outbox。
5. 事务提交后由队列生成供应商订单或计划批次。
6. 返回微信要求的成功响应。

金额不一致不得置为支付成功，进入最高级异常单。

### 16.2 退款申请与通知

内部退款请求字段：`refund_sn`、`order_sn`、`aftersale_sn` 或 `plan_change_request_sn`、`refund_amount_cent`、`reason`、`allocation_ids`。

微信退款回调验签解密后，以微信退款单号幂等更新。`SUCCESS` 才能把本地退款置为完成；处理中由自动任务主动查询。

## 17. 错误码

| 错误码 | 场景 | 客户端处理 |
|---|---|---|
| 40001 | 参数错误 | 修正请求，不重试原请求 |
| 40101 | 登录/签名失效 | 重新登录或刷新凭证 |
| 40301 | 越权 | 停止操作 |
| 40401 | 资源不存在 | 返回列表 |
| 40901 | 幂等键与原内容冲突 | 使用原业务键查询 |
| 40902 | 当前状态不允许 | 刷新详情 |
| 40903 | 价格变化 | 展示新价格并重新确认 |
| 40904 | 库存不足 | 展示候选或返回 Agent |
| 40905 | 配送不支持 | 换地址/时段 |
| 40906 | 推荐包/清单版本冲突 | 获取最新版本 |
| 40907 | 推荐包过期 | 请求 Agent 重新生成 |
| 40908 | 计划版本冲突 | 刷新计划 |
| 40909 | 批次过截单时间 | 禁止修改该批次 |
| 40910 | 计划操作冲突 | 刷新计划订单 |
| 42201 | 食材无法匹配 | 自主采购或后台处理 |
| 42202 | 必须跨食材替代 | 返回 Agent 复核 |
| 42203 | Agent 营养校验未通过 | 不允许购买 |
| 42204 | 商城交易校验未通过 | 展示问题并刷新 |
| 42205 | 专业审核未通过/未完成 | 只允许查看 |
| 42206 | 专属计划付款后不支持个人原因退款 | 展示付款前已确认的政策，不创建退款 |
| 42207 | 批次地址/运力失败 | 更换地址或日期 |
| 50201 | Agent 暂不可用 | 已有订单可继续，换菜稍后重试 |
| 50202 | 供应商暂不可用 | 后端重试并进入待办 |
| 50203 | 微信支付暂不可用 | 查询支付状态后再决定重试 |

## 18. 状态与版本冲突返回要求

任何 `40902/40906/40908/40909/40910` 响应都必须包含：资源类型、资源编号、提交版本、当前版本、当前状态、允许的下一步操作和是否可重试。不能只返回“操作失败”。
