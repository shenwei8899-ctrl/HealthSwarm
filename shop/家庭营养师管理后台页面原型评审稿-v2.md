# 家庭营养师管理后台页面原型评审稿 V2.2（五菜单精简版）

## 1. 文档用途

这是一份**页面评审稿**，用于确认刘北萍负责的商城、订单、供应链后台最终要呈现什么页面、每个页面看什么数据、能做什么操作。V2 已根据《家庭营养师-离线体验版(3).html》增加单餐购买和 21 天 AI 专属计划两条业务路径。

它不是小程序设计稿，也不是技术开发说明书。小程序团队只通过接口调用后台；本文件只描述运营、客服、采购、仓配和管理员使用的管理后台。

## 2. 先看全貌：最终左侧菜单

最终采用 5 个一级菜单。相近功能使用页签合并，功能、权限和业务数据不删除。

```text

  食材资料
  食材包与推荐
  AI 专属计划
  采购清单

订单与履约
  订单管理
  配送批次
  备货配送
  售后与异常

供应链
  供应商档案

运营与系统
  经营数据
  营销管理
  会员管理

```

说明：左侧只显示上面的 18 个二级入口。商品分类、SKU、换菜记录、合作申请、接口日志、支付配置等功能进入对应页面后通过页签查看。专业人工审核一期不启用，未来启用时放在“AI 专属计划”内部页签。

## 3. 岗位进入后台后分别看什么

| 岗位 | 首先使用的菜单 | 主要目的 |
| --- | --- | --- |
| 商品运营 | 商品与配餐 | 维护可售商品、营养资料、固定包和食材对应关系 |
| 营养运营 | 商品与配餐 | 查看 Agent 推荐包、计划版本、换菜记录和缺货替代 |
| 客服 | 订单与履约、运营与系统 | 查普通订单、计划订单、配送批次、售后和会员收货信息 |
| 采购/供应链 | 供应链、订单与履约 | 看待备货需求、推送供应商、跟踪供应商回传 |
| 仓配 | 订单与履约、供应链 | 拣货、发货、安排配送时段、处理配送异常 |
| 管理者 | 工作台、运营与系统 | 看销售、履约、缺货、售后和服务质量 |

## 4. 页面阅读规则

下文的方框是页面布局草图，目的是让你理解页面位置和内容，而不是确定最终颜色、字体或像素尺寸。

- `[筛选]`：用户可输入或选择条件后查询。
- `[按钮]`：页面上允许的操作。
- `列表`：默认进入页面时最常看的数据。
- `详情抽屉/详情页`：点击一条记录后打开，用于查看完整过程和执行进一步操作。
- `状态`：系统自动变化的结果，除非页面明确给出人工处理按钮，否则不允许手工随意改写。

## 5. 工作台：今天需要处理什么

### 5.1 页面原型

```text
┌──────────────── 工作台 ──────────────── 2026-09-29 ──────────────┐
│ 今日销售额       待支付订单       今日待备货批次     异常订单         │
│ ¥ 28,560         18              42                3             │
├─────────────────────────────────────────────────────────────────┤
│ [待处理工作]                                                        │
│  Agent重评待返回 2  计划批次缺货 4  供应商推单失败 1  例外售后 3     │
│  [查看审核] [查看批次] [查看接口异常] [查看退款]                       │
├─────────────────────────────────────────────────────────────────┤
│ 今日订单趋势                         热销商品 / 易缺货商品           │
│ （图表）                             （排行表）                       │
└─────────────────────────────────────────────────────────────────┘
```

### 5.2 作用和使用

这是不同岗位的共同首页。它不用于维护业务数据，而是把“今天必须处理的事”直接列出来。点击待办会进入对应模块，例如“缺货待替代”进入“商品与配餐 / 采购清单 / 缺货处理”页签，“供应商推单失败”进入“供应链 / 供应商协同”页面的推单异常或接口日志页签。

## 6. 商品与配餐（一）：商品管理和固定食材包

### 6.1 商品管理

```text
┌ 商品与配餐 / 商品管理 / 商品页签 ──────────────────────────────────┐
│ [商品名称/编码] [分类] [上架状态] [食材资料完整度] [查询] [新增商品] │
├─────────────────────────────────────────────────────────────────┤
│ 商品图片 │ 商品名称 │ 分类 │ 售价区间 │ 可售 SKU │ 上架 │ 食材资料 │ 操作 │
│ 番茄礼盒 │ 蔬菜     │ 29-39 │ 2        │ 是       │ 完整     │ [编辑][查看]│
│ ...                                                             │
└─────────────────────────────────────────────────────────────────┘
```

**它管理什么：** 一个面向用户销售的商品，例如“有机番茄礼盒”。商品下面可以有不同规格的 SKU，例如 500g、1kg。

**运营如何使用：** 新建商品、上传图文、设定分类和上架状态。只有上架且 SKU 可售的商品，才会被提供给 Agent 作为候选商品。

### 6.2 商品管理：SKU 与库存页签

```text
┌ 商品与配餐 / 商品管理 / SKU与库存页签 ─────────────────────────────┐
│ [商品/SKU] [仓库] [库存状态] [库存不足] [查询] [批量导入库存]         │
├─────────────────────────────────────────────────────────────────┤
│ SKU编码 │ 规格 │ 销售价 │ 可售库存 │ 锁定库存 │ 安全库存 │ 状态 │ 操作 │
│ TM-500  │ 500g │ 29.00  │ 168      │ 12       │ 30       │ 正常 │ [调整][流水]│
├─────────────────────────────────────────────────────────────────┤
│ 点击“流水”：入库、订单锁定、取消释放、发货扣减、人工调整均可追溯。    │
└─────────────────────────────────────────────────────────────────┘
```

**它管理什么：** 真正下单、扣库存、供应商履约的最小单元。价格和库存只以 SKU 为准。

**关键规则：** Agent 只可推荐系统返回的可售 SKU；在用户确认和下单时，后台再次校验最新价格和库存，防止推荐时有货、付款时无货。

### 6.3 商品编辑页中的“食材与营养资料”页签

```text
┌ 商品：有机番茄礼盒 ───────────────────────────────────────────────┐
│ [基础信息] [SKU] [食材组成] [营养资料] [供应商] [操作日志]           │
├ 食材组成 ────────────────────────────────────────────────────────┤
│ 标准食材：番茄       含量：>=95%       过敏原：无                  │
│ [选择标准食材] [添加组成]                                           │
├ 营养资料 ────────────────────────────────────────────────────────┤
│ 每 100g：能量、蛋白质、脂肪、碳水、膳食纤维、钠……                  │
│ 数据来源：供应商检测报告      资料完整度：完整      [编辑/更新]      │
└─────────────────────────────────────────────────────────────────┘
```

这是 Agent 能正确配包的基础。后台记录商品包含什么食材、对应营养资料、过敏原和资料来源；资料缺失必须显示“缺失”，不能默认当作 0。后台不根据健康档案计算个体营养方案，Agent 才负责该判断。

### 6.4 食材包与推荐：固定食材包页签

```text
┌ 商品与配餐 / 食材包与推荐 / 固定食材包页签 ───────────────────────┐
│ [食材包名称] [上架状态] [查询] [新增固定包]                          │
├─────────────────────────────────────────────────────────────────┤
│ 包名称       │ 包内 SKU 数 │ 标价 │ 状态 │ 最近修改 │ 操作           │
│ 一周轻食蔬菜包│ 8           │ 168  │ 上架 │ 今天     │ [编辑][下架]   │
└─────────────────────────────────────────────────────────────────┘
```

固定食材包是运营人工配置、可以反复销售的标准商品组合，例如“清蒸鲈鱼鲜蔬包”“家庭杂粮主食包”。Agent 可以把固定包推荐给具体家庭；没有合适固定包时，也可以提交动态 SKU 组合。两者下单时都展开成真实 SKU。

## 7. 商品与配餐（二）：食材、推荐、计划和采购

```text
┌ 商品与配餐 / 食材资料 / 食材库页签 ───────────────────────────────┐
│ [食材名称] [食材类别] [过敏原] [启用状态] [查询] [新增标准食材]       │
├─────────────────────────────────────────────────────────────────┤
│ 食材编号 │ 标准名称 │ 别名 │ 类别 │ 风险提示 │ 可映射SKU数 │ 操作    │
│ ING-001  │ 西兰花   │ 花椰菜│ 蔬菜 │ -        │ 6           │ [编辑]  │
```

这是统一词典，不是库存商品。它解决“西兰花”“花椰菜”等不同表达被识别成同一种食材的问题，也为 Agent 和商品资料提供共同语言。

```text
┌ 商品与配餐 / 食材资料 / SKU映射页签 ──────────────────────────────┐
│ [标准食材] [商品/SKU] [可替代等级] [启用状态] [查询] [新增映射]      │

│ 标准食材 │ SKU        │ 商品名称         │ 规格 │ 替代等级 │ 状态 │ 操作 │
│ 西兰花   │ BR-500     │ 有机西兰花       │ 500g │ 首选     │ 启用 │ [编辑] │
│ 西兰花   │ BR-300     │ 西兰花家庭装     │ 300g │ 备选     │ 启用 │ [编辑] │
└─────────────────────────────────────────────────────────────────┘
```

**为什么需要它：** Agent 的营养建议可能说“需要西兰花”，但用户能购买的是“有机西兰花 500g”这个 SKU。映射把抽象食材落到实际可下单、可定价、可配送的商品；也让缺货时系统有可控的候选替代品。

这个页面把 Agent 的“菜品/菜谱”衔接到可以购买的固定食材包或真实 SKU。换菜以后，系统根据新菜品重新生成食材需求和采购清单。

### 7.7 食材包与推荐：换菜记录页签

```text
┌ 商品与配餐 / 食材包与推荐 / 换菜记录页签 ─────────────────────────┐

├─────────────────────────────────────────────────────────────────┤
│ 推荐包 │ 菜单版本 │ 用户替换       │ 类型       │ 复核 │ 商品变化 │ 查看 │
│ RP-001 │ M2 -> M3│ 鲈鱼->豆腐虾仁 │ 换食材     │ 通过 │ 已重算   │ [详情]│
└─────────────────────────────────────────────────────────────────┘
```

用户在小程序点“换一换”时，换的是一道菜。后台记录原菜品、新菜品、菜谱版本、食材变化、烹饪步骤、采购清单变化、价格变化和 Agent 整份菜单复核结果。只换做法可能不改变采购商品；跨食材换菜会生成新的推荐包和采购清单版本。已支付订单保持原商品快照。

### 7.8 采购清单：清单页签

```text
┌ 商品与配餐 / 采购清单 / 清单页签 ─────────────────────────────────┐
│ [清单编号] [来源] [用户] [状态] [配送日期] [查询]                    │
├─────────────────────────────────────────────────────────────────┤

└─────────────────────────────────────────────────────────────────┘
```

采购清单是用户确认菜单/食材包后的待购买明细。用户可以取消家中已有的食材，然后直接结算，也可以加入购物车。它不是供应商采购单，也不等于订单。

### 7.9 采购清单：缺货处理页签

```text
┌ 商品与配餐 / 采购清单 / 缺货处理页签 ─────────────────────────────┐
```

异常订单还要覆盖计划批次库存不足、计划暂停后误推单、Agent 恢复重评失败、恢复后排程失败和例外售后处理失败。

## 11. 五条最重要的页面流转

### 11.1 Agent 动态食材包到下单

```text
健康建档（小程序）
  -> Agent 查询“可售商品目录”
  -> Agent 生成菜单/菜品并推荐固定食材包或动态 SKU 组合
  -> 后台“商品与配餐 / 食材包与推荐”保存本次推荐 V1
  -> 用户在小程序查看
  -> 用户取消勾选家中已有食材并确认
  -> 后台“商品与配餐 / 采购清单”
  -> 直接结算或加入购物车、支付
  -> 后台“订单与履约 / 订单管理”
  -> “备货配送” / “供应商协同”
```

### 11.2 用户点击“换一换”

```text
小程序选择替换菜品
  -> Agent 对修改后的整份菜单再次营养校验
  -> 后台保存菜单、推荐包和采购清单新版本
  -> 后台重新匹配 SKU 并校验价格、库存、上架和配送
  -> 小程序显示 V2
  -> 后台“食材包与推荐 / 换菜记录”可追溯菜品、食材和商品变化
```

旧版本仍可查看，但不能再被用户确认、结算或下单。

### 11.3 AI 专属计划到分批履约

```text
Agent生成多个21天计划候选
  -> 后台“商品与配餐 / AI专属计划”保存计划和版本
  -> Agent完成全计划营养、过敏原和适用性校验
  -> 用户选择地址和首批预计送达日，后台生成每日一批且提前一天送达的21批
  -> 后台按21批重新报价并校验运力
  -> 小程序弹出“付款后不支持退款”警告，用户主动确认
  -> 用户一次支付全部21天费用，后台保存确认凭证
  -> 后台“订单与履约 / 订单管理 / 专属计划”生效
  -> 每批在送达日前3天分配库存、生成供应商订单
  -> 用户逐批确认收货
  -> 后续可暂停顺延、Agent重评后恢复或改批次地址，不可主动退款
```

### 11.4 缺货后的处理

```text
库存不足 / 计划批次无法供货 / 供应商拒单
  -> “采购清单 / 缺货处理”或“售后与异常”出现待办
  -> 确认可替代 SKU
  -> 若影响营养组合，交 Agent 复核整包
  -> 用户确认后才替换；付款计划无法履约时进入平台责任例外售后
```

### 11.5 付款前不退款确认与例外售后

```text
小程序在支付前读取后台当前政策版本并弹出明确警告
  -> 用户主动确认，后台保存文案哈希、版本、用户和确认时间
  -> 未确认或政策版本已变化时不能创建计划订单
  -> 支付后个人原因取消/退款请求被拒绝
  -> 平台未履约、错漏发、食品质量问题进入例外售后
  -> 后台按权限处理补发、赔付或法律要求的例外退款
```

## 12. 页面评审结论与剩余确认事项

1. 已确认采用第 2 节的 5 个一级菜单和 18 个二级菜单，相近功能通过页签合并。
2. 已确认保留“固定食材包管理”，但一期以 Agent 动态组合真实 SKU 为主，固定包仅在完全匹配时选用。
3. 已确认固定包与动态组合不设后台硬优先级，是否适用由 Agent 校验决定。
4. 是否确认换一换以菜品为入口，并同步菜单、食材包和采购清单。
5. 已确认“专业审核状态”一期隐藏；AI 专属计划、专属计划订单和配送批次为独立页面。
6. 已确认 21 天一次付清、每日一批、默认提前一天送达。
7. 已确认暂停顺延、Agent 重评后恢复、单批改地址和逐批签收均需后台记录；付款后不提供主动取消退款。
8. 已确认平台未履约、错漏发、质量问题和法律强制情形作为例外售后处理。
9. 是否确认后台不保存完整健康档案，只保存推荐、审核和交易所需引用。
10. 是否确认订单、支付、库存、供应商履约仍以商城后台为唯一业务真相来源。

## 13. 评审通过后的下一步

页面结构确认后，开发顺序建议是：商品/SKU/固定食材包和 Agent 商品目录；菜单、菜品换一换和单餐采购；AI 专属计划、付款前不退款确认和一次支付；每日配送批次、送达日前 3 天推单、供应商履约和例外售后。小程序端由其团队按接口对接。
